## 发现的 Bug
- BUG-002（frontend, Minor，**Closed**，2026-11-11 复测通过）：筛选无结果时不显示"共 0 条"（验收 2）。见 `docs/bugs/BUG-002-trade-list-no-match-hides-total.md`。

## 已知前端行为的判断（不算 bug）
- **点击合约时保留当前的方向和日期筛选**：需求只要求"把筛选设为该合约（四项），回到第 1 页"，验收 3 是在"无筛选时"点的，没有规定其它条件要不要清掉。这不违反需求，所以不报 bug。如果你希望点击合约时清掉方向和日期，请告诉我。
- **地址里每页条数不是 20/50/100 时按 20 处理**：需求只要求页面可选 20 / 50 / 100，不违反需求。
- **地址里的页码超过最后一页时跳到最后一页**：与需求边界情况"前端应能回到有数据的页，不显示空白页"一致。

## 测试过程中的说明
- 第一次跑 E2E 时，AC3 有一处是测试自己的时序问题：点"清除筛选"后立刻输入，被随后的表单重置清空了。已在测试里改为等清除生效后再输入，不是产品问题，真实用户不会这么快操作。
