## 背景 / 用户故事
作为一个期权交易者，我卖 put 被指派后持有股票、再卖 covered call，也会自己买卖股票。我想在**同一个地方**看到全部已实现盈亏：已平仓页里期权平仓和股票卖出在一起、可以按"期权 / 股票"筛选；盈亏汇总按标的、按月把期权和股票加在一起（同一标的的期权和股票合成一行，也能看出各占多少）；首页的已实现盈亏总计、本月包含股票，持仓卡另显示有几个股票持仓。这样我对一个标的（比如做 wheel 的 IXQZ）赚了多少一目了然，也能和券商的已实现盈亏报表核对。

FEAT-011 已经在每笔股票卖出上按 FIFO 算出了被卖出成本和已实现盈亏（股票页的卖出行）。本需求**不改任何计算**，只把这些数字并入已平仓页、盈亏汇总、首页三个已有页面。

## 需要的数据和操作（给 backend）

本需求只读，不新增、不修改任何数据，不改现金、持仓，不改 FEAT-011 的 FIFO 和盈亏计算，**没有数据库迁移**。

### 1. 已平仓记录（FEAT-006 的查询，扩展）

#### 范围
结果由两类记录组成：
- **期权**：平仓（BTC / STC）和到期作废（EXP），与现在完全相同；
- **股票**：每一笔股票**卖出**一条（股票买入、转入不是记录）。

每条记录都有一个**类型**：期权 / 股票。期权交易和股票记录的 ID 是两个独立的序列（可能都有 ID 4），所以一条记录由"类型 + ID"唯一确定。

#### 股票卖出的数据（与期权行同一结构，对应关系）
| 已平仓的数据 | 期权行（不变） | 股票卖出行 |
|-------------|--------------|-----------|
| 类型 | 期权 | 股票 |
| ID | 期权交易 ID | 股票记录 ID（用于"历史"和跳转） |
| 时间 | 平仓时间（作废为到期日 16:00） | 卖出成交时间（UTC + 美东本地） |
| 标的 | 标的 | 标的 |
| 合约（到期日、行权价、C/P、合约显示名） | 有 | **没有（空）** |
| 方向 | BTC / STC / EXP，及被平持仓方向 空头 / 多头 | 股票卖出（没有空头 / 多头之分） |
| 数量 | 张数 + multiplier | **股数**（没有 multiplier） |
| 开仓净额合计（带现金方向符号） | 被平批次开仓净额之和 | **−被卖出成本**（如 `−1,125.16`，与多头期权"开仓为实付、为负"的做法一致） |
| 开仓每单位平均 | 每张平均：÷ 张数，四舍五入到分（Q22） | **每股成本**：被卖出成本 ÷ 股数，四舍五入到 **4 位小数**（Q88），只显示。例：1,125.16 ÷ 150 = 7.50106… → `7.5011` |
| 平仓净额（带符号） | BTC 负、STC 正、EXP 0.00 | **+卖出实收**（如 `+1,200.00`） |
| 平仓每单位平均 | 每张平均，到分 | **每股价格**：卖出实收 ÷ 股数，4 位小数（即股票记录的每股价格）。例：`8.0000` |
| 已实现盈亏 | 开仓净额合计 + 平仓净额 | 同一公式 = 卖出实收 − 被卖出成本（即股票记录上的已实现盈亏） |
| 被平批次 | 开仓交易 ID、时间、方向、张数、开仓净额 | **被卖出批次**：来源记录 ID、来源类型（买入 / 转入）、批次时间（转入另给日期）、扣除股数、这部分成本（带符号，为负）。FIFO 顺序 |
| 备注 | 平仓备注 | 卖出记录的备注 |
| 有审计记录 | 平仓交易本身被修改过 | 卖出记录本身被修改过（股票记录的"有审计记录"标记）；只改过它用到的买入 / 转入不算 |

#### 排序
平仓（卖出）时间倒序；同一时间：**股票卖出在期权行之上（Q92）**，同类之间后录入的在上（期权按期权交易 ID、股票按股票记录 ID，与现在相同）。

#### 筛选（全部可选，之间为"并且"）
| 条件 | 期权行 | 股票行 |
|------|-------|-------|
| **类型（新）**：期权 / 股票，不填 = 两者都要 | 选"期权"或不填时出现 | 选"股票"或不填时出现 |
| 标的（规范化后精确匹配，Q31） | 按标的 | 按标的 |
| 开始日期 / 结束日期（美东日期，两端包含，Q33） | 按平仓时间（作废按到期日 16:00） | 按卖出时间 |
| 到期日、行权价、Call/Put（Q30） | 按合约 | **不匹配**：设了任一项，股票行就不出现（Q90） |
| 方向 BTC / STC / EXP（多选） | 按方向 | **不匹配**：设了方向，股票行就不出现（Q90） |

- 类型只选"股票"同时带了期权专用条件（只可能来自手写的地址）：不报错，按"并且"得到空结果（Q90）。
- 类型的取值不合法 → 与其它枚举筛选相同的"无法解析"错误；其它条件的校验和错误文案不变。

#### 分页与合计
- 分页规则不变（页码从 1，每页 1–100，默认 20，超过最后一页返回空列表）；期权行和股票行在同一个排序里分页。
- 合计（Q46）：符合筛选条件的**全部**记录（期权 + 股票）的笔数和已实现盈亏合计。一笔股票卖出算 **1 笔**。

### 2. 盈亏汇总（FEAT-008，扩展）
- **范围**：期权平仓、到期作废（不变）+ 股票卖出。归属日期 = 卖出成交时间的**美东日期**、月份 = 该日期的美东自然月（例：美东 2026-10-31 23:30 卖出 = UTC 2026-11-01 03:30，归 2026-10）。日期范围筛选同样按此。
- **总计**：笔数、已实现盈亏合计，**另给拆分（Q91）**：期权笔数和合计、股票笔数和合计。期权 + 股票 = 总计。
- **按标的**：同一标的的期权和股票**合成一行**（如 IXQZ 的期权平仓和 IXQZ 股票卖出都在 IXQZ 行）。每行：标的、笔数、已实现盈亏合计，另给期权笔数和合计、股票笔数和合计（Q91）。标的字母序（Q49）。只有股票卖出的标的也出现。
- **按月**：每个有记录的美东月份一行，字段同上（合计 + 期权 / 股票拆分）（Q91）。月份倒序；没有任何记录的月份不显示（Q49）。
- 每个分组的合计、期权、股票三列各自加起来等于总计对应的数；同一日期范围下总计 = 已平仓页（类型不限）的合计。
- 范围内没有记录：总计 0 笔、0.00（期权、股票也都是 0 笔、0.00），两个分组都为空。

### 3. 首页概览（FEAT-008，扩展）
- **已实现盈亏总计、本月**：包含股票卖出（笔数和金额）。只给合计（是否另给拆分由 backend 决定，页面不显示，Q91）。
- **持仓概况**：期权的持仓个数、冻结合计、7 天内到期、已过期未处理 **口径和数字都不变**（只数期权）；**新增股票持仓个数**（当前持股 > 0 的标的数，等于股票持仓查询的个数）（Q89）。

### 4. 重新计算与账户
- 补录、修改、删除任何股票记录（买入、卖出、转入）或期权交易后，三个页面的数字按最新的 FIFO 重放给出（读取时计算，同 FEAT-006/011）。例：改转入的总成本 → 之后用到它的卖出的盈亏变化 → 已平仓行、合计、汇总、首页都变化。
- 只统计当前账户的记录；其它账户的股票卖出不出现、不计入（Q53）。

### 5. 对已有查询的影响（兼容性，给 backend-dev 写契约时参考）
具体字段名、参数名由 backend-dev 在契约中定义；PM 的要求是：
- **已平仓查询**：
  - 新增：每条记录的"类型"、股票行的股数、每股成本 / 每股价格（4 位小数）、被卖出批次；新增"类型"筛选条件。属于新增字段。
  - **行为变化**：不带类型条件时，结果和合计**包含股票卖出**（以前只有期权）——笔数、合计、分页会变。没有股票卖出的账户数字不变。
  - **股票行上期权专用的字段为空**（到期日、行权价、C/P、合约显示名、multiplier、空头/多头、期权被平批次）；"ID"不再在两类之间唯一，需要和类型一起使用。现有前端按"每行都是期权"处理的地方都要改。

- 期权交易列表、期权持仓、股票交易列表、股票持仓、资金、审计的查询都不变。

## 边界情况
- **期权和股票 ID 重复**：两类各自编号，已平仓行、"历史"、跳转都按"类型 + ID"区分（验收 8）。
- **同一标的既有期权又有股票**：按标的汇总合成一行，拆分列分别显示（验收 9）；已平仓页按标的筛选两类都出现（验收 3）。
- **只做过股票的标的**：汇总里期权列为 `—`（QRTV，验收 9）。
- **期权专用筛选**：只匹配期权行；只看股票时禁用（验收 4，Q90）。
- **深夜 / 盘后卖出**：按美东日期和月份归属（S3，验收 5、12）；股票卖出不检查交易时段（FEAT-011）。
- **同一时间的期权平仓与股票卖出**：股票在上（验收 7，Q92）。
- **盈亏为 0.00 的卖出**：显示 `0.00`、不着色，计 1 笔。
- **转入 / 买入**：没有盈亏、不计笔数，但改它们会改变之后卖出的盈亏（验收 13）。
- **一笔卖出跨多个批次、部分卖出按比例四舍五入**：按 FEAT-011 原样显示（验收 2）。
- **到期作废**：仍属于"期权"（类型筛选"期权"包含 BTC、STC、EXP）。
- **多账户**：只看当前账户（验收 14）。
- **以后的指派 / 行权**：FEAT-013/014 产生的股票卖出（call 被指派交出股票）和批次以后会自然出现在这里，口径由那些需求定。
- **股息**：不计入（Q26）。**拆股**：不在本需求（FEAT-028）。

## Out of Scope
- 任何计算口径的变化（FIFO、分摊舍入、每股 4 位小数都按 FEAT-011）
- 盈亏汇总页按类型筛选、按类型的单独汇总页；拆分列可点击跳转
- 首页显示期权 / 股票拆分（Q91：只在汇总页拆分）

**设计决定**：
- 不改任何计算、不落库、无迁移：股票数字直接取 FEAT-011 的 `StockTradeService.views`（FIFO 重放）。
- 已平仓的期权行与股票行合并成一个列表后按 `ClosedRecordKey.NEWEST_FIRST` 排序，再算合计、在内存中分页（不是各自分页），所以 `page`/`size` 在两类之间正确。
- 期权专用条件只在后端判定（`ClosedRecordFilter.includesStocks`）；`type=STOCK` + 期权条件按"并且"得到空结果，不报错（Q90）。`action` 仍只接受 BTC / STC / EXP（不接受 `SELL`）。
- 首页的股票持仓个数放在新的顶层对象 `stockPositions`，不往 `positions`（期权）里加字段，使期权持仓对象保持不变。
- 股票行的 `costPerShare` / `pricePerShare` 为正数（页面显示"每股 7.5011"无符号），被卖出批次给带符号的 `netAmount`（页面显示 `−750.00`），与期权 `coveredLots[].netAmount` 同一惯例。

**已知限制**：每次请求重放所有涉及的合约和有卖出的标的（个人数据量小）。
