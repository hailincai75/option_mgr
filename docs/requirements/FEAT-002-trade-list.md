# FEAT-002: 交易列表与筛选

- **Status:** Verified
- **Priority:** P0
- **Depends on:** FEAT-001（录入开仓期权交易，已 Verified）
- **Scope:**
  - [x] Backend: Done
  - [x] Frontend: Done

## 背景 / 用户故事
作为一个期权交易者，我想要在一个页面上按时间倒序看到我录入的所有期权交易，并能按标的、合约、方向、日期范围筛选，以便核对某个标的/合约的全部开平仓记录、和券商成交记录对账。

本需求只做**查看**：不新增、不修改、不删除交易。目前系统里只有开仓（BTO / STO，FEAT-001）；平仓（BTC / STC）在 FEAT-004 加入后要**不改本需求**就能出现在列表里并能被筛选。修改/删除在 FEAT-005。

## 已定的口径（来自 backlog Open Questions 和 FEAT-001）
- 单账户、只有 USD（Q3、Q4）
- 每笔交易只有一个**含手续费的净额**，没有成交价、没有手续费（Q6）。列表显示净额，不显示价格
- 成交时间按美东时间（America/New_York）显示（Q14）
- 合约 = 标的 + 到期日 + 行权价 + Call/Put；行权价按数值比较（`200` 与 `200.0` 是同一合约，FEAT-001）
- 标的格式：去首尾空格、转大写，1–10 位字母/数字/点（Q25）
- 同一时间的多条记录按录入顺序排（Q19）
- 分页口径与 FEAT-007 现金流水一致：页码从 1 开始，每页条数 1–100，默认 20
- 合约筛选 = 到期日、行权价、Call/Put 三个独立的可选条件，可以与标的任意组合；四项都填即一个具体合约（Q30）
- 标的筛选 = 精确匹配（规范化后），不做前缀/模糊匹配（Q31）
- 方向筛选 = 可多选，现在就包含 BTC / STC（Q32）
- 日期范围按成交时间的**美东日期**、两端都包含，可只填一端（Q33）

## 需要的数据和操作（给 backend）

### 操作：查询交易列表
返回所有期权交易（不论方向；FEAT-004 之后包括 BTC / STC），按筛选条件过滤后排序、分页。

**排序（固定，不可由用户改变）**
1. 成交时间倒序（最新在上）
2. 成交时间相同时，**后录入的在上**（与 FEAT-007 流水一致）

**每笔交易需要返回的数据**（与 FEAT-001 按 ID 查询一笔交易时的内容一致即可，前端不做任何计算）：
- 交易 ID
- 标的、到期日、行权价（去尾零，可直接显示）、Call/Put、合约显示名（如 `AAPL 2026-12-18 200 P`）
- 方向（BTO / STO，以后 BTC / STC）
- 张数、multiplier
- 净额（正数）
- 对总现金的带符号影响（STO / STC 为 +净额，BTO / BTC 为 −净额）
- 对冻结现金的带符号影响（STO put 为 +担保金额；BTO 为 0；以后 BTC 平空头 put 释放冻结为负）
- 成交时间（UTC 时间点 + 对应的美东本地时间，方便前端直接显示）
- 备注

**分页信息**：本页条目、当前页码、每页条数、符合筛选条件的总条数、总页数。
- 页码从 1 开始；超过最后一页时返回空列表（不是错误）
- 每页条数 1–100，默认 20；页码默认 1
- 没有任何符合条件的交易时：总条数 0、总页数 0、空列表

**筛选条件**（全部可选；不传或传空值 = 不按该条件筛选；多个条件之间是"并且"）

| 条件 | 规则 |
|------|------|
| 标的 | 先去首尾空格、转大写，再与交易的标的**精确**相等（`aapl` 能查到 `AAPL`；`AAP` 查不到 `AAPL`）。格式不合法（不满足 Q25：1–10 位字母/数字/点）→ 字段校验错误 |
| 到期日 | 与交易的到期日相等。日期格式不对或日期不存在（如 2026-02-30）→ 请求无法解析错误（与 FEAT-001 一致） |
| 行权价 | 按**数值**与交易的行权价相等（`200`、`200.0`、`200.000` 等价）。须 > 0、最多 3 位小数，否则字段校验错误；不是数字 → 请求无法解析错误 |
| Call/Put | Call 或 Put。不是这两个值 → 请求无法解析错误 |
| 方向 | 可以选一个或多个（BTO / STO / BTC / STC），选中的方向之间是"或者"。BTC / STC 现在就是合法的筛选值（FEAT-004 之前结果为空，不报错）。不认识的值 → 请求无法解析错误 |
| 开始日期 | 美东日期。成交时间换算成美东日期后 **≥ 开始日期** 的交易 |
| 结束日期 | 美东日期。成交时间换算成美东日期后 **≤ 结束日期** 的交易（**包含**结束日期当天整天，直到美东 23:59:59.999…） |

- 开始日期、结束日期可以只填一个；都填时开始日期不得晚于结束日期，否则字段校验错误（指向结束日期或开始日期均可，由 backend 定，写进契约）。开始 = 结束表示只看这一天。
- 日期范围可以包含未来日期（结果自然为空或只到今天），不报错。
- 日期按**美东日期**判断，不是 UTC 日期。例：美东 2026-11-03 23:30（= UTC 2026-11-04 04:30）属于 2026-11-03。夏令时期间同理（美东 2026-07-15 21:00 = UTC 2026-07-16 01:00，属于 2026-07-15）。
- 字段校验错误要返回能直接显示在对应筛选项下的中文原因（与 FEAT-001 录入表单的文案风格一致）。

### 其它
- 不新增、不修改任何数据；不影响现金汇总和流水。
- FEAT-001 的按 ID 查询一笔交易保持不变。

## 页面与交互（给 frontend）

### 入口与页面
- 新增"交易"页面（交易列表），顶部导航有入口（如"交易"），与已有的"录入开仓""资金"并列。
- 页面上有一个去"录入开仓"的按钮/链接。
- 本需求**不做交易详情页**；列表行已经显示一笔交易的全部字段（详情页和审计历史在 FEAT-005 做）。

### 列表（表格）
按后端返回的顺序显示，每行一笔交易，列如下：

| 列 | 显示 |
|----|------|
| 成交时间 | 美东时间 `YYYY-MM-DD HH:mm`（如 `2026-11-03 10:30`），表头或页面上注明"美东时间" |
| 方向 | 代码 + 中文：`BTO（买入开仓）`、`STO（卖出开仓）`；以后 `BTC（买入平仓）`、`STC（卖出平仓）`。不认识的值原样显示 |
| 合约 | 后端给的合约显示名，如 `AAPL 2026-12-18 200 P`；可点击，点击后把筛选设为该合约（标的 + 到期日 + 行权价 + C/P），回到第 1 页 |
| 张数 | 如 `2`；multiplier ≠ 100 时附注，如 `1（multiplier 10）` |
| 净额 | 带方向符号的现金变动：流入 `+349.35`（绿色），流出 `−512.65`（红色）。用统一格式化 util：千分位、2 位小数、负号 `−` |
| 冻结变动 | 非 0 时带符号显示（如 `+20,000.00`），0 显示 `—`（与资金页流水一致） |
| 备注 | 备注全文；过长时可截断显示，鼠标悬停或展开能看到全文；没有备注显示 `—` |

- 前端不计算任何金额，只格式化后端返回的值。
- 列表下方：分页器 + "共 N 条"。每页默认 20 条，可选 20 / 50 / 100。

### 筛选区
- 筛选项：标的（文本）、到期日（日期）、行权价（文本）、Call/Put（不选 / Call / Put）、方向（多选 BTO / STO / BTC / STC）、开始日期、结束日期（日期，注明"美东日期"）。
- "查询"按钮应用筛选；"清除筛选"按钮清空所有条件并回到第 1 页。（是否在输入时自动查询由 frontend 决定，但不能每敲一个字就发请求造成闪烁。）
- 改变筛选条件后**总是回到第 1 页**。
- 前端格式校验（与后端规则一致，错误显示在对应筛选项下，不发请求）：标的格式、行权价 > 0 且最多 3 位小数、开始日期不晚于结束日期。后端返回字段错误时同样显示在对应筛选项下。

### 地址栏（可收藏、可分享）
- 当前的筛选条件、页码、每页条数都反映在页面地址的查询参数里（参数名由 frontend 定）。
- 直接打开带参数的地址（或刷新页面）时，筛选区回填这些条件，列表显示对应结果。
- 浏览器"后退"回到上一次的筛选/页码状态。
- 地址里的参数不合法（如手工改成开始日期晚于结束日期、行权价为 `abc`）时，页面不崩溃：在对应筛选项下显示错误，用户可以修改或"清除筛选"。

### 空状态、加载与错误
- 系统中一笔交易都没有（且没有筛选条件）：显示"暂无交易"，并提供"录入开仓"入口。
- 有筛选条件但没有结果：显示"没有符合条件的交易"，并提供"清除筛选"。
- 加载中显示加载状态；请求失败显示错误信息和"重试"按钮（沿用现有 `QueryError` 的做法）。

### 与录入页的联动
- 在"录入开仓"页成功保存一笔交易后，再打开交易列表时**无需手动刷新**就能看到这笔交易（录入成功后让交易列表的缓存失效）。

## 验收标准
除特别说明，以下场景使用同一组数据（"**基准数据**"），从空库开始，通过 FEAT-007 / FEAT-001 录入，当前时间不早于 2026-11-05 10:00（美东；后端测试可用可调时钟固定为这个时间，E2E 直接用真实时钟）：

入金 100,000.00（2026-10-26 10:00），然后**按以下顺序**录入 6 笔交易（录入顺序即编号 T1–T6）：

| 编号 | 方向 | 合约 | 张数 | multiplier | 净额 | 成交时间（美东） | 备注 |
|------|------|------|------|-----------|------|-----------------|------|
| T1 | STO | AAPL 2026-12-18 200 P | 1 | 100 | 349.35 | 2026-11-03 10:30 | 第一笔 CSP |
| T2 | BTO | AAPL 2026-12-18 210 C | 1 | 100 | 512.65 | 2026-11-03 10:30 | — |
| T3 | STO | F 2026-12-18 12.5 P | 2 | 100 | 48.70 | 2026-11-02 15:59 | — |
| T4 | STO | AAPL 2026-12-18 200 P | 1 | 100 | 360.00 | 2026-11-04 11:00 | 加仓 |
| T5 | BTO | MSFT 2027-01-15 450 C | 1 | 100 | 900.00 | 2026-11-03 23:30 | — |
| T6 | STO | XYZ 2026-12-18 200 P | 1 | 10 | 34.35 | 2026-10-30 10:00 | — |

（全部录入后现金汇总应为 总现金 99,379.75、冻结 44,500.00、可用 54,879.75，现金流水 7 条，仅用于确认数据准备正确。）

1. **默认排序与列显示**
   **When** 打开交易页面，不加任何筛选
   **Then** 显示 6 行，"共 6 条"，从上到下依次为 T4、T5、T2、T1、T3、T6（T1 与 T2 成交时间相同，后录入的 T2 在上）。
   **And** 各行显示：
   - T4：`2026-11-04 11:00`、`STO（卖出开仓）`、`AAPL 2026-12-18 200 P`、`1`、`+360.00`、冻结变动 `+20,000.00`、备注"加仓"
   - T5：`2026-11-03 23:30`、`BTO（买入开仓）`、`MSFT 2027-01-15 450 C`、`1`、`−900.00`、冻结变动 `—`、备注 `—`
   - T2：`2026-11-03 10:30`、`BTO（买入开仓）`、`AAPL 2026-12-18 210 C`、`1`、`−512.65`、冻结变动 `—`
   - T1：`2026-11-03 10:30`、`STO（卖出开仓）`、`AAPL 2026-12-18 200 P`、`1`、`+349.35`、冻结变动 `+20,000.00`、备注"第一笔 CSP"
   - T3：`2026-11-02 15:59`、`STO（卖出开仓）`、`F 2026-12-18 12.5 P`、`2`、`+48.70`、冻结变动 `+2,500.00`
   - T6：`2026-10-30 10:00`、`STO（卖出开仓）`、`XYZ 2026-12-18 200 P`、`1（multiplier 10）`、`+34.35`、冻结变动 `+2,000.00`
   **And** 页面上没有任何"价格""每张价格""手续费"列。

2. **按标的筛选（精确匹配、自动规范化）**
   **When** 标的填 `aapl` 查询 **Then** 依次显示 T4、T2、T1，"共 3 条"。
   **When** 标的填 ` AAPL `（前后有空格）**Then** 结果同上。
   **When** 标的填 `AAP` **Then** 显示"没有符合条件的交易"，"共 0 条"，有"清除筛选"按钮。
   **When** 标的填 `$AAPL` **Then** 标的筛选项下显示格式错误（如"标的只能包含字母、数字和点"），不显示错误的查询结果。

3. **按合约筛选**
   **When** 标的 `AAPL`、到期日 2026-12-18、行权价 `200`、类型 Put **Then** 依次显示 T4、T1，"共 2 条"。
   **When** 行权价改为 `200.00`，其余相同 **Then** 结果同上（行权价按数值比较）。
   **When** 只填到期日 2026-12-18 **Then** 依次显示 T4、T2、T1、T3、T6，"共 5 条"（T5 到期日不同，不显示）。
   **When** 只选类型 Call **Then** 依次显示 T5、T2，"共 2 条"。
   **When** 只填行权价 `12.5` **Then** 只显示 T3。
   **When** 行权价填 `0`、`-5`、`200.1234` 中任一 **Then** 行权价筛选项下显示错误，不查询。
   **When**（无筛选时）点击 T6 行的合约 `XYZ 2026-12-18 200 P` **Then** 筛选区变为 标的 XYZ、到期日 2026-12-18、行权价 200、Put，列表只显示 T6，位于第 1 页。

4. **按方向筛选（可多选）**
   **When** 方向只选 STO **Then** 依次显示 T4、T1、T3、T6，"共 4 条"。
   **When** 方向只选 BTO **Then** 依次显示 T5、T2，"共 2 条"。
   **When** 方向选 BTO 和 STO **Then** 6 条全部显示，顺序同第 1 条。
   **When** 方向只选 BTC（或 STC）**Then** 显示"没有符合条件的交易"，不报错。

5. **按日期范围筛选（美东日期，两端包含）**
   **When** 开始日期 2026-11-03、结束日期 2026-11-03 **Then** 依次显示 T5、T2、T1，"共 3 条"（T5 美东 2026-11-03 23:30，UTC 已是 2026-11-04 04:30，仍算 2026-11-03）。
   **When** 开始日期 2026-11-04、结束日期 2026-11-04 **Then** 只显示 T4（T5 不在内）。
   **When** 只填开始日期 2026-11-03 **Then** 依次显示 T4、T5、T2、T1。
   **When** 只填结束日期 2026-11-02 **Then** 依次显示 T3、T6。
   **When** 开始日期 2026-11-04、结束日期 2026-11-03 **Then** 日期筛选项下显示"开始日期不能晚于结束日期"之类的错误，不查询。
   **When** 开始日期 2026-11-06、结束日期 2099-12-31（范围内没有交易，且包含未来日期）**Then** 显示"没有符合条件的交易"，不报错。
   **And Given** 另一空库：入金 1,000.00（2026-07-01 10:00），录入 BTO 1 张 AAPL 2026-12-18 210 C 净额 100.00，成交时间 2026-07-15 21:00（美东，夏令时；UTC 2026-07-16 01:00）
   **When** 开始 = 结束 = 2026-07-15 **Then** 显示这一笔；**When** 开始 = 结束 = 2026-07-16 **Then** 没有结果。

6. **组合筛选**
   **When** 标的 `AAPL`、方向 STO、开始日期 2026-11-03、结束日期 2026-11-04 **Then** 依次显示 T4、T1，"共 2 条"。
   **When** 再把结束日期改为 2026-11-03 **Then** 只显示 T1。
   **When** 点击"清除筛选" **Then** 所有筛选项清空，6 条全部显示，回到第 1 页。

7. **分页**
   **Given** 另一空库：入金 100,000.00（2026-08-01 10:00），录入 45 笔 BTO 1 张 AAPL 2026-12-18 210 C，每笔净额 1.00，成交时间从 2026-09-01 10:00 起每天一笔（最后一笔 2026-10-15 10:00）
   **When** 打开交易页面 **Then** "共 45 条"，每页 20 条，共 3 页；第 1 页第一行是 2026-10-15 10:00；第 3 页有 5 行，最后一行是 2026-09-01 10:00；翻页能看到全部 45 条，没有重复和遗漏。
   **When** 每页条数改为 50 **Then** 1 页显示全部 45 条。
   **When** 在第 3 页时，筛选开始日期 2026-10-01 **Then** 回到第 1 页，"共 15 条"（2026-10-01 至 2026-10-15）。
   **And**（后端）请求第 4 页（每页 20）→ 返回空列表、总条数 45、总页数 3；每页条数 0 或 101、页码 0 → 字段校验错误。

8. **空状态**
   **Given** 空库（可以有入金，但没有交易）**When** 打开交易页面 **Then** 显示"暂无交易"和"录入开仓"入口，没有表格行。

9. **地址栏可收藏**
   **Given** 基准数据
   **When** 筛选标的 `AAPL`、方向 STO 并查询 **Then** 地址栏包含这些条件；复制该地址在新标签页打开（或刷新页面），筛选区回填 AAPL 和 STO，列表依次显示 T4、T1。
   **When** 接着把方向改为 BTO 查询，再点浏览器"后退" **Then** 回到 AAPL + STO 的筛选和结果。
   **When** 直接打开一个开始日期晚于结束日期的地址（如开始 2026-11-04、结束 2026-11-03）**Then** 页面正常显示，日期筛选项下有错误提示；点击"清除筛选"后显示全部 6 条。

10. **新录入的交易自动出现**
    **Given** 基准数据，已打开过交易页面
    **When** 到"录入开仓"页录入 STO 1 张 F 2026-12-18 12.5 P，净额 25.00，成交时间 2026-11-05 09:45，然后回到交易页面
    **Then** 无需手动刷新，第一行就是这笔（`2026-11-05 09:45`、`+25.00`、冻结变动 `+1,250.00`），"共 7 条"。

11. **只读，不影响现金**
    **Given** 基准数据 **When** 在交易页面做任意筛选、翻页 **Then** 现金汇总仍为 99,379.75 / 44,500.00 / 54,879.75，现金流水条数不变（7 条）。

## 边界情况
- **同一成交时间多笔**：后录入的在上（验收 1：T2 在 T1 上）。
- **同一合约多次开仓**：每笔一行，不合并（验收 3：T4、T1 两行）。合并显示是 FEAT-003 持仓的事。
- **美东日期 vs UTC 日期**：日期范围按美东日期，含夏令时（验收 5）。
- **夏令时切换当天**：成交时间换算成美东日期后再比较，切换当天的交易按其美东本地日期归属，不会因为 23/25 小时的一天而漏掉。
- **周末 / 美股假日**：日期范围可以是任意日期，不检查交易日。
- **行权价写法不同**：`200`、`200.0`、`200.000` 视为同一行权价（验收 3）。
- **非标准 multiplier**：张数列附注 multiplier（验收 1 的 T6）。
- **平仓交易（FEAT-004 之后）**：自动出现在列表中、可被方向筛选；方向显示 `BTC（买入平仓）` / `STC（卖出平仓）`，净额 BTC 为负、STC 为正，BTC 平空头 put 时冻结变动为负。本需求不需要为此单独实现或验收；FEAT-004 验收时一并检查列表。
- **修改/删除交易（FEAT-005 之后）**：列表显示修改后的值、不显示已删除的交易；本需求不涉及。
- **超过最后一页**：返回空列表、不报错（验收 7）。用户在最后一页时数据变少（以后有删除时），前端应能回到有数据的页，不显示空白页（实现方式由 frontend 定）。
- **很长的备注**（500 字符）：表格不能被撑破，可截断 + 悬停看全文。
- **标的拆股**：不在本需求（FEAT-028）。

## Out of Scope
- 交易详情页、从列表进入详情（FEAT-005 做修改/删除和审计历史时一起做）
- 在列表里新增、修改、删除交易（FEAT-001 / FEAT-004 / FEAT-005）
- 按其它列排序（只有固定的成交时间倒序）
- 筛选结果的合计（如净额合计、权利金合计）——盈亏与汇总在 FEAT-006 / FEAT-008
- 按备注搜索、按 multiplier 筛选、按"未平仓/已到期"状态筛选（持仓状态见 FEAT-003 / FEAT-010）
- 标的前缀/模糊匹配（Q31 已定为精确匹配）
- 从现金流水跳转到交易、从交易跳转到现金流水
- 导出 CSV（FEAT-029）
- 股票交易（FEAT-011）、策略分组筛选（FEAT-021）
- 任何券商接入

## Open Questions
无。Q30（合约筛选 = 三个独立可选条件）、Q31（标的精确匹配）、Q32（方向多选，含 BTC / STC）、Q33（美东日期、两端包含）均已由用户按 PM 建议确认，见上方"已定的口径"和 backlog。

## Implementation Notes
### Backend
**API**（详见 `docs/api/api-contract.md` 的 FEAT-002 小节）
- `GET /api/option-trades?symbol=&expirationDate=&strike=&optionType=&action=&startDate=&endDate=&page=&size=`，全部可选；不传、空串或全空白 = 不筛选
- 返回 `{items, page, size, totalItems, totalPages}`；`items[]` 与 `GET /api/option-trades/{id}` 的响应体完全相同（含 `contractLabel`、`strike` 去尾零、`tradedAt` + `tradedAtLocal`、`cashChange`、`frozenChange`、`note`、`ledgerEntryId`），前端直接显示即可
- 固定排序：`tradedAt` 倒序，同一时间 `id` 大（后录入）的在上
- `action` 多选：重复参数 `action=BTO&action=STO` 或逗号分隔 `action=BTO,STO`；`BTC`/`STC` 合法，目前结果为空
- `optionType` / `action` 的取值区分大小写（`CALL`/`PUT`、`BTO`…，与 FEAT-001 一致）；`symbol` 不区分（会转大写）
- 错误（`details[].field` = query 参数名，`message` 中文，可直接显示在对应筛选项下）：
  - 400 `BAD_REQUEST`：日期格式不对/日期不存在（`expirationDate`/`startDate`/`endDate`）、`strike` 不是数字、`optionType`/`action` 取值不对、`page`/`size` 不是整数
  - 400 `VALIDATION_ERROR`：`symbol` 格式、`strike` ≤ 0 / 超过 3 位小数 / 过大、`startDate` 晚于 `endDate`（**field = `endDate`**，"开始日期不能晚于结束日期"）、`page` < 1、`size` 不在 1–100
  - 同一请求里所有同类问题一起返回；既有无法解析又有不满足规则时只报 `BAD_REQUEST`

**文件**
- 新增 `trade/domain/TradeFilter`、`trade/repository/OptionTradeSpecifications`、`trade/web/TradeListQuery`
- 修改 `trade/service/OptionTradeService`（`list`、`TradePage`、`TRADE_SOURCE_TYPES`、按 id 查询改用批量查流水）、`trade/web/OptionTradeController`（`GET /api/option-trades`）、`trade/web/OptionTradeDtos`（`TradePageResponse`）、`trade/repository/OptionTradeRepository`（`JpaSpecificationExecutor`）、`cash/service/CashLedgerService` + `CashLedgerEntryRepository`（`findBySources` 批量查流水）
- 没有数据库迁移（只读）
- 测试：`trade/domain/TradeFilterTest`（美东日期边界，含夏令时与切换当天）、`trade/web/OptionTradeListControllerTest`（验收 1–8、11 的后端部分）
- 文档：`docs/api/api-contract.md`（FEAT-002 小节）、`docs/architecture.md`

**设计决定**
- 日期范围按美东日期：`startDate` → 该日美东 00:00 的时间点（含），`endDate` → 次日美东 00:00（不含），在数据库里按 `traded_at` 范围查询；夏令时切换当天（23/25 小时）也正确
- 行权价按数值比较：参数去尾零后与 `NUMERIC` 列比较（`200` = `200.00` = `200.000`）
- 行权价筛选沿用 FEAT-001 的上限（≤ 9,999,999.999，Q29）
- 起止日期颠倒时错误挂在 `endDate` 上
- 无法解析（`BAD_REQUEST`）优先于规则校验（`VALIDATION_ERROR`）；前者的 message 也给了中文（与 FEAT-001 的 `BAD_REQUEST` 不同，那边是英文通用文案）
- FEAT-004：平仓交易写入同一表后，只需把 `OPTION_CLOSE` 加进 `OptionTradeService.TRADE_SOURCE_TYPES`，列表/筛选/按 id 查询即可显示平仓

**已知限制**
- `totalItems`、`totalPages` 与本页数据是两次查询，极少数情况下（两次查询之间有新录入）可能不完全一致；单用户场景可接受

**地址栏**
- 参数名与 API 相同：`symbol`、`expirationDate`、`strike`、`optionType`、`action`（逗号分隔，如 `action=BTO,STO`；也接受重复参数）、`startDate`、`endDate`、`page`、`size`。空条件、`page=1`、`size=20` 不写入
