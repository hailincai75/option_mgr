## 背景 / 用户故事
作为一个期权交易者，我的期权到期时大多数是价外、没有价值，直接作废。现在这些持仓过了到期日只能一直显示"已过期 N 天"（Q34），卖出 put 的担保现金也一直冻结着。

到期日当天有两个时间点：美东 16:00 停止交易；但直到美东 17:30 券商仍接受行权指令，期权仍可能被指派，所以 17:30 之后结果才确定。

我想要在持仓页对一个已到期（17:30 之后）的持仓点一下"作废"：这个合约剩下的全部张数一次清掉，空头保留全部权利金、多头亏掉全部开仓成本，计入已实现盈亏；卖出 put 冻结的现金释放出来。作废记在到期日美东 16:00，不管我哪天才去点，盈亏都算在到期那个月。点错了可以删除，账目恢复原样并留下审计记录。

（我账户里有 2026-11-20 到期的期权，这是 M2 第一个要做的需求。）

## 已定的口径
来自 backlog Open Questions，本需求新定的：
- **Q9 手动作废**：系统不自动作废。到期后由用户在持仓行上点"作废"确认；没处理的持仓继续显示"已过期 N 天"并标红（Q34）。
- **Q83 到期日的两个时间点（收紧 Q36）**：
  - **16:00 停止交易**：从 FEAT-012 起，某合约的开仓、平仓，成交时间晚于该合约到期日**美东 16:00:00** 的一律拒绝。**正好 16:00:00 允许**（≤ 16:00），16:00:01 起拒绝。新增（FEAT-001 开仓、FEAT-004 平仓）和修改（FEAT-005，改后的成交时间）都适用。成交日晚于到期日的照旧拒绝（Q36 / FEAT-001 原有规则和提示不变）。
  - **17:30 结果确定**：17:30 之前仍可能被指派，所以作废从 17:30 起才能做（见 Q10）。
  - 已存储的数据不追溯拒绝：FEAT-012 之前录入的、成交时间在到期日 16:00 之后的交易（下称"旧的 16:00 之后交易"）保留，处理见"旧的 16:00 之后交易"一节。
- **Q10 何时可以作废**：从到期日**美东 17:30** 起（含 17:30）。持仓页在到期日当天：16:00 之前只有"平仓"；16:00 到 17:30 之前显示"到期待确认"、没有任何按钮；17:30 起只有"作废"；到期日之后只有"作废"。
- **Q63 记账时间**：作废记录的时间固定为**到期日美东 16:00**（不是 17:30），用户不填；与点按钮的时刻无关。盈亏按这个时间归属日期和月份，冻结也从这个时间起释放。
- **Q64 在哪里出现**：作废是一条"到期作废"记录——
  - 交易列表：一行，方向显示"到期作废"，张数，净额 `0.00`，可按方向筛选；
  - 已平仓页：一行（平仓净额 `0.00`），算已实现盈亏，进入合计、盈亏汇总和首页；
  - 资金流水：**只在释放冻结时**出现一行（现金 `0.00`、冻结 −X）；不释放冻结（多头、空头 call）时不出现。
- **Q65 作废全部剩余张数**：不填张数，该合约当时剩下的所有批次一起作废。部分被指派时，先记指派（FEAT-013），再作废剩下的。作废之后如果又补录了一笔到期日之前的同合约开仓，它不在这次作废里，持仓页会显示"已过期"，再点一次作废即可。
- **Q66 可以删除（撤销），没有可修改的字段**：删除后持仓恢复原样、冻结恢复，写审计（同删除交易），并按 Q19 重放检查——恢复冻结后之后某时点可用现金为负则拒绝。记错就删掉重记。
- **Q84 不能填备注**：作废一键确认，不填任何内容；备注显示 `—`。

沿用的口径：
- 空头 put 作废时释放该批次冻结的现金（Q13）；释放额 = 被作废批次的冻结之和（每笔开仓已按 Q28 向上取整，不重新计算）
- 空头 call 不冻结现金，作废释放 0（FEAT-038）
- 已实现盈亏按**每笔作废整体**计算，直接用净额（Q6、Q21）：空头 = 被作废批次开仓实收之和 − 0；多头 = 0 − 被作废批次开仓实付之和
- 按 `(时间, 录入顺序)` 重放；补录、修改、删除都把改动应用到全部历史上重放，任何一笔记录或任何一个时点不成立就整笔拒绝（Q19、Q27、Q39、FEAT-005）
- 新增不写审计，修改/删除写审计；修改/删除引起的连带改正写进同一条审计的"连带变化"（Q42）；"历史"入口只对有审计记录的行显示（M1.5 小改动）
- 到期日之后不能平仓（Q36）；开仓的成交日不能晚于到期日（FEAT-001）；FEAT-012 起两者都进一步收紧到"不晚于到期日 16:00"（Q83）
- 所有规则按账户独立（Q53）
- 前端不做任何金额、盈亏、冻结计算

## 需要的数据和操作（给 backend）

### 到期作废记录
| 数据 | 规则 |
|------|------|
| 所属账户 | 当前账户（Q53），不能改 |
| 合约 | 标的、到期日、行权价、Call/Put |
| 方向 | "到期作废"（与 BTO/STO/BTC/STC 并列的一种记录类型；被作废的持仓方向——空头 / 多头——由重放得出） |
| 张数 | 作废时该合约**在到期日 16:00 时点**的全部持仓张数（Q65），作废时确定后保存，不能修改 |
| multiplier | 取持仓的 multiplier（同平仓） |
| 时间 | 到期日美东 16:00，存 UTC（例：2026-11-20 16:00 美东 = `2026-11-20T21:00:00Z`；2027-03-19 16:00 美东（夏令时）= `2027-03-19T20:00:00Z`） |
| 净额 | 恒为 `0.00`（没有现金收付） |
| 现金变动 | `0.00` |
| 冻结变动 | −（被作废批次的剩余冻结之和）；多头、空头 call 为 `0.00` |
| 备注 | 无（Q84：创建时不能填；Q66：没有可改的字段），显示 `—` |
| 录入顺序 | 作废记录创建时的顺序，与交易共用"同一时间按录入顺序"的排序 |

作废记录是一种期权记录，和交易一起出现在交易列表、按 ID 查询、合约重放中；是否与交易共用 ID 编号、如何存储由 backend 决定。

### 在重放中的位置与匹配（重点）
- 作废记录按 `(时间 = 到期日 16:00, 录入顺序)` 与该合约的交易一起重放：
  - 到期日 16:00 之前的交易都在它之前；
  - 成交时间**正好是**到期日 16:00 的交易：在作废之前录入的排在它前面，之后录入的排在它后面（与 Q19 "同一时间按录入顺序"一致）；
  - 到期日 16:00 之后的同合约交易 FEAT-012 起不能再录入（Q83）；只有旧的 16:00 之后交易可能存在，它们排在作废后面，处理见"旧的 16:00 之后交易"。
- 匹配：和平仓一样按 FIFO 匹配**整笔**批次（Q21）。作废时它的张数就是当时的全部持仓，所以覆盖全部剩余批次；之后补录/修改/删除较早的交易时，保存的张数按新的 FIFO 重新匹配（Q39 的同一做法），必须正好是最早 1 笔或连续多笔整批次之和，且不超过当时持仓，否则拒绝那次补录/修改/删除。
- 已实现盈亏、被作废批次、释放冻结都按重放得出（与平仓一致），补录/修改/删除后按新匹配；释放冻结有变化时改正作废记录的冻结变动（只会因 Q28 取整差异或批次重新匹配引起）。

### "剩余张数"的含义
- = 到期日 16:00 时点该合约的净持仓张数（包括所有开仓日期不同的批次：例如 11-03 开 2 张、11-05 开 1 张、11-18 平掉 11-03 那笔 → 剩余 1 张，就是 11-05 那笔）。
- 正常情况下（没有旧的 16:00 之后交易）就等于持仓页显示的张数；有旧的 16:00 之后交易时作废会被拒绝（操作 1 第 4 步），不会出现两者不一致还能作废的情况。
- 持仓页给出的"作废张数"由后端提供，前端不计算。

### 操作 1：作废一个持仓
输入：合约（标的、到期日、行权价、Call/Put）+ 用户在页面上看到的张数（只用于防止"对话框打开期间持仓已变化"，不是用户填写的值）。

按顺序检查，任一失败就整笔拒绝、什么都不保存，返回能直接给用户看的中文原因：
1. **时间（Q10）**：当前时间 ≥ 到期日美东 17:30，否则拒绝，如"到期日（2026-11-20）美东 17:30 起才能作废"。
2. **有持仓**：在到期日 16:00 时点（同一时间已有的记录排在本次之前）该合约有持仓，否则拒绝，如"该合约（XYZ 2026-11-20 45 P）没有持仓，无法作废"（包括已经作废过、已全部平仓）。
3. **张数与页面一致**：到期日 16:00 时点的持仓张数 ≠ 请求里的张数 → 拒绝，如"持仓已变化（当前 4 张），请刷新后重试"。
4. **没有旧的 16:00 之后交易**：该合约（当前账户）存在成交时间晚于到期日 16:00:00 的交易（只可能是 FEAT-012 之前录入的）→ 拒绝，提示最早的那一笔，如"2026-11-20 16:10 的 BTC 2 张晚于到期日美东 16:00，与到期作废冲突；请先把这笔交易的时间改为 16:00 或之前，或删除它"。理由见"旧的 16:00 之后交易"。
5. **现金**：作废只释放冻结、不动现金，不会造成不足；仍按 Q19 重放确认（实现上可省略，但不能出现为负）。

保存成功后的效果：
- 该合约在到期日 16:00 时点的全部批次被作废；持仓页不再有该合约（除非之后又有补录的批次）。
- 已实现盈亏（后端计算）：空头 = 被作废批次开仓净额之和；多头 = −被作废批次开仓净额之和。
- 冻结：空头 put 释放被作废批次的冻结之和，**从到期日 16:00 起**生效（之后各时点的可用现金随之增加）；空头 call、多头不变。
- 资金流水：只有释放冻结 > 0 时新增一条，来源类型"到期作废"，时间 = 到期日 16:00，金额 `0.00`，冻结变动 −释放额，说明如 `到期作废 3 张 XYZ 2026-11-20 45 P`（multiplier ≠ 100 时同 FEAT-001 加注，如 `（multiplier 1）`）。
- 不写审计（与新增交易一致，Q42）；"有审计记录"标记为否。
- 返回本次作废的结果：合约、方向（被作废的是空头还是多头）、张数、时间、冻结变动、被作废批次（每批：开仓交易 ID、开仓时间、方向、张数、开仓净额）、已实现盈亏。

### 操作 2：删除作废记录（Q66）
- 与 FEAT-005 删除交易相同的原则：把"删除"应用到全部历史上重放：
  - 合约重放：被作废的批次恢复为持仓；之后同合约的记录（例如再次作废、在作废之后录入的成交时间正好 16:00 的交易）按新历史重新检查，违规则拒绝。例：同一合约有两条作废，删除较早的一条会让较晚那条不再是整笔批次时拒绝，提示先删除较晚那条。
  - 现金重放（Q19）：冻结从到期日 16:00 起恢复，之后每个时点总现金、可用现金都不能为负，否则拒绝，提示时点和金额，如"可用现金不足：删除后 2026-11-30 10:00 时可用现金将变为 −905.00"。
- 成功：作废记录和它的流水（如有）删除；持仓、冻结、已实现盈亏、汇总全部恢复为作废前；写一条审计记录（操作"删除"，修改前的完整内容：合约、方向"到期作废"、张数、multiplier、净额 `0.00`、时间、现金变动 `0.00`、冻结变动；连带变化同 FEAT-005）。
- 删除后可以重新作废（新记录，新 ID，没有审计记录）。
- 不提供修改（没有可改字段）；请求修改作废记录 → 拒绝，提示"到期作废不能修改，记错请删除后重新作废"。

### 与其它操作的交互（补录 / 修改 / 删除之前的交易，FEAT-001/004/005）
统一原则：**把改动应用到全部历史上（包括作废记录），按 `(时间, 录入顺序)` 重放，任何一笔不成立就整笔拒绝。** 作废记录被当作"一笔平掉 N 张的记录"参与检查：

| 改动 | 结果 |
|------|------|
| 修改被作废批次的净额、备注 | 允许；作废的已实现盈亏随之变化 |
| 删除被作废的开仓，或把它的张数改小 | 作废张数超过当时持仓 → 拒绝，提示"该开仓被 2026-11-20 16:00 的到期作废 3 张覆盖（修改/删除后作废将超过当时持仓 2 张），请先删除该到期作废" |
| 修改被作废开仓的 multiplier | 与平仓相同：与作废记录的 multiplier 不一致 → 拒绝（Q23） |
| 修改开仓张数使作废不再是整笔批次 | 拒绝（Q21） |
| 修改开仓张数，作废仍是整笔批次但覆盖的批次变了 | 允许，作废重新匹配；剩下的批次成为持仓（显示"已过期"，可再作废）；释放冻结变化写入审计"连带变化" |
| 补录到期日 16:00 之前的同合约开仓 | 作废仍是整笔批次 → 允许，补录的批次（或重新匹配后剩下的批次）成为持仓，可再作废（Q65）；否则拒绝，提示先删除该到期作废 |
| 补录 / 修改 / 删除到期日 16:00 之前的同合约平仓 | 之后作废超过持仓或不再是整笔批次 → 拒绝，提示先删除该到期作废；否则允许 |
| 新增或修改后成交时间正好是到期日 16:00:00 的同合约交易 | 时间规则允许（Q83）；排序按 `(16:00, 录入顺序)`：作废已存在时排在作废之后——平仓"成交时没有持仓"被拒；开仓成为新的持仓批次，可再作废（同 Q65） |
| 到期日当天 16:00 之后的同合约开仓、平仓（新增，或修改成交时间到 16:00 之后） | 拒绝（Q83），不论有没有作废记录，如"成交时间不能晚于到期日（2026-11-20）美东 16:00" |
| 到期日之后的同合约平仓 | 照旧被 Q36 拒绝（"到期日（2026-11-20）之后不能平仓"）；开仓照旧被 FEAT-001 拒绝，提示不变 |
| 改动其它合约、入金/出金 | 只受 Q19 现金重放约束；作废释放的冻结参与重放 |

### 交易成交时间收紧（Q83，对 FEAT-001 / FEAT-004 / FEAT-005 的改动）
- 规则：期权交易（开仓 STO/BTO、平仓 BTC/STC）的成交时间必须 ≤ 该合约到期日美东 16:00:00（按当天时区换算，夏令时同样是美东 16:00）。正好 16:00:00 允许；16:00:01 起拒绝。
- 适用：新增交易；修改交易时检查**改后的**成交时间（旧的 16:00 之后交易不改时间、只改其它字段的情况见 Q85）。入金/出金不受影响。
- 成交日 = 到期日、时间晚于 16:00 → 新提示"成交时间不能晚于到期日（2026-11-20）美东 16:00"；成交日晚于到期日 → 原有提示不变（平仓"到期日（2026-11-20）之后不能平仓"，开仓沿用 FEAT-001 的提示）。
- 只按当前规则检查被新增/修改的**那一笔**；重放时其它已存储的交易（包括旧的 16:00 之后交易）只按原有规则（Q7、Q19、Q21、Q23、Q39 等）检查，不因时间规则被拒——已存储数据不追溯。
- 持仓页"是否可以平仓"相应改为：当前时间 < 到期日美东 16:00（原为"今天 ≤ 到期日"）。正好 16:00:00 的平仓仍可以从"录入交易"页（Q37）录入。
- 少数 ETF / 指数期权到期日交易到 16:15：这段时间的成交只能记为 16:00 或之前（规则不区分品种）。

### 旧的 16:00 之后交易（FEAT-012 之前录入的数据）
- 不删除、不改动、不追溯拒绝；交易列表、持仓、已平仓照常显示。
- 作废按 `(16:00, 录入顺序)` 排序，这些交易排在作废之后。作废覆盖 16:00 时点的全部持仓，所以 16:00 之后的平仓在作废后一定没有持仓；16:00 之后的开仓不在作废范围内、之后又不能平仓或作废，会永远留在持仓里。也就是说**任何一笔**旧的 16:00 之后交易都会与作废冲突，所以规则是：该合约有任何一笔旧的 16:00 之后交易 → 作废被拒（操作 1 第 4 步），提示把它的时间改为 16:00 或之前，或删除它。
- 把它的时间改为 ≤ 16:00（FEAT-005 修改，按改后的时间检查，允许）或删除后，即可正常作废。
- 持仓页：这类合约在 17:30 之后照常显示"作废"按钮（后端不预先判断冲突），点确认后显示上面的拒绝原因。
- 不改时间、只改其它字段（净额、备注、张数等）能否保存：Q85 已定（A）：允许（只有改了成交时间才按 Q83 检查改后的时间）。

### 持仓（FEAT-003）新增的数据
- 每个持仓：**是否可以作废**（当前时间 ≥ 到期日美东 17:30）、**作废张数**（到期日 16:00 时点的持仓张数）、作废会记在的时间（到期日 16:00，美东显示）。前端按"是否可以作废"显示按钮，不自己判断时间。
- **是否可以平仓**改为：当前时间 < 到期日美东 16:00（原为"今天 ≤ 到期日"）。
- **是否到期待确认**（新）：到期日当天 16:00 ≤ 当前时间 < 17:30。此时"可以平仓""可以作废"都为否。
- DTE、"今天到期"/"已过期 N 天"、首页"7 天内到期""已过期未处理"的口径不变（到期日当天 DTE = 0，17:30 之后仍算"今天到期"，第二天起才算"已过期"）。

### 查询的变化

## 边界情况
- **周末 / 假日**：到期日是星期五，周末和之后任何一天点作废都记在星期五 16:00（验收 1、5）。不检查交易日；到期日落在休市日时仍记在该日 16:00（交易日历在 FEAT-009）。提前收盘日（如 2026-11-27 13:00 收盘）仍按 16:00 截止交易、17:30 起可作废、记在 16:00。
- **夏令时**：16:00 美东按当天时区换算 UTC（EST → 21:00Z，EDT → 20:00Z）。
- **到期日当天的两个时间点**：成交时间 ≤ 16:00:00 允许、16:01 起拒绝（验收 9）；16:00 到 17:30 之前"到期待确认"、没有按钮；17:30 起可作废，作废仍记在 16:00（验收 4）。
- **成交时间正好 16:00**：允许；与作废同一时间时按录入顺序，作废之后录入的平仓没有持仓被拒（验收 9），开仓成为新批次可再作废。
- **旧的 16:00 之后交易（FEAT-012 之前录入）**：不追溯拒绝，但会挡住该合约的作废，改时间到 ≤ 16:00 或删除后才能作废（验收 9）。
- **多批次、不同开仓日期**：一次作废全部剩余批次，盈亏按整笔（验收 2）；先部分平仓再作废剩余（验收 6）。
- **同一合约多次作废**：作废后补录的较晚批次可以再作废，两条都记在到期日 16:00，按录入顺序（验收 8）；删除较早那条会让较晚那条不再是整笔批次时拒绝，提示先删较晚的。
- **作废后补录/修改/删除较早的交易**：按重放原则，作废按 FIFO 整笔重新匹配，违规则拒绝并提示先删除作废（验收 8、11）。
- **删除作废**：冻结从 16:00 起恢复，Q19 重放；之后可用为负则拒绝（验收 5）。
- **空头 call**：释放 0、没有流水（验收 3）。多头：盈亏为负的开仓实付，没有流水（验收 3）。
- **multiplier ≠ 100、行权价 3 位小数**：释放额 = 各批次冻结之和（验收 11）。
- **对话框打开期间持仓变化**：按张数核对，拒绝（验收 12）。
- **被指派 / 行权**：不在本需求。部分被指派要先记指派（FEAT-013）再作废剩余；FEAT-013 上线前，被指派的持仓保持"已过期"，不要点作废。
- **指数期权**：作废规则相同（只是不能记指派/行权，Q11 待定）。
- **标的拆股**：不在本需求（FEAT-028）。

**已知限制**
- 前端完全依赖后端的 `closable` / `expiryPending` / `expirable`：页面停留跨过 16:00 或 17:30 时不会自动切换按钮，需刷新页面或任一写操作后重新加载（点击按钮后后端仍会按当时时间检查）。
