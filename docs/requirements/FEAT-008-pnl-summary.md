# FEAT-008: 盈亏汇总与首页概览

- **Status:** Verified
- **Priority:** P1
- **Depends on:** FEAT-006（已实现盈亏与已平仓记录，已 Verified）；FEAT-003（持仓）、FEAT-007（现金汇总）
- **Scope:**
  - [x] Backend: Done
  - [x] Frontend: Done

## 背景 / 用户故事
作为一个期权交易者，我打开系统时想一眼看到：账上现金多少、冻结多少、到目前为止总共赚了多少、这个月赚了多少、手上有几个持仓、有没有快到期或已经过期还没处理的仓位。复盘时，我还想按标的、按月份看已实现盈亏的汇总，并能限定日期范围。

本需求是 M1 的最后一项：
- **首页概览**：把目前只显示后端状态的首页改成一个只读的概览页。
- **盈亏汇总页**：按标的、按月汇总已实现盈亏，可按平仓日期范围筛选。

不做未实现盈亏、行情、到期处理（M2 / M3）。

## 已定的口径（来自 backlog Open Questions）
- 已实现盈亏只来自平仓，按**每笔平仓整体**计算，直接用含手续费的净额（Q6、Q21）；与 FEAT-006 已平仓记录的数字完全一致
- 与交易无关的现金变动（入金、出金、用入金/出金记录的利息杂费）**不计入**已实现盈亏（Q26）
- FEAT-006 只显示筛选结果的一个合计；按标的、按月分组汇总和首页数字归本需求（Q46）
- 补录、修改、删除交易后，盈亏按最新的 FIFO 匹配重新得出（Q39、FEAT-005）
- 日期按美东；日期范围按美东日期、两端包含，可只填一端（Q14、Q33）
- 持仓的 DTE、"已过期 N 天"、冻结合计按 FEAT-003（Q34、Q35）
- 本系统只做管理与分析，不下单

- 首页概览（只读）：现金汇总；已实现盈亏总计和本月（带笔数）；持仓个数和冻结合计；"7 天内到期"（0 ≤ DTE ≤ 7，含今天）和"已过期未处理"的个数；录入交易入口；后端状态移到底部小字（Q48）
- 汇总排序：按标的字母序，按月从最近往前；没有平仓的月份不显示（Q49）
- 汇总页单独成页，筛选只有平仓日期范围，默认全部时间；点标的或月份跳到已平仓页（Q50）

## 需要的数据和操作（给 backend）

### 归属规则（所有汇总共用）
- 一笔平仓的盈亏归属于它的**平仓成交时间所在的美东日期**，以及该日期所在的**美东自然月**。例：平仓时间 美东 2026-10-31 23:30（= UTC 2026-11-01 03:30）→ 属于 2026-10-31、2026-10 月。
- **今天 / 本月**：服务器当前时间所在的美东日期 / 美东自然月（不是 UTC）。"本月"= 本月 1 日起到当前为止的平仓（不会有晚于当前时间的交易）。
- 汇总的数字一律由后端计算；同一范围内，分组合计之和 = 总计 = FEAT-006 已平仓页在相同日期范围下的 `已实现盈亏合计`。

### 操作 1：首页概览数据（Q48）
一次返回首页需要的数字（或复用已有接口，由 backend 决定），全部是"当前"的值：

| 数据 | 规则 |
|------|------|
| 今天 / 本月 | 美东日期（如 `2026-11-12`）和月份（如 `2026-11`） |
| 已实现盈亏总计 | 全部平仓的盈亏之和，以及平仓笔数 |
| 本月已实现盈亏 | 平仓美东日期在本月的盈亏之和，以及笔数；本月没有平仓时为 0.00、0 笔 |
| 现金汇总 | 总现金 / 冻结 / 可用（FEAT-007 已有） |
| 持仓概况 | 持仓个数、冻结现金合计（FEAT-003 已有） |
| 即将到期 | 0 ≤ DTE ≤ 7 的持仓个数（含今天到期） |
| 已过期未处理 | DTE < 0 的持仓个数 |

### 操作 2：盈亏汇总（Q49、Q50）
**筛选**：平仓开始日期、平仓结束日期（美东日期，两端包含，可只填一端，都不填 = 全部时间）；开始晚于结束 → 字段校验错误；日期格式不对 → 无法解析错误（与 FEAT-002/006 一致）。

**返回**：
- **总计**：范围内的平仓笔数、已实现盈亏合计。
- **按标的**：每个有平仓的标的一行：标的、平仓笔数、已实现盈亏合计。按标的字母升序（与 FEAT-003 相同的字符序）。
- **按月**：每个有平仓的美东自然月一行：月份（`YYYY-MM`）、平仓笔数、已实现盈亏合计。按月份**倒序**（最近的月在上）。范围内没有平仓的月份**不出现**（Q49）。
- 两个分组各自的合计都等于总计。
- 范围内没有平仓：总计 0 笔、0.00，两个分组都为空。

不分页（标的和月份数量有限）。只读。

## 页面与交互（给 frontend）

### 首页概览（Q48）
首页（`/`）改为概览，全部只读、数字全部来自后端：
- **现金**：总现金 / 冻结 / 可用（复用 FEAT-007 的现金汇总组件），链接到资金页。
- **已实现盈亏**：`总计 +703.05（6 笔）`、`本月（2026-11）+633.05（4 笔）`，正绿负红；链接到盈亏汇总页；"本月"可链接到已平仓页并带上本月的日期范围。
- **持仓**：`持仓 3 个`、`冻结现金合计 44,000.00`；`7 天内到期 1 个`、`已过期未处理 1 个`（大于 0 时醒目显示，已过期用红色）；链接到持仓页。
- **快捷入口**：录入交易。
- 后端状态（原首页内容：状态、版本、服务器时间）移到页面底部一行小字；后端不可用时仍要能看到错误提示。原有健康检查的 `data-testid` 保持不变。
- 加载中 / 出错（错误 + 重试）各卡片分别处理，一个卡片出错不影响其它卡片。
- 页面上注明"截至 2026-11-12（美东）"。

### 盈亏汇总页（Q50）
- 新增"盈亏汇总"页面，导航有入口。
- 顶部筛选：平仓开始日期、平仓结束日期（注明"美东日期"），"查询""清除"；筛选写在地址栏，可收藏、刷新保留、后退恢复；不合法参数在字段下报错、不崩溃。
- 总计一行：`共 6 笔平仓，已实现盈亏合计 +703.05`。
- 两个表格（或两个标签页）：
  - **按标的**：标的、笔数、已实现盈亏（正绿负红），最后一行"合计"。点击标的 → 进入已平仓页（FEAT-006），带上该标的和当前日期范围。
  - **按月**：月份、笔数、已实现盈亏，最后一行"合计"。点击月份 → 进入已平仓页，日期范围为该月 1 日到月末，再与当前筛选范围取交集。
- 合计行的数字来自后端，前端不相加。
- 空状态：范围内没有平仓时显示"所选范围内没有平仓记录"（无筛选时显示"暂无平仓记录"），合计 0.00。
- 说明一行："已实现盈亏只来自平仓，已含手续费；不含入金、出金和利息等"。

### 刷新
- 在任何页面新增、修改、删除交易或入金/出金后，回到首页或盈亏汇总页无需手动刷新即显示新数字。

## 验收标准
**关于"今天 / 本月"**：后端系统测试把时钟固定在 **2026-11-12 10:00（美东）**，下面写的"本月"数字按此时钟。E2E 用真实时钟，断言方式：页面"截至"日期 = 运行当天的美东日期；"本月"标签 = 运行当天的美东年月；本月盈亏 = 下面数据中平仓美东日期落在该月的盈亏之和（在 2026-11 运行为 +633.05；在 2026-12 及以后运行为 0.00、0 笔）。即将到期 / 已过期的 E2E 数据用相对运行当天的到期日（见验收 1）。

**场景 Q**（= FEAT-006 的场景 P 加上 10 月的两组交易）：空库，入金 100,000.00（2026-10-26 10:00），先录入：

| 编号 | 方向 | 合约 | 张数 | 净额 | 成交时间（美东） |
|------|------|------|------|------|-----------------|
| O1 | BTO | TSLA 2026-12-18 300 C | 1 | 500.00 | 2026-10-27 10:00 |
| O2 | STO | AAPL 2026-11-20 180 P | 1 | 150.00 | 2026-10-28 10:00 |
| O3 | STC | TSLA 2026-12-18 300 C | 1 | 620.00 | 2026-10-30 10:00 |
| O4 | BTC | AAPL 2026-11-20 180 P | 1 | 200.00 | 2026-10-31 23:30 |

（O3 盈亏 +120.00；O4 盈亏 −50.00，美东 2026-10-31 23:30 = UTC 2026-11-01 03:30，归属 10 月。）

再按 FEAT-006 场景 P 的顺序录入 T1–T5、C1–C4（C1 +658.70、C2 −15.65、C3 +350.00、C4 −360.00，都在 11 月）。

全部录入后没有持仓，现金汇总 100,703.05 / 0.00 / 100,703.05（总现金 − 入金 = 703.05 = 全部已实现盈亏）。

1. **首页概览**
   **Given** 场景 Q，再录入（用于持仓概况）：
   - A = STO 1 张 TSLA 2026-11-06 250 P，净额 300.00（2026-11-02 09:00）——已过期未处理
   - B = BTO 1 张 SPY 2026-11-13 600 C，净额 80.00（2026-11-09 10:00）——DTE 1
   - C = STO 1 张 AAPL 2026-11-20 190 P，净额 120.00（2026-11-09 10:00）——DTE 8
   **When** 今天 2026-11-12 打开首页
   **Then** 显示：
   - `截至 2026-11-12（美东）`
   - 现金 总现金 101,043.05、冻结 44,000.00、可用 57,043.05
   - 已实现盈亏 `总计 +703.05（6 笔）`、`本月（2026-11）+633.05（4 笔）`
   - `持仓 3 个`、`冻结现金合计 44,000.00`、`7 天内到期 1 个`（SPY，DTE 1；AAPL 190 P 的 DTE 8 不算）、`已过期未处理 1 个`（TSLA，红色）
   - 底部一行后端状态（如 `后端：UP · 版本 … · 服务器时间 …`）
   **E2E**：B 的到期日用运行当天 + 1 天，C 用运行当天 + 8 天（成交时间都用运行前的日期），A 的到期日 2026-11-06；断言 7 天内到期 1 个、已过期未处理 1 个。

2. **本月的边界（美东）**（后端测试，调时钟）

   - 时钟 2026-12-01 05:30Z（= 美东 2026-12-01 00:30）→ 本月为 2026-12，`0.00（0 笔）`；总计仍为 `+703.05（6 笔）`
   - 时钟 2026-10-31 23:45（美东）、且只录入了 O1–O4 时 → 本月 2026-10 为 `+70.00（2 笔）`（O4 的 UTC 时间已是 11-01，仍算 10 月）

3. **盈亏汇总：全部时间**
   **Given** 场景 Q（不含验收 1 追加的 A、B、C）
   **When** 打开盈亏汇总页，不加筛选
   **Then** 总计 `共 6 笔平仓，已实现盈亏合计 +703.05`。
   **按标的**（字母序）：
   | 标的 | 笔数 | 已实现盈亏 |
   |------|------|-----------|

   | 月份 | 笔数 | 已实现盈亏 |

   | 合计 | 6 | +703.05 |

4. **盈亏汇总：日期范围（美东日期，两端包含）**
   - 开始 2026-11-01、结束 2026-11-06 → 总计 `3 笔，+993.05`；按标的 AAPL 1 笔 +658.70、MSFT 1 笔 +350.00、XYZ 1 笔 −15.65；按月只有 2026-11（3 笔 +993.05）。O4（美东 10-31 23:30，UTC 已是 11-01）**不在内**；C3（美东 11-06 23:30）在内。

   **And** 每种范围下的总计 = 已平仓页（FEAT-006）在相同平仓日期范围下的 `已实现盈亏合计`（例：11-01 至 11-06 两边都是 +993.05）。

## 边界情况
- **深夜平仓 / 跨月**：按美东日期与美东月份归属（O4 归 10 月，验收 2、4）。
- **"本月"切换**：按美东午夜，不按 UTC（验收 2）。页面停留跨过午夜不要求自动更新，刷新后按新的"今天"。
- **没有平仓的月份**：不显示（Q49）。
- **补录 / 修改 / 删除**：汇总和首页数字随之变化（验收 6）。
- **入金、出金、利息**：不计入已实现盈亏（Q26，验收 6）。
- **分组合计**：后端给出，前端不相加；按标的、按月合计都等于总计。
- **已过期未处理、即将到期**：只显示个数并链接到持仓页；完整的到期提醒视图在 FEAT-010，处理在 FEAT-012/013/014。
- **M2 的到期作废 / 指派 / 行权盈亏**：本需求不含，以后的需求决定是否计入汇总。

## Implementation Notes
### Backend
**API**（详见 `docs/api/api-contract.md` 的 FEAT-008 小节）
- `GET /api/dashboard` → `asOfDate`（美东今天）、`currentMonth`（`YYYY-MM`）、`cash`（`totalCash`/`frozenCash`/`availableCash`）、`realizedPnl`（`closedCount`、`total`）、`currentMonthRealizedPnl`（同）、`positions`（`positionCount`、`frozenTotal`、`expiringWithin7DaysCount`、`expiredUnprocessedCount`）。首页一次请求即可；健康检查仍用 `GET /api/health`
- `GET /api/pnl-summary?startDate=&endDate=` → `startDate`/`endDate`（回显，未填为 `null`）、`closedCount`、`realizedPnlTotal`、`bySymbol[]`（`symbol`、`closedCount`、`realizedPnl`，字母序）、`byMonth[]`（`month` `YYYY-MM`、`closedCount`、`realizedPnl`，倒序）。合计行用 `closedCount` / `realizedPnlTotal`，前端不相加
- 日期错误与 FEAT-002/006 相同：格式错 / 日期不存在 → 400 `BAD_REQUEST`；开始晚于结束 → 400 `VALIDATION_ERROR`，field `endDate`
- 跳转：标的 → `/api/closed-trades?symbol=…&startDate=…&endDate=…`；月份 → 该月 1 日至月末与当前范围的交集（前端计算日期范围）；本月 → `startDate=<本月 1 日>&endDate=<asOfDate>`

**文件**
- 新增 `trade/domain/PnlSummary`、`trade/service/PnlSummaryService`、`trade/web/PnlSummaryController`
- 修改 `trade/service/ClosedTradeService`（抽出 `all(filter)`，分页与汇总共用）
- 测试：`trade/web/PnlSummaryControllerTest`（验收 1、2、3、4、6、7 的后端部分，含与 `/api/closed-trades` 相同范围的交叉核对、本月的美东边界、7 天窗口含第 0 天和第 7 天）
- 没有数据库迁移；文档：`docs/api/api-contract.md`、`docs/architecture.md`

**设计决定**
- 汇总不另算盈亏：平仓与盈亏直接取自 FEAT-006 的 `ClosedTradeService`，持仓数字取自 FEAT-003，现金取自 FEAT-007，因此各页面数字天然一致（测试做了交叉核对）
- 首页用一个接口 `/api/dashboard` 返回全部数字（各卡片可分别显示 loading / 错误由前端决定；也可以继续单独调用现有接口）
- 本月 = 平仓美东日期 ≥ 本月 1 日（不会有晚于当前时间的交易）
- 即将到期 = 0 ≤ DTE ≤ 7（DTE 按 FEAT-003，美东日历天数）；已过期 = DTE < 0
- 每次请求重放全部涉及的合约（个人数据量可以接受）
