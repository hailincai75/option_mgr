## 背景 / 用户故事
作为一个在 2 个账户里做期权的交易者，FEAT-035 之后我在"全部账户"下能看到合并的首页、持仓、资金汇总和盈亏汇总，但点"本月已实现"或盈亏汇总里的标的时，落到已平仓页的占位提示；想核对两个账户全部交易、全部流水时还要来回切换。我想让交易列表、股票交易、已平仓、资金流水 4 个列表页在全部账户下也显示两个账户合在一起的记录，每行能看出属于哪个账户，筛选照常可用，仍然只读。

本需求是 FEAT-035 拆分的第二部分；策略页、组合 Greeks 汇总在 FEAT-047，审计页永远不合并（Q225）。

## 已定的口径
- Q53：合并不改变任何计算，每行数字与在该账户下看到的完全相同。Q55：筛选链接不带账户，按当前账户（含全部账户）解释。
- Q214 账户列、不设账户筛选、同序按账户 ID；Q215 不合并行；Q216 合计跨账户相加；Q217 写入口隐藏、后端拒绝；Q223 未支持页面占位；Q225 审计页不合并；Q226 实现方式由 backend-dev 定。
- Q44 没有交易详情页；Q46 已平仓显示筛选结果全部记录的笔数与合计；Q90 / Q92 已平仓的期权专用筛选与同一时间排序；"历史"只对有审计记录的行显示（M1.5 小改动）。
- Q228：流水每行余额为该行所在账户自己的余额，全部账户下表头 `账户余额`；Q229：同一时间不同账户按录入顺序（后录入的在上）；Q230：不加账户筛选；Q231："历史"保留，点击切换到该行账户并打开审计页按该记录筛选；Q232：流水行的 `在…中修改` 链接隐藏。

## 规则
1. **范围**：交易列表（期权交易，含平仓、到期作废、被指派、行权行）、股票交易、已平仓、资金页流水区在全部账户模式下显示全部账户的记录，不再显示 FEAT-035 规则 7 的占位。策略页、审计记录页仍是占位（FEAT-047 / Q225）。
2. **账户列**：每行首列 `账户`（账户名称），只在全部账户模式出现（Q214）。已平仓行展开的被平 / 被卖出批次属于同一账户，不另加账户列。
3. **排序**：各页原排序不变（交易列表、股票交易、流水：时间倒序、同一时间后录入的在上；已平仓：时间倒序 → 同一时间股票在上（Q92）→ 后录入的在上）。同一时间不同账户的记录同样按录入顺序（后录入的在上），完全相同才按账户 ID（Q229）。
4. **筛选与地址栏**：各页已有筛选、校验、错误文案、地址栏参数、后退恢复全部照常，作用于全部账户的记录。切换账户时地址栏参数保留（Q55），结果按新账户重新显示。不加账户筛选（Q214、Q230）。
5. **分页**：分页对**合并后的整个列表**进行（不是每个账户各自分页）；每页条数选项、默认值、超过最后一页的处理都不变。`共 N 条` / `共 N 笔` 为全部账户合计。
6. **合计**：已平仓顶部 `共 N 笔平仓`、`已实现盈亏合计` 为符合筛选条件的全部账户记录之和，由后端给出（Q216）。**一致性**（恢复 FEAT-008 / 040）：同一日期范围下，全部账户的盈亏汇总总计（笔数、金额）= 全部账户已平仓页（类型不限）的合计。
7. **流水余额**（Q228）：每行余额是该行所在账户自己的"该条之后总现金余额"（与单账户相同），全部账户下表头为 `账户余额`。
8. **只读**（Q217）：4 个页面上的写入口隐藏：`录入开仓` / `录入股票` 按钮和空状态里的录入入口、每行 `修改` / `删除`、流水行的 `在交易列表中修改` / `在股票交易中修改`（Q232）。`历史` 保留（仍只在有审计记录的行），点击切换到该行所在账户并打开审计记录页按该记录筛选（Q231）。
9. **页面间链接**：只做跳转、筛选的链接照常可用并停留在全部账户模式：交易列表点合约设筛选；已平仓点合约 → 交易列表、点标的 → 股票交易；股票交易的 `来自被指派 #N` 等关联链接；持仓页股票表点标的 → 股票交易；首页 `本月` 与盈亏汇总的标的 / 月份 → 已平仓。这些链接在全部账户下落到合并结果，不再是占位。

## 需要的数据和操作（给 backend）
全部账户模式下（实现方式见 Q226，沿用 FEAT-035 的全部账户范围）：
- **期权交易列表、股票交易列表、已平仓记录、现金流水**：返回全部账户的记录，每行字段、数字与单账户完全相同，另加账户 ID 和名称；筛选、校验、错误与单账户相同；排序按规则 3；分页按规则 5（总条数、总页数为合并后的）。
- **已平仓合计**：符合筛选条件的全部账户记录的笔数和已实现盈亏合计（规则 6）。
- **流水余额**：每行仍是该账户自己的"该条之后总现金余额"，不变（规则 7）。
- **盈亏汇总**（FEAT-035 已支持）：与已平仓全部账户合计一致（规则 6），后端测试恢复这项交叉核对。
- **按 ID 查询单笔记录**：全部账户下页面不需要（只用于已隐藏的修改对话框）；是否支持由 backend-dev 定。
- **不变**：任何写请求不指明单个账户仍被拒绝；审计记录仍不支持全部账户（Q225）；单账户的接口与行为不变。

## 页面与交互（给 frontend）
- **交易列表、股票交易、已平仓、资金页流水区**：去掉占位，按规则 2–9 显示；行展开（被平 / 被卖出批次）、已平仓类型筛选与 Q90 提示照常；数字全部取后端值。空状态 `暂无交易` 等不带录入入口。
- **流水余额列**：见规则 7（全部账户下表头 `账户余额`）。资金汇总区沿用 FEAT-035。
- **历史**：见规则 8（点击先切换到该行账户，再打开审计记录页）。
- **切回单个账户**：恢复单账户样子（无账户列，按钮和链接回来）。

## 边界情况
- **同一合约在两个账户**：分行（Q215），合约筛选两边都出现（验收 2）；同一时间按录入顺序（规则 3）。
- **已平仓两类 ID 重复**：行仍按"类型 + ID"区分（FEAT-040）；全局 ID 不会跨账户重复。
- **转入只有日期**：在股票交易中的位置沿用单账户规则。
- **新增 / 改名账户**：自动包含；改名后账户列立即显示新名称（同 FEAT-035）。
- **地址栏参数不合法、页码超过最后一页**：与单账户相同的处理。
- **到期作废 / 被指派 / 行权行**：照常出现在交易列表和已平仓，`删除` 隐藏；股票交易的 `指派买入` / `行权买入` 等行照常。
- **在单账户修改后切到全部账户**：无需手动刷新，显示最新数据。
- **到期日当天、周末 / 假日**：沿用各页面单账户规则。拆股不在本需求。

## Out of Scope

- **账户列（Q214）**：`TradeTable`、`StockTradeTable`、`ClosedTradeTable`、`CashLedgerTable` 内用 `useIsAllAccounts()`，全部账户下加首列 `账户`（复用 FEAT-035 的 `AccountNameCell`，显示后端 `accountName`）；展开的被平 / 被卖出批次不加账户列。行 key 不变（id 全局唯一；已平仓按类型 + id）。
- **只读（Q217、Q232）**：全部账户下隐藏 `录入开仓` / `录入股票交易`（卡片右上与空状态）、行上 `修改` / `删除`、流水的 `修改` / `删除` / `在交易列表中修改` / `在股票交易中修改`。空状态仍显示 `暂无交易` / `暂无股票交易`。
- **流水余额（Q228）**：全部账户下余额列表头为 `账户余额`，值仍是后端 `balanceAfter`。
- **历史（Q231）**：新组件 `components/account/HistoryLink.tsx`，4 个表格的"历史"都用它；仍只在 `hasAuditLog` 为 true 时出现。单账户是普通链接；全部账户下点击先 `selectAccount(row.accountId)`（记入 localStorage），再 `navigate('/audit?objectType=…&objectId=…')`，审计请求带该行账户 id。
- **筛选、地址栏、分页、深链接**：页面查询代码不变（请求头由统一封装按当前账户发 `ALL`），筛选、校验、地址栏参数、分页、`共 N 条`、已平仓合计全取后端；首页 / 盈亏汇总 / 已平仓 / 持仓 / `来自被指派 #N` 等链接只改地址栏，停留在全部账户并显示合并结果。切换账户时页面按账户重新挂载、地址栏参数保留（与 FEAT-033 相同），切回单账户即恢复无账户列的样子和全部写入口。
- **类型**：`OptionTrade`、`StockTrade`、已平仓两类行（`ClosedRecordBase`）、`CashLedgerEntry` 都继承 `RowAccountFields`（`accountId?`、`accountName?`，可选只为兼容旧测试数据）。
- **testid**（新增，见 architecture.md）：`trade-cell-account`、`stock-cell-account`、`closed-cell-account`、`cash-ledger-account`（均带 `data-account-id`）；`trade-row` / `stock-row` / `closed-row` / `cash-ledger-row` 新增 `data-account-id`；全部账户下的 `*-history` 也带 `data-account-id`。
- **测试**：`src/pages/AllAccountsLists.test.tsx`（场景 L 虚构数据，14 个用例：验收 1、2、3、4、5/6 深链接、7、8、9 及空状态）；`src/pages/AllAccounts.test.tsx` 中 FEAT-035 对交易 / 股票 / 已平仓 / 流水占位的断言改为新行为。
- **已知限制**：未接真实后端联调（后端并行开发，用 mock 测试）；没有账户筛选（Q230）。
