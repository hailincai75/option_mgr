# FEAT-038: 允许卖出开仓 call（STO call），不冻结现金

- **Status:** Verified
- **Priority:** P0
- **Depends on:** FEAT-033（多账户，已 Verified）；FEAT-001 ~ FEAT-008
- **Scope:**
  - [x] Backend: Done
  - [x] Frontend: Done

## 背景 / 用户故事
作为一个期权交易者，我的账户里有被指派来的股票，我在上面卖 covered call，并且会展期（roll）。现在系统拒绝所有 STO call（Q16："需要股票持仓功能（FEAT-011）后才能卖出 call"），我无法把真实账户的交易录进来。

我想要现在就能录入 STO call 和之后的 BTC 平仓，持仓、盈亏、汇总都和 put 一样正常工作。在股票持仓功能（FEAT-011）上线之前，系统**不检查**我是否有股票覆盖，也**不为卖出的 call 冻结现金**——由我自己保证。

## 已定的口径
- **Q16 被取代（用户新决定）**：允许 STO call；不冻结任何现金；系统不检查股票覆盖（无法检查，FEAT-011 之前没有股票数据）。用户自行负责覆盖。FEAT-011 上线时再加覆盖检查（见 backlog FEAT-011）。
- 除"不冻结"外，STO call 与 STO put 的其它规则完全相同：
  - 净额为含手续费的实收，> 0，最多 2 位小数（Q6、Q17、Q29）
  - 一个合约任一时刻只能纯多或纯空（Q7、Q27）；同一合约有持仓时 multiplier 一致（Q23）
  - 平仓 BTC 必须整笔平掉最早的一笔或几笔批次（Q21）；到期日之后不能平仓（Q36）
  - 补录、修改、删除按时间重放检查（Q19、Q39、FEAT-005）
  - 按账户隔离（Q53）
- 现金：STO call 只增加现金（+净额），冻结变动 0；Q18（担保检查）不适用于 call。BTC 平空头 call 释放冻结 0，只检查"平仓实付 ≤ 当时可用现金"（Q19 重放）。
- BTO / STC（多头 call）规则不变。

- 录入交易页选 STO + Call 时显示一行提示文字，不弹确认框、不阻止提交（Q61）
- 持仓页空头 call 的冻结列显示灰色"未冻结"小标签（悬停说明需自行保证股票覆盖）；其它页面不加标记（Q62）

## 需要的数据和操作（给 backend）
- **开仓（STO call）**：
  - 取消 Q16 的拒绝。
  - 检查顺序与 STO put 相同，但没有担保和 Q18：字段 → Q7 → Q23 → 现金（本笔只增加现金，按 Q19 重放不会出现不足）。
  - 保存后现金 +净额、冻结变动 0.00。
  - 流水说明格式同 FEAT-001，如 `STO 1 张 IXQZ 2026-11-20 7.5 C`。
- **平仓（BTC 空头 call）**：
  - 规则同 FEAT-004。
  - 被平批次的冻结都是 0，所以释放冻结 0.00。
  - 现金检查：本笔时点可用现金 ≥ 净额，并按 Q19 重放之后每个时点。
  - 已实现盈亏 = 被平批次开仓实收之和 − 平仓实付。
- **修改 / 删除（FEAT-005）**：STO call 没有担保，修改时不做 Q18 检查（Q45 对 call 不适用）；其余检查不变。
- **持仓、交易列表、已平仓、盈亏汇总、首页**：
  - 空头 call 正常出现。
  - 冻结现金为 0，不计入冻结合计。
  - 持仓的方向、批次、平均净额、DTE、可平张数、平仓按钮都与空头 put 相同。
- 原来的"不支持卖出 call"错误不再出现在任何操作中（契约中如何标注由 backend 定）。

## 页面与交互（给 frontend）
- **录入交易页**：选 STO + Call 时不再被拒。在净额字段附近显示一行提示（Q61）："卖出 call 不冻结现金，请自行确保账户有足够股票覆盖（每张 = multiplier 股）；股票持仓功能（FEAT-011）上线后将自动检查。"
- **持仓页**：
  - 空头 call 行正常显示，"平仓"按钮预填 `BTC（买入平仓）`。
  - 冻结现金列不显示 `—`，而是一个灰色小标签"未冻结"，悬停说明"卖出 call 不冻结现金，需自行保证股票覆盖"（Q62）。
- **交易列表、已平仓、盈亏汇总、首页、资金页**：无需改动，空头 call 的冻结变动显示 `—`（为 0）。
- 前端不计算任何金额。

## 边界情况
- **同一时刻展期**：BTC 旧合约和 STO 新合约是不同合约，录入先后都可以；同一时间按录入顺序显示（验收 3）。
- **裸卖 call**：系统无法区分 covered 还是裸卖，一律允许、不冻结；由用户负责（Q16 被取代）。
- **可用现金为 0**：STO call 仍允许（验收 4）；BTC 时按实付检查（验收 5）。
- **冻结合计**：只来自空头 put，与卖出 call 无关（验收 7）。
- **已过期未处理的空头 call**：与空头 put 一样显示"已过期 N 天"，没有冻结要释放；作废/指派在 M2（FEAT-012/013）。被指派时 call 需要交出股票，规则由 FEAT-013 定。
- **FEAT-011 上线后**：已有的空头 call 不会被追溯拒绝；如何检查覆盖、是否锁定股票由 FEAT-011 定。
- **补录 / 修改 / 删除**：按 FEAT-005 规则，call 不做 Q18。

## Out of Scope
- 股票持仓、股票覆盖检查、锁定股票（FEAT-011）
- 卖出 call 的保证金或现金担保
- 被指派 / 作废（FEAT-012/013）
- covered call 策略分组（FEAT-021）
- 展期一次录入两腿（FEAT-024）；目前分两笔录入
