## 背景 / 用户故事
作为一个期权交易者，我想要按合约看到我当前所有未平仓的期权持仓：多还是空、几张、开仓时总共收/付了多少（含手续费）、每张平均多少、卖 put 冻结了多少现金、什么时候到期、还剩几天，并能展开看每个合约由哪几笔开仓（FIFO 批次）组成，以便掌握风险敞口和临近到期的仓位。

本需求只做**查看**，不在持仓页做平仓、到期处理或修改。目前只有开仓交易（FEAT-001），平仓（BTC / STC）在 FEAT-004 加入；本需求的"批次"和"持仓"定义要能直接容纳 FEAT-004 的部分平仓，不需要返工。

## 已定的口径（来自 backlog Open Questions、FEAT-001、FEAT-002）
- 单账户、只有 USD（Q3、Q4）
- 每笔交易只记含手续费的净额：STO = 扣手续费后的实收，BTO = 含手续费的实付；没有成交价、没有单独的手续费（Q6）
- 一个合约任一时刻只能纯多或纯空（Q7），所以一个合约最多一个持仓，方向唯一
- 合约 = 标的 + 到期日 + 行权价 + Call/Put；行权价按数值比较（FEAT-001）
- 同一合约有未平仓持仓时 multiplier 必须一致（Q23），所以一个持仓只有一个 multiplier
- STO put 冻结 行权价 × multiplier × 张数，**每笔交易**单独向上取整到分（Q13、Q28）
- 成本法 FIFO；同一时间的交易按录入顺序（Q19）。持仓不存库，按 `(成交时间, 录入顺序)` 重放该合约的全部交易得出（FEAT-001 架构）
- 时间、日期按美东（America/New_York）（Q14）
- M2 才处理到期作废/指派/行权（FEAT-012/013/014）；在那之前，过了到期日的持仓仍然是未平仓持仓
- 每张平均净额 = 开仓净额合计 ÷ 张数，**四舍五入**到分，带与合计相同的符号，只用于显示，不参与任何计算；不显示折合每股价格（Q22）
- 已过到期日未处理的持仓照常显示：DTE 为负、标红、显示"已过期 N 天"，冻结不释放；到期日当天 DTE = 0，标"今天到期"。本需求只显示状态，不提供任何操作按钮（Q34）
- 排序：到期日 → 标的 → 行权价 → Call 在 Put 前；不分页、不筛选；顶部只显示持仓个数和冻结现金合计（Q35）

## 需要的数据和操作（给 backend）

### 概念
- **批次（lot）**：每一笔开仓交易（BTO / STO）就是一个批次。批次记录：原张数、原开仓净额、原冻结金额（STO put 的担保，BTO 和其它为 0）。
  - **剩余张数** = 原张数 − 已按 FIFO 被平仓扣掉的张数。本需求内没有平仓，剩余张数 = 原张数。
  - **剩余开仓净额** = 原开仓净额 − 已分摊给平仓的部分；**剩余冻结** = 原冻结 − 已释放的部分。分摊和释放的规则由 FEAT-004 定（分摊舍入见 Q21）；本需求内两者都等于原值。
  - 剩余张数为 0 的批次不再属于持仓。
- **持仓**：某合约在**当前**（所有交易都不晚于当前时间，所以就是全部交易）净张数不为 0 时，就是一个持仓。持仓由该合约所有剩余张数 > 0 的批次组成，批次按 FIFO 顺序（成交时间早的在前，同一时间先录入的在前）。
- **"今天"**：服务器当前时间所在的**美东日期**（美东午夜切换，不是 UTC 午夜）。

### 每个持仓需要返回的数据
| 数据 | 规则 / 例子 |
|------|-------------|
| 合约 | 标的、到期日、行权价（去尾零）、Call/Put、合约显示名（如 `AAPL 2026-12-18 200 P`），与 FEAT-001/002 一致 |
| 方向 | 多头（由 BTO 建立）或空头（由 STO 建立） |
| 张数 | 净张数的绝对值 = 各批次剩余张数之和（正整数） |
| multiplier | 该持仓的 multiplier |
| 开仓净额合计 | 各批次剩余开仓净额之和，**带现金方向符号**：空头为正（实收），多头为负（实付）。例：两笔 STO 净额 349.35 + 360.00 → `+709.35`；一笔 BTO 512.65 → `−512.65` |
| 每张平均净额 | 开仓净额合计 ÷ 张数，**四舍五入**到分（Q22），带与合计相同的符号。只用于显示，不参与任何计算。例：709.35 ÷ 2 = 354.675 → `+354.68` |
| 冻结现金 | 空头 put：各批次剩余冻结之和（**不是**用合计张数重新算再取整）；其它持仓为 0。例：两笔 STO 1 张 F 12.345 P（multiplier 1），每笔冻结 12.35 → 持仓冻结 24.70 |
| 到期日 | `YYYY-MM-DD` |
| DTE | 到期日 − 今天（美东日期）的**日历天数**，含周末和假日。到期日当天 = 0；到期日已过为负数（如到期日 2026-11-06、今天 2026-11-11 → −5）（Q34） |
| 批次数 | 剩余张数 > 0 的批次个数 |
| 批次明细 | 见下 |

### 每个批次需要返回的数据
交易 ID、开仓方向（BTO / STO）、成交时间（UTC + 美东本地时间）、原张数、剩余张数、剩余开仓净额（带现金方向符号，同上）、剩余冻结、备注。

### 整体
- 返回"今天"的美东日期（页面显示"截至 YYYY-MM-DD（美东）"，E2E 用它核对 DTE）。
- 返回持仓个数和**冻结现金合计**（所有持仓冻结之和）。在 M2 之前，所有冻结都来自未平仓的空头 put，所以这个合计应等于 FEAT-007 现金汇总里的冻结现金。
- **排序**（Q35）：到期日升序（最近到期、已过期的在最上）→ 标的字母升序 → 行权价数值升序 → Call 在 Put 前。
- 不分页（个人持仓数量少），一次返回全部持仓。不提供筛选（见 Out of Scope）。
- 不修改任何数据，不影响现金。

## 页面与交互（给 frontend）

### 入口
- 新增"持仓"页面，顶部导航有入口（如"持仓"）。

### 页面内容
- 顶部一行：`截至 2026-11-11（美东）`、`共 5 个持仓`、`冻结现金合计 44,500.00`（数字全部来自后端）。
- 持仓表格，每行一个持仓，按后端顺序显示：

| 列 | 显示 |
|----|------|
| 合约 | 合约显示名，如 `AAPL 2026-12-18 200 P`；可点击，跳转到交易列表（FEAT-002）并按该合约筛选（标的 + 到期日 + 行权价 + C/P） |
| 方向 | `空头` / `多头`（可用颜色或标签区分） |
| 张数 | 如 `2`；multiplier ≠ 100 时附注，如 `1（multiplier 10）`，与 FEAT-002 一致 |
| 开仓净额合计 | 带符号：`+709.35`（绿）、`−512.65`（红）；表头或提示说明"空头为实收，多头为实付，均已含手续费" |
| 每张平均净额 | 带符号，如 `+354.68`；表头注明"仅供参考" |
| 冻结现金 | 非 0 显示金额（如 `40,000.00`），0 显示 `—` |
| 到期日 | `2026-12-18` |
| DTE | 正数显示数字（如 `37`）；0 显示 `0` 并标注"今天到期"；负数显示"已过期 N 天"并用红色标记（Q34） |

- 每行可展开，显示该持仓的批次表（FIFO 顺序，最早的在上）：开仓时间（美东 `YYYY-MM-DD HH:mm`）、方向（`STO（卖出开仓）` / `BTO（买入开仓）`）、剩余张数 / 原张数（如 `1 / 1`）、剩余开仓净额（带符号）、冻结（0 显示 `—`）、备注（空为 `—`）。
- 金额统一用格式化 util（千分位、2 位小数、负号 `−`）。前端不做任何加总、平均、DTE 或冻结计算。
- 不提供平仓、删除、编辑按钮。

### 空状态、加载与错误
- 没有任何持仓：显示"暂无持仓"和"录入开仓"入口；顶部显示 `共 0 个持仓`、`冻结现金合计 0.00`。
- 加载中、请求失败（错误信息 + 重试）沿用现有做法。

### 与其它页面的联动
- 在"录入开仓"页成功保存后，打开持仓页无需手动刷新就能看到变化（录入成功时让持仓数据失效）。
- 页面停留跨过美东午夜时 DTE 不要求自动更新；刷新或重新进入页面时按新的"今天"显示。

## 验收标准
**关于"今天"**：DTE 依赖当前日期。后端系统测试把时钟固定在 **2026-11-11 10:00（美东）**，下面的 DTE 数字都按"今天 = 2026-11-11"写。E2E 使用真实时钟，断言方式为：页面"截至"日期 = 运行时的美东日期，且每个持仓的 DTE = 到期日 − 该日期的日历天数（第 6 条另有说明）。

**基准数据**（与 FEAT-002 相同）：空库，入金 100,000.00（2026-10-26 10:00），按顺序录入：

|------|------|------|------|-----------|------|-----------------|------|
| T1 | STO | AAPL 2026-12-18 200 P | 1 | 100 | 349.35 | 2026-11-03 10:30 | 第一笔 CSP |
| T2 | BTO | AAPL 2026-12-18 210 C | 1 | 100 | 512.65 | 2026-11-03 10:30 | — |
| T3 | STO | F 2026-12-18 12.5 P | 2 | 100 | 48.70 | 2026-11-02 15:59 | — |
| T4 | STO | AAPL 2026-12-18 200 P | 1 | 100 | 360.00 | 2026-11-04 11:00 | 加仓 |
| T5 | BTO | MSFT 2027-01-15 450 C | 1 | 100 | 900.00 | 2026-11-03 23:30 | — |
| T6 | STO | XYZ 2026-12-18 200 P | 1 | 10 | 34.35 | 2026-10-30 10:00 | — |

（现金汇总 99,379.75 / 44,500.00 / 54,879.75。）

   **When** 打开持仓页
   **Then** 顶部显示 `截至 2026-11-11（美东）`、`共 5 个持仓`、`冻结现金合计 44,500.00`（等于资金页的冻结现金）。表格从上到下：
   | 合约 | 方向 | 张数 | 开仓净额合计 | 每张平均净额 | 冻结现金 | 到期日 | DTE | 批次数 |
   |------|------|------|-------------|-------------|---------|--------|-----|-------|
   | AAPL 2026-12-18 200 P | 空头 | 2 | +709.35 | +354.68 | 40,000.00 | 2026-12-18 | 37 | 2 |
   | AAPL 2026-12-18 210 C | 多头 | 1 | −512.65 | −512.65 | — | 2026-12-18 | 37 | 1 |

   | MSFT 2027-01-15 450 C | 多头 | 1 | −900.00 | −900.00 | — | 2027-01-15 | 65 | 1 |
   （同一到期日按标的字母序；AAPL 两个合约按行权价 200 在 210 前。）

2. **同一合约多次开仓：合并显示，展开看 FIFO 批次**
   **When** 展开 `AAPL 2026-12-18 200 P`
   **Then** 显示 2 个批次，从上到下：
   - `2026-11-03 10:30`、`STO（卖出开仓）`、`1 / 1`、`+349.35`、冻结 `20,000.00`、备注"第一笔 CSP"
   - `2026-11-04 11:00`、`STO（卖出开仓）`、`1 / 1`、`+360.00`、冻结 `20,000.00`、备注"加仓"
   **When** 展开 `F 2026-12-18 12.5 P` **Then** 只有 1 个批次：`2026-11-02 15:59`、`2 / 2`、`+48.70`、冻结 `2,500.00`（一笔 2 张 = 一个批次，不拆成 2 个）。
   **When** 展开 `AAPL 2026-12-18 210 C` **Then** 1 个批次：`2026-11-03 10:30`、`BTO（买入开仓）`、`1 / 1`、`−512.65`、冻结 `—`。

3. **每张平均净额的舍入（Q22：四舍五入到分）**
   - 第 1 条的 AAPL 200 P：709.35 ÷ 2 = 354.675 → `+354.68`。
   **Given** 另一空库：入金 10,000.00（2026-10-26 10:00）
   **When** 录入 BTO 3 张 KO 2026-12-18 60 C，净额 200.00（2026-11-02 10:00）
   **Then** 该持仓开仓净额合计 `−200.00`，每张平均净额 `−66.67`（200.00 ÷ 3 = 66.666…）。
   **And When** 再录入 BTO 3 张 PEP 2026-12-18 150 C，净额 100.00 **Then** 每张平均净额 `−33.33`。

4. **冻结按批次相加，不重新取整（Q28）**
   **Given** 另一空库：入金 100.00（2026-10-26 10:00）
   **When** 录入 STO 1 张 F 2026-12-18 12.345 P，multiplier 1，净额 0.50（2026-11-02 10:00），再录入同一合约同样一笔（2026-11-03 10:00）
   **Then** 持仓：空头、`2（multiplier 1）`、`+1.00`、每张 `+0.50`、冻结现金 `24.70`（12.35 + 12.35，不是 12.345 × 2 = 24.69 取整）；顶部冻结合计 `24.70`，与资金页冻结现金一致；展开有 2 个批次，各冻结 `12.35`。

5. **DTE（今天 = 2026-11-11）**
   - 到期日 2026-12-18 → `37`；2027-01-15 → `65`（日历天数，含周末和感恩节等假日）。
   - 后端测试把时钟改为 2026-11-12 00:30（美东）后再查询：2026-12-18 → `36`。时钟为 2026-11-12 04:30Z（= 美东 2026-11-11 23:30）时仍为 `37`（按美东日期，不按 UTC 日期）。

6. **到期日当天（0DTE）与已过期未处理**
   **Given** 另一空库：入金 50,000.00（2026-10-26 10:00）；录入 STO 1 张 TSLA 2026-11-06 250 P，净额 300.00（2026-11-02 10:00）；录入 BTO 1 张 SPY 2026-11-11 600 C，净额 50.00（2026-11-02 10:00）

7. **新录入后自动刷新**
   **Given** 基准数据，已打开过持仓页

   **When** 点击持仓 `AAPL 2026-12-18 200 P` 的合约

## 边界情况
- **同一合约多次开仓**：合并为一行，批次按 FIFO 顺序（验收 2、7）。
- **同一时间开仓的多个批次**：先录入的在前（Q19）。
- **一笔多张**：一个批次，不拆分（验收 2 的 F）。
- **多个标的**：各自成行，按排序规则排列（验收 1）。
- **0DTE**：DTE 为 0，标"今天到期"（验收 6）。
- **已过到期日、未处理**：仍是持仓，DTE 为负、显示"已过期 N 天"，冻结不释放；作废/指派/行权在 M2（FEAT-010/012/013）。
- **美东午夜**：DTE 按美东日期，UTC 已跨日但美东未跨日时不变（验收 5）。
- **周末 / 假日**：DTE 是日历天数，不扣除周末假日；交易日 DTE 在 FEAT-009。
- **multiplier ≠ 100**：张数列附注（验收 1 的 XYZ、验收 4）；冻结、净额都按实际 multiplier（已在交易录入时算好）。
- **平均净额除不尽**：按 Q22 规则舍入，只显示（验收 3、7）；合计不受舍入影响。
- **担保不是整分**：持仓冻结 = 各批次冻结之和（验收 4）。
- **FEAT-004 之后的部分平仓**：FIFO 先扣最早批次的剩余张数；剩余张数为 0 的批次不显示；净张数为 0 的合约不再是持仓。批次的剩余净额、剩余冻结按 FEAT-004 的规则（Q21 等）计算，本需求的数据结构已包含"原 / 剩余"，无需返工。FEAT-004 验收时一并检查持仓页。
- **补录较早的开仓**：按成交时间进入 FIFO 顺序的相应位置（例：已有 11-04 的批次，补录 11-02 的同合约开仓，则补录的那笔排第一）。
- **标的拆股**：不在本需求（FEAT-028）。

## Out of Scope
- 平仓、FIFO 扣减和冻结释放（FEAT-004）；在持仓页直接发起平仓

## Implementation Notes
### Backend
**API**（详见 `docs/api/api-contract.md` 的 FEAT-003 小节）
- `GET /api/option-positions`，无参数 → `{asOfDate, positionCount, frozenTotal, positions[]}`
- `positions[]`：`symbol`、`expirationDate`、`strike`（去尾零）、`optionType`、`contractLabel`、`direction`（`SHORT`/`LONG`）、`contracts`、`multiplier`、`openingNetTotal`（空头正、多头负）、`averageNetPerContract`（HALF_UP 到分）、`frozenCash`、`dte`、`expirationStatus`（`ACTIVE` / `EXPIRES_TODAY` / `EXPIRED`）、`daysPastExpiration`（已过期天数 N，未过期 0）、`lotCount`、`lots[]`
- `lots[]`（FIFO 顺序）：`tradeId`、`action`、`tradedAt` + `tradedAtLocal`、`originalContracts` / `remainingContracts`、`originalNetAmount` / `remainingNetAmount`（带现金方向符号）、`originalFrozen` / `remainingFrozen`、`note`
- 跳转交易列表：持仓的 `symbol`、`expirationDate`、`strike`、`optionType` 可原样作为 FEAT-002 的同名 query 参数
- 前端不需要做任何计算：张数、合计、平均、冻结、DTE、过期天数、状态都由后端给出；金额全部是字符串

**文件**
- 新增 `trade/domain/`：`LotTrade`、`PositionLot`、`OptionPosition`、`PositionBuilder`、`PositionDirection`、`ExpirationStatus`；`trade/service/OptionPositionService`；`trade/web/OptionPositionController`
- 没有数据库迁移（只读）
- 测试：`trade/domain/PositionBuilderTest`、`trade/web/OptionPositionControllerTest`（验收 1–7、9、10 的后端部分，时钟默认 2026-11-11 10:00 美东，可调）
- 文档：`docs/api/api-contract.md`（FEAT-003 小节）、`docs/architecture.md`

**设计决定**
- 持仓不落库：每次请求读出全部交易及对应现金流水，按合约分组，FIFO（成交时间、交易 id）重放得出
- 批次的开仓净额和冻结取自该笔交易的**现金流水**（`amount`、`frozen_change`），不是重新计算，所以持仓冻结 = 各批次冻结之和（Q28 的 12.345 例子为 24.70），冻结合计与现金汇总的 `frozenCash` 一致
- "今天" = 注入的 `Clock` 当前时间的美东日期；DTE = 日历天数差（`ChronoUnit.DAYS`）
- 状态额外给出 `expirationStatus`、`daysPastExpiration`，前端不用自己判断正负或取反
- 排序：标的按字符串（字符编码）升序。标的只有大写字母、数字和点，所以就是字母序，数字和点排在字母前
- 批次同时返回原值和剩余值（本需求两者相等），FEAT-004 只需在 `PositionBuilder` 里实现 FIFO 扣减；目前遇到平仓交易会抛异常（FEAT-004 之前不可能存在平仓交易）

**已知限制**
- 每次请求加载全部交易和对应流水（个人数据量小，可接受）
