## 背景 / 用户故事
作为一个期权交易者，我想在持仓页看到每个期权和股票持仓按当前行情的市值和未实现盈亏，以及本账户的合计，以便知道现在平掉能赚 / 亏多少。

## 已定的口径（只引用）
- Q6：期权只记含手续费的净额（STO 实收、BTO 实付），没有单独的手续费。Q67：股票同样只记含手续费的净额。
- Q8：put 被指派得到的股票，成本已扣除权利金（股票持仓的总成本直接用，不另调整）。
- Q21 / Q69 / Q87：期权整笔批次、股票按比例分摊后的**剩余**净额 / 成本，即 FEAT-003 的"开仓净额合计"、FEAT-011 的"总成本"。
- Q139 / Q140 / Q148：mark 的定义与手动覆盖，都由 FEAT-016 给出，本需求直接使用显示出来的 mark / 现价。
- Q149：指数期权不拉取（无报价，可手动）。Q150 / Q151：到期日 < 美东今天的合约冻结，显示库里最后报价。
- FEAT-033 / backlog 多账户约定：按账户隔离，只做单账户视图（合并查看在 FEAT-035）。
- 本需求的 Q152–Q160 已定，结论见下方规则中的引用。Q161：场景只用 multiplier 100，计算仍用字段值。
- Q162：页面上所有市值（期权行、股票行、合计行）都带显式正负号（`+160.00` / `−125.00`，0 为 `0.00`）。

## 规则
1. **期权市值** = mark × 张数 × multiplier，带方向：多头为正、空头为负（Q152）。mark 用 FEAT-016 当前显示的值（含手动覆盖、行情未更新时保留的上次报价、`数据源已无该合约` 的最后报价）。
2. **期权未实现盈亏** = 开仓净额合计（FEAT-003，带现金方向：空头 +，多头 −）+ 市值（规则 1）。即：空头 = 实收 − mark × 张数 × multiplier；多头 = mark × 张数 × multiplier − 实付。开仓手续费已在净额里（Q6）；不预估平仓手续费（Q153）。
3. **股票市值** = 现价 × 持股；**股票未实现盈亏** = 市值 − 总成本（FEAT-011，被 covered call 覆盖的股数也算在内）。现价用 FEAT-016 股票行的值（含 Finnhub 来源、手动覆盖）。
4. **取整**：市值四舍五入到分，盈亏用取整后的市值计算（Q154）。
5. **百分比**：期权 = 未实现盈亏 ÷ |开仓净额合计|；股票 = 未实现盈亏 ÷ 总成本；四舍五入到 2 位小数，带符号；分母为 0.00 时显示 `—`（Q155）。
6. **无法计算**：
   - mark 为空（从未有报价、指数期权、bid 为 0 且无 theo）→ 市值、盈亏、百分比都显示 `无报价`，不计入合计；股票现价为空同理。
   - 已过期未处理（到期日 < 美东今天，Q150）→ 不计算，显示 `已到期，待处理`，不计入合计（Q156）。到期日当天仍正常计算。
7. **合计**（只算当前账户，Q157）：期权市值合计、期权未实现盈亏合计；股票市值合计、股票未实现盈亏合计；两者相加的总市值、总未实现盈亏。被规则 6 排除的持仓不计入，并给出个数：`N 个持仓无报价 / 已到期待处理，未计入`（Q160）。合计不受持仓页到期过滤影响（Q158）。
8. 所有计算只在后端做；前端只显示后端的值和标签。

## 需要的数据和操作（给 backend）
- 期权持仓每行加：市值、未实现盈亏、百分比（规则 1、2、4、5），以及不可计算时的原因（无报价 / 已到期待处理，规则 6）。
- 股票持仓每行加：市值、未实现盈亏、百分比（规则 3–6）。
- 账户合计（规则 7）：6 个数字 + 未计入的持仓个数（可分原因）。
- 不需要新的写操作；行情刷新、手动覆盖后重新查询即得到新值（实时计算，不存库）。

## 页面与交互（给 frontend）
- **期权持仓表**：在 `Mark` 列后加 `市值`、`未实现盈亏` 两列。市值带符号（多头 `+370.00`、空头 `−125.00`，Q162）；盈亏正绿负红，下面小字百分比（如 `+68.70` / `+22.80%`）。不可计算时两列显示后端给的文字（`无报价` / `已到期，待处理`），灰色。
- **股票持仓表**：在 `现价` 后加 `市值`、`未实现盈亏`（同上格式）。
- **持仓页顶部**（FEAT-003 顶部一行之下）新增一行合计：`期权 市值 +160.00 未实现 +61.75 ｜ 股票 市值 +6,110.00 未实现 +230.00 ｜ 合计 市值 +6,270.00 未实现 +291.75`；有未计入时后面加灰字 `1 个持仓无报价，未计入`。表头注明"未实现盈亏已含开仓手续费，未扣平仓手续费；按 mark 计算，仅供参考"。
- 切换账户、立即刷新、设置 / 清除手动值后，行和合计随持仓重新查询更新。
- 首页不改（Q159）。

## 验收标准
场景（所有条目共用）：今天 2026-11-23（星期一）10:00 拉取成功，标的均为虚构。
账户 A：
- P1：STO 1 张 QRTV 2026-12-18 50P，净额 118.70；假 CBOE bid 1.20 / ask 1.30（mark 1.25）。
- P2：BTO 2 张 QRTV 2026-12-18 55C，净额 301.30；bid 1.80 / ask 1.90（mark 1.85）。
- P3：STO 1 张 IXQZ 2026-12-18 65C，净额 84.35；bid 0.80 / ask 0.90（mark 0.85）。
- P4：STO 1 张 QRTV 2026-12-18 47.5P，净额 45.00；链中从无该合约。
- IXQZ 股票 100 股，总成本 5,880.00；现价 61.10。

账户 B：P5：STO 1 张 QRTV 2026-12-18 50P，净额 120.00。

1. **Given** 场景 **When** 打开账户 A 的持仓页 **Then** P1 市值 `−125.00`、未实现 `−6.30`（`−5.31%`）；P2 市值 `+370.00`、未实现 `+68.70`（`+22.80%`）；P3 市值 `−85.00`、未实现 `−0.65`（`−0.77%`）。
2. **Given** 场景 **Then** IXQZ 股票行 市值 `+6,110.00`、未实现 `+230.00`（`+3.91%`）。
3. **Given** 场景 **Then** P4 的市值、未实现盈亏都显示 `无报价`；顶部合计 `期权 市值 +160.00 未实现 +61.75 ｜ 股票 市值 +6,110.00 未实现 +230.00 ｜ 合计 市值 +6,270.00 未实现 +291.75`，并显示 `1 个持仓无报价，未计入`。
4. **Given** 场景 **When** 切换到账户 B **Then** P5 市值 `−125.00`、未实现 `−5.00`（`−4.17%`）；合计 期权 `−125.00` / `−5.00`，股票 `0.00` / `0.00`，合计 `−125.00` / `−5.00`，无"未计入"提示。
5. **Given** 场景 **When** 把 P1 的 Mark 手动设为 1.40 **Then** 账户 A 的 P1 市值 `−140.00`、未实现 `−21.30`，期权合计未实现 `+46.75`；账户 B 的 P5 未实现 `−20.00`。**When** 把 P4 的 Mark 手动设为 0.30 **Then** P4 市值 `−30.00`、未实现 `+15.00`，`未计入` 提示消失。
6. **Given** 场景，账户 A 另有 P6：BTO 1 张 QRTV 2026-12-18 60C、净额 15.65，bid 0.10 / ask 0.15（mark 0.125） **When** 查看 **Then** P6 市值 `+12.50`、未实现 `−3.15`（`−20.13%`）；合计 期权 `+172.50` / `+58.60`，合计 `+6,282.50` / `+288.60`。**When** 10:15 拉取时 P6 变为 bid 0 / ask 0.05 / theo 0.03 **Then** P6 市值 `+3.00`、未实现 `−12.65`（`−80.83%`）；合计 期权 `+163.00` / `+49.10`，合计 `+6,273.00` / `+279.10`。
7. **Given** 场景 **When** 10:15 起 QRTV 拉取失败（行上显示 `行情未更新（上次：11-23 10:00）`） **Then** P1、P2 仍按 1.25、1.85 显示 `−6.30`、`+68.70`，计入合计。
8. **Given** 场景，账户 A 另有 STO 1 张 QRTV 2026-11-20 45P、净额 60.00（已过期未处理，库里最后 mark 0.05） **When** 查看 **Then** 该行市值、未实现盈亏显示 `已到期，待处理`，合计不变，提示 `1 个持仓无报价、1 个持仓已到期待处理，未计入`。**When** 对它做"到期作废"后 **Then** 该行消失，提示恢复为 `1 个持仓无报价，未计入`。
9. **Given** 场景 **When** STC 2 张 P2、净额 368.70 **Then** P2 不再出现，期权合计 市值 `−210.00`、未实现 `−6.95`，合计 市值 `+5,900.00`、未实现 `+223.05`。
10. **Given** 一个没有任何持仓的账户 **When** 打开持仓页 **Then** 合计行全部 `0.00`，无"未计入"提示。

## 边界情况
- **到期日当天**：正常计算（规则 6 只排除到期日 < 今天）；当天收盘后链中消失按 FEAT-016 保留最后报价，仍计算。
- **mark 为 theo**（bid 为 0）：照常计算，不另加标注（验收 6）。
- **同一合约在多个账户**：共用 mark，各账户按自己的张数和净额计算（验收 4、5）。
- **covered call 的股票**：被覆盖的股数照常计入股票市值（规则 3）。
- **被指派得到的股票**：总成本已含权利金调整（Q8），不再与原期权关联。
- **拆股调整合约 / 指数期权**：通常无报价 → 规则 6；手动设 mark 后可计算。
- **百分比的分母为 0**：开仓净额或总成本为 0.00 时（如 0 成本转入）百分比显示 `—`。
- **合计行与到期过滤**：选"已过期未处理""今天到期"等过滤时合计仍为全账户（规则 7）。

## Out of Scope
- 首页显示未实现盈亏（见 Q159）；盈亏汇总页的未实现部分。
- 今日盈亏（用前收计算）、历史市值曲线（收盘快照的查看另立）。
- 合并查看（FEAT-035）、策略组层面的未实现盈亏（FEAT-023）。
- 已过期合约按内在价值估算（Q156）。
- 非 100 multiplier 的场景（Q161）。
- Greeks（FEAT-018/019）。

### Backend
- **新增**：`backend/src/main/java/com/optionmgr/valuation/`。`domain/ValuationStatus`、`RowValuation`、`UnrealizedValuation`（单行计算）、`UnrealizedSummary`（三组合计与 `excludedLabel`），`service/UnrealizedValuationService`，`web/UnrealizedSummaryController`（`GET /api/positions/unrealized-summary`）。
- **修改**：`trade/web/OptionPositionController`（`PositionResponse` 加 5 个字段）、`stock/web/StockTradeDtos` + `StockPositionController`（`StockPositionResponse` 加 5 个字段）。纯新增字段，没有数据库迁移。
- **测试**：`valuation/domain/UnrealizedValuationTest`（13 个，规则 1–7 和验收数字）、`valuation/web/UnrealizedPnlControllerTest`（10 个，验收 1–10 + 股票无现价 + 账户错误）。
- **设计决定**（契约阶段定、已被接受）：已到期判定优先于无报价（已过期且有 mark 或无 mark 都是 `已到期，待处理`）；百分比只给带负号的数值，`+`、`%`、`—` 由前端格式化；股票无现价也计入"无报价"个数；合计不给百分比；市值先按正数取整再加符号。单行和合计用同一套代码、同一个 `QuoteBook`。
- **已知限制**：合计与两个持仓接口是三次独立请求，中间如果正好有一次行情拉取或交易录入，页面上可能短暂对不上，下一次查询后一致。`OptionPositionController.toResponse` 也被 FEAT-043 的调整响应用到，所以那里的 `position` 也带这 5 个新字段（纯新增）。
