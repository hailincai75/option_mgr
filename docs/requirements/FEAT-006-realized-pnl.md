## 背景 / 用户故事
作为一个期权交易者，我想要在一个页面上看到每一笔平仓赚了还是亏了多少（已含手续费），能按标的、合约、方向、平仓日期筛选，并看到筛选结果的已实现盈亏合计，以便复盘交易、核对券商的已实现盈亏。

FEAT-004 已经在每笔平仓上算出了已实现盈亏和被平批次（平仓确认信息、按 ID 查询）。本需求新增的是**"已平仓记录"列表页**：一行一笔平仓、可展开看被平批次、筛选、分页、筛选结果合计。按标的/按月分组汇总和首页盈亏数字属于 FEAT-008。

## 已定的口径（来自 backlog Open Questions）
- 每笔交易只记含手续费的净额（Q6）；已实现盈亏直接用净额算，不再单独扣手续费
- 平仓必须整笔平掉该合约最早的 1 笔或连续多笔开仓批次，不支持部分平仓；已实现盈亏**按每笔平仓整体**计算，没有分摊、没有舍入（Q21）：
  - 平空头（BTC）：被平批次开仓实收之和 − 平仓实付
  - 平多头（STC）：平仓实收 − 被平批次开仓实付之和
  - 例：STO 2 张净收 698.70，BTC 2 张实付 241.30 → +457.40
- 每张平均净额 = 净额 ÷ 张数，四舍五入到分，带正负号，只用于显示（Q22）
- 已实现盈亏由后端在读取时按 FIFO 重放得出（Q38）；补录、修改、删除交易后之后的平仓按新的匹配重新计算（Q39、FEAT-005）
- 时间、日期按美东；日期范围按美东日期、两端包含（Q14、Q33）
- 标的精确匹配；合约筛选为到期日 / 行权价 / C·P 三个独立条件；方向多选（Q30–Q32）

- 页面显示**当前筛选结果**的笔数和已实现盈亏合计（一个数字）；按标的、按月等分组汇总和首页数字仍归 FEAT-008（Q46）
- 不显示持有天数（Q47）

## 需要的数据和操作（给 backend）

### 操作：查询已平仓记录
返回所有平仓交易（BTC / STC），每笔一条，按筛选条件过滤、排序、分页。只读，不改任何数据。

**排序（固定）**：平仓成交时间倒序；同一时间后录入的在上（与 FEAT-002 一致）。

**每条记录需要的数据**（全部由后端给出，前端不做加总、平均、盈亏计算）：

| 数据 | 规则 / 例子 |
|------|-------------|
| 平仓交易 ID | 用于跳转审计历史 |
| 平仓时间 | UTC + 美东本地时间 |
| 合约 | 标的、到期日、行权价（去尾零）、Call/Put、合约显示名；与 FEAT-002 一致 |
| 平仓方向 | BTC / STC；以及被平掉的持仓方向（BTC → 空头，STC → 多头） |
| 张数、multiplier | 平仓张数；multiplier 用于"≠ 100 时附注" |
| 开仓净额合计 | 被平批次开仓净额之和，带现金方向符号：空头为正（实收），多头为负（实付）。例：+698.70 + 360.00 → `+1,058.70` |
| 开仓每张平均 | 开仓净额合计 ÷ 张数，四舍五入到分，同号（Q22）。例：1,058.70 ÷ 3 → `+352.90` |
| 平仓净额 | 带现金方向符号：BTC 为负、STC 为正。例：`−400.00` |
| 平仓每张平均 | 平仓净额 ÷ 张数，四舍五入到分，同号（Q22）。例：400.00 ÷ 3 = 133.333… → `−133.33` |
| 已实现盈亏 | 带符号，按 Q21 公式 = 开仓净额合计 + 平仓净额（带符号相加）。例：`+658.70` |
| 被平批次 | FIFO 顺序：开仓交易 ID、开仓时间、方向、张数、开仓净额（带符号） |
| 备注 | 平仓交易的备注 |

**整体（Q46）**：符合筛选条件的**全部**记录（不只是当前页）的笔数和已实现盈亏合计。没有记录时合计为 0.00。

**分页**：与 FEAT-002 相同——页码从 1 开始、超过最后一页返回空列表；每页 1–100 条，默认 20。

**筛选条件**（全部可选；空 = 不筛选；之间是"并且"；规则、校验和错误与 FEAT-002 相同）：
- 标的：规范化后精确匹配（Q31）
- 到期日、行权价（按数值）、Call/Put：三个独立条件（Q30）
- 方向：BTC / STC 多选（Q32）；只接受这两个值，其它值按"无法解析"报错
- 平仓开始日期 / 结束日期：平仓成交时间的**美东日期**，两端包含，可只填一端；开始晚于结束 → 字段校验错误（Q33）

### 其它
- 不新增、不修改数据；不影响现金、持仓。
- 新增、补录、修改、删除任何交易后，查询结果按最新的 FIFO 匹配给出（盈亏、被平批次、合计都会随之变化）。

## 页面与交互（给 frontend）

### 入口
- 新增"已平仓"页面（已平仓记录），顶部导航有入口（如"已平仓"）。

### 顶部
- `共 N 笔平仓`、`已实现盈亏合计 +633.05`（正绿负红；有筛选时为筛选结果的合计，并注明"当前筛选"）。数字来自后端。

### 表格
按后端顺序，每行一笔平仓：

| 列 | 显示 |
|----|------|
| 平仓时间 | 美东 `YYYY-MM-DD HH:mm`，注明"美东时间" |
| 合约 | 合约显示名；可点击，跳到交易列表（FEAT-002）并按该合约筛选 |
| 方向 | `BTC（买入平仓）` / `STC（卖出平仓）`，旁边标出被平持仓 `空头` / `多头` |
| 张数 | 如 `3`；multiplier ≠ 100 时附注 `1（multiplier 10）`（与 FEAT-002 一致） |
| 开仓净额合计 | 带符号着色，如 `+1,058.70`，下方小字 `每张 +352.90` |
| 平仓净额 | 带符号着色，如 `−400.00`，下方小字 `每张 −133.33` |
| 已实现盈亏 | 带符号，正绿负红，如 `+658.70` |
| 备注 | 平仓备注；长的截断 + 悬停；空为 `—` |
| 操作 | "历史"：跳到审计记录页并按这笔平仓筛选（FEAT-005） |

- 表头或页面说明："净额均已含手续费；空头开仓为实收、多头开仓为实付；每张平均仅供参考"。
- 每行可展开，显示被平批次（FIFO 顺序，最早在上）：开仓时间（美东）、方向（`STO（卖出开仓）` 等）、张数、开仓净额（带符号）。

### 筛选区、分页、地址栏
- 与 FEAT-002 交易列表相同的做法：标的、到期日、行权价、Call/Put（不限 / Call / Put）、方向（BTC / STC 多选）、平仓开始日期、平仓结束日期（注明"美东日期"）；"查询""清除筛选"；前端格式校验与后端错误显示在对应筛选项下。
- 改筛选回到第 1 页；分页器 + 每页 20 / 50 / 100。
- 筛选条件、页码、每页条数写在地址栏，可收藏、刷新保留、后退恢复；不合法的地址参数不崩溃，在对应筛选项下报错。

### 空状态、加载与错误
- 一笔平仓都没有（无筛选）：显示"暂无平仓记录"，顶部 `共 0 笔平仓`、`已实现盈亏合计 0.00`。
- 有筛选无结果：显示"没有符合条件的平仓记录"和"清除筛选"，合计 0.00。
- 加载中、请求失败（错误 + 重试）沿用现有做法。

### 刷新
- 在任何页面新增、修改、删除交易后，打开已平仓页无需手动刷新即显示最新的盈亏和批次匹配。

## 边界情况
- **一笔平仓覆盖多个批次**：一行，盈亏整笔计算（验收 1、2）。
- **亏损**：负数红色（C2、C4）。
- **多头平仓**：开仓净额为负、平仓净额为正（C3、C4）。
- **multiplier ≠ 100**：附注（C2）；盈亏只用净额，不受 multiplier 影响。
- **每张平均除不尽**：四舍五入只用于显示（C1 的 −133.33）；合计和盈亏不受影响。
- **深夜平仓**：按美东日期归属（验收 4）。
- **补录 / 修改 / 删除**：盈亏和批次按新匹配，合计随之变化（验收 5）。
- **同一时间多笔平仓**：后录入的在上。
- **超过最后一页**：空列表，合计仍是全部结果的合计。
- **M2 的到期作废 / 被指派 / 行权**：也会产生已实现盈亏，但不在本需求；那些需求再决定是否加入本列表。
- **标的拆股**：不在本需求（FEAT-028）。

## Out of Scope
- 按标的、按月、按日期范围的分组汇总，首页总盈亏和本月盈亏（FEAT-008）
- 持有天数、胜率、平均盈亏等统计（Q47；FEAT-031）
- 按盈利/亏损筛选、按其它列排序
- 未实现盈亏（FEAT-017）
- 到期作废 / 指派 / 行权产生的盈亏（FEAT-012/013/014）
- 导出 CSV（FEAT-029）
- 在本页修改或删除交易（到交易列表操作，FEAT-005）
- 任何券商接入

## Implementation Notes
### Backend
**API**（详见 `docs/api/api-contract.md` 的 FEAT-006 小节）
- `GET /api/closed-trades`：query 参数、校验、错误与 FEAT-002 交易列表完全相同，只是 `action` 只接受 `BTC`/`STC`（其它值 400 `BAD_REQUEST`，`方向只能是 BTC、STC`），日期筛平仓日期（美东）
- 响应 `{items, page, size, totalItems, totalPages, filteredCount, filteredRealizedPnlTotal}`；`filteredCount` / `filteredRealizedPnlTotal` 覆盖全部筛选结果（不只本页）
- 每条：`id`、`tradedAt` + `tradedAtLocal`、合约四项 + `contractLabel`、`action`、`closedDirection`（`SHORT`/`LONG`）、`contracts`、`multiplier`、`openingNetTotal` + `openingNetPerContract`、`closeNetAmount` + `closeNetPerContract`、`realizedPnl`、`note`、`coveredLots[]`（同 FEAT-004）。金额都带现金方向符号，前端只格式化
- "历史"跳转：`/api/audit-log?objectType=OPTION_TRADE&objectId=<id>`；合约跳转：合约四项原样作为交易列表参数

**文件**
- 新增 `trade/domain/ClosedTrade`、`trade/service/ClosedTradeService`、`trade/web/ClosedTradeController`
- 修改 `trade/web/TradeListQuery`（可限定允许的方向）、`trade/service/OptionTradeService`（`views` 包内可见）
- 测试：`trade/web/ClosedTradeControllerTest`（验收 1–6、8、9 的后端部分）
- 没有数据库迁移；文档：`docs/api/api-contract.md`、`docs/architecture.md`

**设计决定**
- 独立接口 `/api/closed-trades`，而不是在交易列表上加参数：响应结构不同（开仓/平仓的每张平均、方向、合计）
- 盈亏和被平批次每次读取时重放得出（与 FEAT-004/005 一致），补录/修改/删除后自动是新匹配
- 合计要覆盖全部筛选结果，所以每次请求读出全部符合条件的平仓、按合约重放、在内存中分页。个人数据量下可以接受；以后数据很多时再考虑缓存
