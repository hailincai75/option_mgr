## 背景 / 用户故事
用户（2026-11-16）："想把应用暴露到互联网，以便从手机访问；要求非常严格的访问控制。" FEAT-049 解决"谁能登录"；本需求解决"网络上谁能连到这个应用"、应用和数据放在哪、HTTPS、备份，以及用户要自己做的设置。

作为系统唯一的使用者，我想在外面用手机打开我的期权管理系统，同时除了我以外没有人能连到它，以便随时查看持仓又不泄露交易数据。

## 访问方式（Q250，待你选）
| 方式 | 说明 | 限制程度 |
|------|------|------|
| **A 私有网络**（PM 推荐） | Tailscale / WireGuard 一类：应用**从不出现在公网**，手机装客户端加入你的私有网络后才能连；HTTPS 用私有网络提供的主机名证书（如 Tailscale 的 `*.ts.net`）。FEAT-049 作为第二层 | 最严：没有公网入口；不在私有网络里的设备连端口都看不到 |
| **B 隧道 + 身份网关** | 如 Cloudflare Tunnel + Cloudflare Access，只放行你的 Google 邮箱：家里不开端口，请求在到达应用之前先过 Google 登录；需要一个自己的域名 | 较严：有公网地址，但网关挡在前面；流量经第三方，第三方能看到明文 |
| **C 公网 HTTPS**（不推荐） | 云主机或家里路由器端口转发 + Let's Encrypt 证书，只靠 FEAT-049 保护 | 最松：任何人都能连到登录页，应用的任何漏洞都直接暴露 |

## 规则
1. **只监听本机**：A、B 下应用只监听 `127.0.0.1`，由私有网络客户端（A）或隧道程序（B）在本机转发进来；家庭局域网的其它设备、公网都不能直接连到 8080。C 下只开放 443。
2. **只有正式构建**：对外提供的只是后端 + FEAT-049 规则 4 的正式构建前端；Vite 开发服务器（5173）和测试 profile 永远不对外。
3. **对外 profile**：新增一个"对外运行"配置：API 文档（swagger）、actuator、H2 控制台**关闭**（404）；测试登录和测试重置不存在；对外地址必须是 `https://` 开头，否则拒绝启动；其余同 FEAT-049 规则 11。
4. **HTTPS**：手机到应用全程 HTTPS，证书由所选方式提供（A：私有网络的主机名证书；B：网关；C：Let's Encrypt），证书自动续期。用 `http://` 访问时不提供任何内容（或只跳转到 https）。
5. **真实客户端 IP**：只信任本机转发程序加的来源 IP 头，用于 FEAT-049 的限流和登录日志；直接连接时忽略该头，防止伪造。
6. **应用和数据位置**（Q251）：决定应用和 H2 文件库放在家里电脑还是云主机；不论放哪，数据库文件只在那台机器的 `data/` 下，不进 git、不上传到第三方（备份见规则 8）。
7. **常驻运行**（Q254）：开机自动启动应用；崩溃后自动重启；启动和停止有脚本，写进部署文档。
8. **备份**（Q252）：每天自动把数据库复制一份带时间戳的备份，保留天数可配置；备份失败写日志。部署文档写清**恢复步骤**，用户至少演练一次。
9. **部署文档**：backend-dev 写一份部署说明（放 `docs/architecture.md` 或其指定位置）：所选方式的安装步骤、需要的配置项名称（只写名称，不写值）、启动 / 停止 / 查看日志 / 备份恢复。
10. agent 只写配置、脚本和文档；**不安装、不登录、不注册任何服务**，不触碰用户的路由器、DNS、云账户。

## 前提（用户自己做，agent 不做）
agent 不得创建任何账户、不得输入或保存任何凭据。按所选方式由用户本人：
- **A**：注册私有网络服务账户（可用自己的 Google 账户登录）；电脑和手机都安装客户端并登录；在管理后台开启主机名和 HTTPS 证书；建议只允许自己的设备加入，关闭共享 / 邀请。
- **B**：注册 Cloudflare、准备一个域名并把 DNS 交给它；电脑上安装隧道程序；配置 Access 策略只允许自己的 Google 邮箱。
- **C**：开云主机或在路由器上开端口转发；配置域名 DNS。
- **都要**：在 FEAT-049 的 Google OAuth 客户端里加上对外主机名的重定向 URI；在 `.env` 里填对外地址。

## 验收标准
多数项目要在真实环境由用户本人验证（标"手动"）；标"自动"的由 qa 用对外 profile 在本机测试。场景：方式按 Q250 的结论，下面以 A 为例；对外地址记为 `https://<主机名>`（占位）；数据中有 FEAT-049 场景的入金 10,000.00。

1. **手机能用**（手动）：**Given** 手机用蜂窝网络（不连家里 Wi-Fi）、私有网络客户端已开 **When** 打开 `https://<主机名>` 并用自己的 Google 账户登录 **Then** 看到首页，资金页总现金 `10,000.00`。
2. **网络外的设备连不上**（手动）：**When** 手机关掉私有网络客户端、或用不在私有网络里的设备访问 `https://<主机名>` **Then** 无法连接（不是登录页，而是连不上）。
3. **公网和局域网无入口**（手动）：**When** 从外部检查家里公网 IP 的 80、443、8080，以及从局域网其它设备访问 `http://<电脑局域网 IP>:8080` **Then** 全部无法连接。
4. **对外 profile 关闭管理端点**（自动）：**When** 以对外 profile 启动并已登录 **Then** swagger、actuator、H2 控制台、测试登录、测试重置都返回 404。
5. **对外地址必须 HTTPS**（自动）：**When** 对外 profile 下对外地址配置为 `http://example.test` **Then** 启动失败，日志写明原因；改为 `https://example.test` 后正常启动。
6. **HTTPS 与 cookie**（手动）：**Then** 手机浏览器显示证书有效；会话 cookie 带 Secure；用 `http://<主机名>` 访问拿不到任何页面内容。
7. **真实 IP**（自动 + 手动）：**When** 从手机连续发起 11 次登录 **Then** 第 11 次 429（FEAT-049 规则 9），日志里的 IP 是手机在私有网络中的地址，不是 `127.0.0.1`；直接连接时伪造的来源 IP 头被忽略（自动）。
8. **重启后自动恢复**（手动）：**When** 电脑重启并登录系统（或按 Q254 的方式） **Then** 5 分钟内手机可以再次访问并登录。
9. **备份与恢复**（自动 + 手动）：**When** 到了每天的备份时间 **Then** `data/` 下出现带时间戳的新备份，超过保留天数的被删除；**When** 按部署文档把某个备份恢复到一个新的目录并启动 **Then** 资金页总现金与备份时相同（`10,000.00`）。

## 边界情况
- **电脑睡眠 / 关机**（A、B 放家里时）：手机连不上，属于预期；见 Q251。
- **私有网络服务故障**：手机暂时连不上，不影响数据；在家里本机照常用 localhost。
- **手机丢失**：在私有网络后台移除该设备 + 在 Google 账户里退出该设备；应用会话最长到 FEAT-049 的绝对超时，必要时重启应用使全部会话失效（写进部署文档）。
- **同时在电脑和手机上用**：各自一个会话，互不影响。
- **证书续期失败**：浏览器报证书错误、不能继续，不降级到 http。
- **行情定时任务**：照常在应用所在机器运行（时间按美东）；放云主机时注意时区配置不变。

## Open Questions
- **Q250 手机怎么连到应用**：A 私有网络 / B 隧道 + 身份网关 / C 公网 HTTPS（见上表）。PM 建议：A，加上 FEAT-049 作为第二层；应用从不上公网。代价是手机要装客户端并保持开启。
- **Q251 应用和数据放哪里**：家里电脑还是云主机？PM 建议：家里电脑（数据不离开你的机器）；代价是电脑睡眠或关机时手机连不上，需要把电脑设为不睡眠。云主机随时在线，但交易数据放到第三方机器上，且要另付费、另管安全。
- **Q252 备份**：每天几点、保留多少天、要不要异地副本？PM 建议：每天美东 20:00、保留 30 天、只放本机 `data/`；异地副本由你自己定期拷到加密 U 盘或网盘，不由应用自动上传。
- **Q253 HTTPS 证书来源**：PM 建议：跟随 Q250（A 用私有网络自带的主机名证书，不需要自己的域名）。如果你希望用自己的域名，请告诉我。
- **Q254 常驻运行方式**：开机自动启动（不需要登录 Windows）还是登录 Windows 后启动？PM 建议：开机自动启动（作为 Windows 服务或开机任务），这样重启后无人值守也能恢复访问。
