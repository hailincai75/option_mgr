# FEAT-005: 交易与入金/出金的修改、删除（含审计）

- **Status:** Verified
- **Priority:** P0
- **Depends on:** FEAT-004（平仓，已 Verified）；FEAT-001、FEAT-002、FEAT-003、FEAT-007
- **Scope:**
  - [x] Backend: Done
  - [x] Frontend: Done

## 背景 / 用户故事
作为一个期权交易者，我录入交易或入金/出金时难免填错（净额、张数、时间、备注……）。我想要直接修改或删除录错的记录，系统按时间重放全部历史，确认改完之后持仓、FIFO 批次和现金在每个时点仍然成立才保存，并把每次修改/删除完整地记进审计记录，以便账目和券商一致，同时能追溯改过什么。

## 已定的口径（来自 backlog Open Questions）
- 修改/删除必须留审计：操作时间、操作类型（修改/删除）、修改前和修改后的完整内容；单用户，不记录"谁"（Q12）
- 入金/出金可以**修改**，同样写审计、同样受 Q19 约束（Q24）；能否删除见 Q40
- 按时间重放：从改动点起每个时点总现金和可用现金都不能为负；同一时间按**录入顺序**排（Q13、Q19）
- 一个合约任一时刻只能纯多或纯空（Q7）；有未平仓持仓时 multiplier 必须一致（Q23）
- STO put 冻结 行权价 × multiplier × 张数，每笔向上取整到分（Q13、Q28）；M1 拒绝 STO call（Q16）
- 平仓必须整笔平掉最早的一笔或连续几笔开仓批次（Q21）；BTC 先释放冻结再检查现金（Q20）；成交日不得晚于到期日（Q36）
- 改动较早的记录不能让之后已有的任何交易违规（Q27、Q39）；之后的平仓按新的 FIFO 匹配重新计算被平批次、释放冻结和已实现盈亏（Q39）
- 格式与上限同 FEAT-001 / FEAT-004 / FEAT-007（Q17、Q25、Q29）

- 入金/出金也可以删除，同样写审计、受 Q19 约束（Q40）
- 改动较早记录后，之后已有的 STO put 只按 Q19 检查，不重新按 Q18 检查；被修改的那笔本身按 Q18 检查（Q41）
- 修改/删除连带引起的系统改正写进同一条审计记录的"连带变化"；新增交易引起的改正不审计（Q42）
- 可改字段见下表；合约和方向不能改，录错请删除后重录（Q43）
- 审计记录在独立的"审计记录"页查看，各行"历史"跳转并筛选；不做交易详情页（Q44）
- 修改 STO put 时，只有改了张数、multiplier 或成交时间才对它本身重查 Q18；只改净额或备注不重查（仍要满足 Q19）（Q45）
- 本需求作为一个整体实现，入金/出金的修改删除不拆出去

## 需要的数据和操作（给 backend）

### 可修改的字段（Q43）
| 记录 | 可改 | 不可改（录错请删除后重录） |
|------|------|------|
| 开仓（BTO / STO） | 张数、净额、成交时间、multiplier、备注 | 标的、到期日、行权价、Call/Put、方向 |
| 平仓（BTC / STC） | 张数、净额、成交时间、备注 | 标的、到期日、行权价、Call/Put、方向；multiplier 始终取持仓的值 |
| 入金 / 出金 | 类型（入金 ↔ 出金）、金额、时间、备注 | — |

- 各字段的格式校验与新增时完全相同（FEAT-001 / FEAT-004 / FEAT-007）。
- 修改后的记录**保留原来的录入顺序**（同一时间多条记录的先后不因修改而改变）。
- 提交的内容与原记录完全相同时，不保存、不写审计，提示"没有修改"。

### 操作：修改一笔交易 / 删除一笔交易 / 修改入金出金 / 删除入金出金
所有改动都按同一个原则检查：**把改动应用到全部历史上，按 `(时间, 录入顺序)` 重新重放；只要有任何一笔记录或任何一个时点不成立，就整笔拒绝、什么都不改**，并返回能直接给用户看的中文原因（指出哪个时间的哪一笔、具体数字）。

需要重新检查的内容：
1. **被修改的记录本身**：字段校验；成交时间不晚于当前；开仓的到期日不早于成交日、平仓的成交日不晚于到期日（Q36）。
2. **被修改的开仓本身**：多空冲突（Q7）、multiplier 一致（Q23）；STO put 按 Q18 检查"本笔之前的可用现金 ≥ 新的担保金额（不含本笔权利金）"（Q41）。
3. **被修改的平仓本身**：成交时点有相反方向持仓、不超过持仓、正好是最早若干笔整批次（Q21）。
4. **该合约之后的每一笔已有交易**（以及被删除交易之后的交易）：开仓仍不违反 Q7 / Q23；平仓仍有持仓、方向正确、不超量、整笔批次（Q27、Q39）。
   - 典型拒绝：删除一笔已被之后平仓平掉的开仓；把开仓张数改成之后的平仓不再是整笔批次；把开仓时间挪到平仓之后。
5. **现金（Q19、Q20）**：所有现金记录（入金、出金、开仓、平仓）按新的历史重放，从最早受影响的时点起每个时点总现金 ≥ 0、可用现金 ≥ 0。之后已有的 STO put 只按这一条检查，不再按 Q18 检查（Q41）。
   - 典型拒绝：删除一笔 BTC 平仓后冻结恢复，之后的出金让可用现金变负；把入金改小或改晚。

保存成功后的效果：
- **交易的现金流水随之改变**：修改 → 该交易原来那条流水更新（时间、金额、冻结变动、说明、备注），不新增流水；删除 → 该条流水删除。
- 之后平仓的被平批次、已实现盈亏按新历史重新得出；释放冻结金额如有变化（只会因 Q28 的取整差异，或平仓/开仓张数变化导致），对应平仓流水的冻结变动随之改正（Q39）。
- 入金/出金修改 → 对应流水更新；删除 → 流水删除。
- 余额、冻结、可用、持仓、批次全部按新历史显示。
- 写一条审计记录（见下）。

被删除或不存在的记录再被修改/删除/按 ID 查询时，返回"不存在"。

### 审计记录
每次成功的修改或删除写一条，记录本身不能修改或删除：

| 内容 | 说明 |
|------|------|
| 审计 ID | 递增 |
| 操作时间 | 服务器当前时间（UTC 存储，显示为美东） |
| 操作类型 | 修改 / 删除 |
| 对象 | 期权交易 或 入金/出金，及其 ID |
| 修改前 | 完整内容：交易 = 合约（标的、到期日、行权价、C/P）、方向、张数、multiplier、净额、成交时间、备注、现金变动、冻结变动；入金/出金 = 类型、金额、时间、备注 |
| 修改后 | 同上；删除时为空 |
| 改动的字段 | 修改时列出前后不同的字段（如"净额：360.00 → 365.00"），供页面直接显示 |
| 连带变化（Q42） | 本次改动导致其它交易的**冻结变动**被系统改正时，逐条列出：交易 ID、合约、方向、冻结变动 原值 → 新值。没有时为空 |

- 新增交易（FEAT-001/004 补录）引起的冻结改正不写审计（Q42）。
- 查询：全部审计记录按操作时间倒序（同一时间审计 ID 大的在上）分页，页码从 1 开始、每页 1–100 条、默认 20（与 FEAT-002 一致）；可按对象（类型 + ID）筛选。

## 页面与交互（给 frontend）

### 交易列表（FEAT-002）每行的操作
- 每行加三个操作：**修改**、**删除**、**历史**。
- **修改**：打开对话框，可改字段预填当前值；不可改字段（合约、方向，平仓的 multiplier）只显示不可编辑，并提示"合约或方向录错请删除后重新录入"。净额标签随方向变化（与录入页一致）；成交时间为美东本地时间。
- **删除**：弹出确认框，显示这笔交易的摘要（如 `STO 1 张 AAPL 2026-12-18 200 P，2026-11-04 11:00，+360.00`）和"删除后不可恢复，会写入审计记录"。
- **历史**：跳到审计记录页并按该交易筛选。
- 前端只做格式校验；后端拒绝时原文显示原因，对话框保留已填内容。
- 成功后：交易列表、持仓页、现金汇总、现金流水、审计记录无需手动刷新即显示新数据。

### 资金页流水（FEAT-007）每行的操作
- 入金 / 出金的行：**修改**（类型、金额、时间、备注）、**删除**（Q40）、**历史**，交互同上。
- 期权开仓 / 平仓的行不提供修改删除（到交易列表里改），可提供跳到交易列表的链接（可选）。

### 审计记录页（Q44）
- 新增"审计记录"页面，导航有入口。
- 表格按后端顺序：操作时间（美东 `YYYY-MM-DD HH:mm:ss`）、操作（修改 / 删除）、对象（如 `期权交易 #2` / `入金 #1`）、摘要（交易显示合约 + 方向，入金出金显示类型 + 金额）、改动（修改：逐行显示"字段：原值 → 新值"；删除：显示"已删除"）、连带变化（有时显示，如 `交易 #5 BTC 冻结变动 −24.70 → −24.69`）。
- 每行可展开看修改前 / 修改后的完整内容。
- 可按对象筛选（从"历史"进入时自动带上，筛选反映在地址栏，可清除）。分页同交易列表。
- 没有记录时显示"暂无审计记录"。
- 金额用统一格式化 util。

## 验收标准
所有场景从空库开始，当前时间不早于 2026-11-11 10:00（美东；后端测试可固定时钟，E2E 用真实时钟）。"现金汇总"= 总现金 / 冻结 / 可用。

**场景 A**：入金 D1 = 80,000.00（2026-10-26 10:00，入金 #1）；按顺序录入
- L1（交易 #1）= STO 2 张 AAPL 2026-12-18 200 P，净额 698.70（2026-11-03 10:30）
- L2（交易 #2）= STO 1 张 AAPL 2026-12-18 200 P，净额 360.00（2026-11-04 11:00）
- C1（交易 #3）= BTC 2 张 AAPL 2026-12-18 200 P，净额 241.30（2026-11-05 10:00，平掉 L1，已实现盈亏 +457.40）

现金汇总 80,817.40 / 20,000.00 / 60,817.40；持仓 AAPL 200 P 空头 1 张（L2）。

1. **修改开仓净额**
   **When** 把 L2 的净额从 360.00 改为 365.00
   **Then** 保存成功；现金汇总 80,822.40 / 20,000.00 / 60,822.40；交易列表中 L2 显示 `+365.00`；持仓 `+365.00`、每张 `+365.00`；现金流水条数不变（仍 4 条），L2 那条显示 `+365.00`。
   **And** 审计记录页第一行：操作"修改"、对象 `期权交易 #2`、摘要含 `AAPL 2026-12-18 200 P` 和 STO、改动 `净额：360.00 → 365.00`；展开可见修改前、修改后的完整内容。

2. **修改平仓净额（盈亏随之变化）**
   **When** 把 C1 的净额从 241.30 改为 250.00
   **Then** 现金汇总 80,808.70 / 20,000.00 / 60,808.70；按 ID 查询 C1 的已实现盈亏为 `+448.70`。

3. **修改平仓张数（整笔批次规则）**
   **When** 把 C1 的张数从 2 改为 3
   **Then** 保存成功；C1 平掉 L1 和 L2，冻结变动 `−60,000.00`，已实现盈亏 `+817.40`（698.70 + 360.00 − 241.30）；现金汇总 80,817.40 / 0.00 / 80,817.40；持仓页没有该合约。
   **When**（从场景 A 原始状态）把 C1 的张数改为 1
   **Then** 被拒绝，提示"必须一次平掉整笔开仓：最早一笔是 2 张，可平 2 张或 3 张"；什么都不变，不写审计。

4. **修改开仓张数影响之后的平仓**
   **When** 把 L1 的张数从 2 改为 3
   **Then** 被拒绝：修改后 2026-11-05 10:00 的 BTC 2 张不再是整笔批次（最早一笔是 3 张）；提示指出该时间和该笔；什么都不变。
   **When** 把 L1 的张数从 2 改为 1（净额不变）
   **Then** 保存成功：C1 改为平掉 L1 和 L2（1 + 1 = 2 张），冻结变动仍为 `−40,000.00`，已实现盈亏变为 `+817.40`；现金汇总 80,817.40 / 0.00 / 80,817.40；持仓页没有该合约。

5. **修改时间**
   **When** 把 L1 的成交时间改为 2026-11-06 10:00（晚于 C1）
   **Then** 被拒绝：2026-11-05 10:00 的 BTC 2 张将超过当时持仓 1 张。
   **When** 把 C1 的成交时间改为 2026-11-03 10:00（早于 L1 开仓）**Then** 被拒绝：成交时没有持仓。
   **When** 把 C1 的成交时间改为晚于当前时间 **Then** 字段校验错误，显示在成交时间下。

6. **删除开仓**
   **When** 删除 L1
   **Then** 被拒绝，提示该开仓被 2026-11-05 10:00 的 BTC 2 张平掉（删除后那笔平仓将超过当时持仓 1 张），请先修改或删除那笔平仓；什么都不变。
   **When** 删除 L2
   **Then** 保存成功：现金汇总 80,457.40 / 0.00 / 80,457.40；持仓页没有该合约；交易列表只剩 C1、L1；现金流水剩 3 条（L2 那条被删除）；按 ID 查询 L2 → 不存在。
   **And** 审计记录页第一行：操作"删除"、对象 `期权交易 #2`、改动"已删除"；展开可见删除前的完整内容（STO 1 张 AAPL 2026-12-18 200 P、360.00、2026-11-04 11:00、现金变动 +360.00、冻结变动 +20,000.00）。

7. **删除平仓（冻结恢复，受现金检查）**
   **When** 删除 C1
   **Then** 保存成功：现金汇总 81,058.70 / 60,000.00 / 21,058.70；持仓 AAPL 200 P 空头 3 张、2 个批次、可平张数 2 / 3。
   **And Given** 场景 A 之后又录入出金 50,000.00（2026-11-06 10:00）；现金汇总 30,817.40 / 20,000.00 / 10,817.40
   **When** 删除 C1
   **Then** 被拒绝，提示"2026-11-06 10:00 时可用现金将变为 −28,941.30"（31,058.70 − 60,000.00）；什么都不变。

8. **修改入金（Q24、Q19、Q41）**
   **When** 把 D1 从 80,000.00 改为 70,000.00
   **Then** 保存成功，现金汇总 70,817.40 / 20,000.00 / 50,817.40；资金页 D1 那条显示 `+70,000.00`，之后各条余额重新累计。
   **When**（从场景 A）把 D1 改为 59,000.00
   **Then** 保存成功（每个时点都不为负：2026-11-04 11:00 之后可用为 58.70；L2 不再按 Q18 重查），现金汇总 59,817.40 / 20,000.00 / 39,817.40。
   **When**（从场景 A）把 D1 改为 58,900.00
   **Then** 被拒绝，提示"2026-11-04 11:00 时可用现金将变为 −41.30"。
   **When**（从场景 A）把 D1 的时间改为 2026-11-04 12:00
   **Then** 被拒绝：2026-11-03 10:30 时可用现金将变为负数（−39,301.30）。

9. **修改入金/出金类型、删除入金/出金（Q40）**
   **Given** 入金 1,000.00（2026-11-02 10:00，#1）、入金 500.00（2026-11-03 10:00，#2，实际应为出金）
   **When** 把 #2 的类型改为出金 **Then** 现金汇总 500.00 / 0.00 / 500.00；流水 #2 显示 `−500.00`；审计改动 `类型：入金 → 出金`。
   **Given** 入金 1,000.00（2026-11-02 10:00）录了两次（#1、#2）
   **When** 删除 #2 **Then** 现金汇总 1,000.00 / 0.00 / 1,000.00，流水剩 1 条，审计记录"删除 入金 #2"。
   **When**（场景 A）删除 D1 **Then** 被拒绝：2026-11-03 10:30 时可用现金将变为负数。

10. **连带改正冻结并记入审计（Q28、Q39、Q42）**
    **Given** 入金 100.00（2026-10-26 10:00）；F1（交易 #1）= STO 1 张 F 2026-12-18 12.345 P，multiplier 1，净额 0.50（2026-11-02 10:00，冻结 12.35）；F2（交易 #2）= 同合约 STO 1 张，净额 0.50（2026-11-03 10:00，冻结 12.35）；FC（交易 #3）= BTC 2 张，净额 0.20（2026-11-05 10:00，平掉 F1+F2，释放 24.70）。现金汇总 100.80 / 0.00 / 100.80
    **When** 把 F1 的张数从 1 改为 2
    **Then** 保存成功：F1 冻结变为 24.69（12.345 × 2 = 24.69）；FC 改为只平掉 F1，冻结变动从 `−24.70` 改正为 `−24.69`，已实现盈亏变为 `+0.30`；F2 成为剩余持仓（空头 1 张，冻结 12.35）；现金汇总 100.80 / 12.35 / 88.45。
    **And** 审计记录：修改 `期权交易 #1`，改动 `张数：1 → 2`、`冻结变动：+12.35 → +24.69`；连带变化 `交易 #3 BTC 冻结变动 −24.70 → −24.69`。

11. **字段与不可改字段**
    - 修改对话框中合约、方向不可编辑；平仓不显示可编辑的 multiplier。
    - 修改时输入不合法（张数 0 / 1.5，净额 0 / 3 位小数，金额 0，备注 501 字符，时间晚于当前）→ 错误显示在对应字段下，不保存。
    - 提交与原值完全相同的内容 → 提示"没有修改"，不写审计。
    - 开仓修改为 STO call 不可能（方向、类型不可改）。

12. **审计记录页**
    **Given** 依次完成：第 1 条（修改 L2 净额）、再把 L2 备注改为"加仓"、再删除 L2
    **Then** 审计记录页按时间倒序 3 条：删除 #2；修改 #2（`备注：— → 加仓`）；修改 #2（`净额：360.00 → 365.00`）。
    **When** 在交易列表 C1 行点"历史" **Then** 审计记录页按 `期权交易 #3` 筛选，显示"暂无审计记录"；清除筛选后显示全部 3 条。
    **And** 审计记录没有修改、删除按钮。

13. **自动刷新**
    **Given** 第 1 条的修改在交易列表里完成 **Then** 不刷新页面，交易列表、持仓页、现金汇总、现金流水、审计记录都显示新值。

## 边界情况
- **删除被平仓覆盖的开仓**：拒绝，提示先处理那笔平仓（验收 6）。
- **删除平仓**：批次恢复、冻结恢复，可能让之后的现金变负 → 拒绝（验收 7）。
- **改动导致之后平仓重新匹配**：允许，被平批次和盈亏按新匹配（验收 4、10）。
- **释放冻结的取整差异**：连带改正记入同一条审计（验收 10）。
- **同一时间的记录**：修改后仍按原录入顺序排；把时间改成与另一条相同时，按两者原来的录入顺序。
- **修改到到期日之后**：平仓成交日晚于到期日 → 拒绝；开仓到期日早于成交日 → 拒绝。
- **已过期未处理的合约**：可以修改/删除其交易（只要满足上述规则）。
- **之后的 STO put 与 Q18**：只按 Q19 重查（Q41，验收 8 的 59,000.00）。
- **修改成相同值**：不保存、不审计。
- **对话框打开期间记录已被删除/改动**：以后端为准，返回不存在或校验失败。
- **周末 / 假日**：不检查（FEAT-009）。

## Out of Scope
- 修改合约或方向（删除后重录，Q43）
- 撤销 / 恢复已删除的记录；修改或删除审计记录
- 审计记录"谁"操作（Q12）
- 交易详情页（Q44 用审计记录页代替）
- 新增交易引起的系统改正的审计（Q42）
- 批量修改 / 批量删除、导入导出（FEAT-029/030）
- 股票交易、到期处理的修改（M2 再定）
- 任何券商接入

## Open Questions
无。Q24（入金/出金可修改）以及 Q40（可删除）、Q41（之后的 STO put 只按 Q19 重查）、Q42（连带改正写入同一条审计）、Q43（可改字段）、Q44（审计记录页）均已由用户确认，见上方"已定的口径"和 backlog。

**API**（详见 `docs/api/api-contract.md` 的 FEAT-005 小节）

**设计决定**
- 修改保留录入顺序：交易 id 和流水 id 都不变，只更新内容；同一时间的记录仍按原 id 先后排
- 检查：交易修改/删除重放整个合约（被修改的那笔先报，否则报第一个违规的交易），再重放整个现金流水（第一个为负的时点）。现有历史本身总是合法的，所以任何违规都由这次改动引起
- **Q18 只在必要时重查**：被修改的 STO put 只有在张数、multiplier 或成交时间变了时才按 Q18 检查。只改净额或备注时，担保和"本笔之前的可用现金"都不变，不重查——否则在先改小较早的入金（Q41 允许）后，连改这笔的备注都会被拒绝。见 Open issues
- 删除一笔被之后平仓平掉、且那笔平仓因此违规的开仓，提示"该开仓被 … 平掉（删除后那笔平仓将…），请先修改或删除那笔平仓"；如果删除后那笔平仓按 FIFO 仍合法（改为平掉别的批次），则允许删除
- 审计 `changes` 比较可改字段，外加系统重算的 `frozenChange`（验收 10）；不单独列 `cashChange`（由方向和净额决定），所以改净额只出现一行"净额"（验收 1）
- 审计 `summary` 取修改前的内容（删除时就是被删除的记录）
- 连带改正只记录冻结变动（这是唯一会被系统改正的值）
- 已有平仓保存了自己的 multiplier；修改开仓的 multiplier 使之后的平仓与持仓 multiplier 不一致时拒绝（`MULTIPLIER_MISMATCH`），不会连带改平仓的 multiplier
- `PUT` 是整体替换可改字段：`note` / `remark` 不传等于清空；开仓 `multiplier` 不传等于不改

**已知限制**
- 每次修改/删除加载该合约全部交易和全部现金流水重放（数据量小）
- 审计 JSON 存在 `VARCHAR(10000)` 中（一条记录约 1–2 KB）

**Open issues**
- 上面"Q18 只在必要时重查"是对 Q41 的解读：Q41 原文是"被修改的那笔交易本身按 Q18 检查"，没有说只改备注时是否也要查。请 PM / 用户确认
