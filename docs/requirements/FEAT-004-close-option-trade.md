## 背景 / 用户故事
作为一个期权交易者，我想要把在券商平掉的期权仓位（买入平仓 BTC、卖出平仓 STC）记进系统，只填含手续费的净额，系统按 FIFO 找到被平掉的开仓批次，平掉空头 put 时自动释放冻结的担保现金，并告诉我这笔平仓赚了多少，以便持仓、现金和券商保持一致。

## 已定的口径（来自 backlog Open Questions）
- 只记**含手续费的净额**（Q6）：BTC = 含手续费的实付，STC = 扣除手续费后的实收；> 0，最多 2 位小数（Q17），上限与开仓相同（Q29）
- 一个合约任一时刻只能纯多或纯空（Q7）：BTC 只能平空头，STC 只能平多头
- 成交时间按美东录入，默认当前时间，存 UTC，不得晚于当前时间（Q14）
- 现金不能为负；补录按时间重放，之后每个时点总现金和可用现金都不能为负；同一时间按录入顺序（Q13、Q19）
- **BTC 平空头 put：先释放被平批次的冻结现金，再检查现金**（Q20）。例：总现金 20,349.35、冻结 20,000.00、可用 349.35，BTC 1 张实付 500.00 → 允许，平仓后 19,849.35 / 0.00 / 19,849.35
- **不允许部分平仓一笔开仓（Q21，新规则，取代原"按张数比例分摊"提议，也暂时取代 Q6 中"部分平仓按比例分摊"和项目规则里"部分平仓"的边界情况）**：
  - 每笔开仓（批次）只能一次整笔平掉
  - 平仓仍按 FIFO：一笔平仓的张数必须**正好等于该合约最早的 1 笔或连续多笔整批次的张数之和**
  - 例：批次 A（11-03，2 张）、B（11-04，1 张）：平 2 张 → 平掉 A ✓；平 3 张 → 平掉 A 和 B ✓；平 1 张 → 拒绝，提示"必须一次平掉整笔开仓，最早一笔是 2 张"
  - 一笔平仓覆盖多个批次时，已实现盈亏按**这一笔平仓整体**计算，不做任何分摊和舍入：空头 = 被平批次开仓净额之和 − 平仓实付；多头 = 平仓实收 − 被平批次开仓净额之和
  - 部分平仓以后可以作为单独需求再做
- 补录的交易不能让之后已有的交易违规（Q27 的同一思路，扩展到平仓）
- 持仓、批次、冻结合计按 FEAT-003 的规则显示

- 到期日当天（美东）任何时刻都允许平仓，成交日晚于到期日才拒绝；16:00 之后是否禁止留给 M2 的 Q10（Q36）
- 平仓有两个入口：持仓页每行的"平仓"按钮，以及原"录入开仓"页改为"录入交易"并放开 BTC / STC（用于补录已过期合约在到期日或之前的平仓）（Q37）
- 平仓成功的确认信息里显示被平掉的批次和本笔已实现盈亏（后端计算）；"已平仓记录"列表和统计仍在 FEAT-006（Q38）
- 补录平仓改变了之后已有平仓匹配的批次时允许，之后的平仓按新的 FIFO 匹配重新计算释放的冻结和已实现盈亏；之后任一笔因此违规则拒绝补录（Q39）

## 需要的数据和操作（给 backend）

### 一笔平仓交易需要保存的数据
| 字段 | 说明 / 规则 |
|------|-------------|
| 合约 | 标的、到期日、行权价、Call/Put；规则同 FEAT-001（标的规范化、行权价按数值比较） |
| 方向 | BTC 或 STC |
| 张数 | 正整数，≤ 100,000；还要满足下面的"整笔批次"规则 |
| 净额 | 必填，> 0，最多 2 位小数，≤ 9,999,999,999,999.99。BTC = 含手续费实付，STC = 扣手续费实收 |
| 成交时间 | 美东日期 + 时刻，存 UTC；不得晚于当前时间；成交时间的**美东日期不得晚于到期日**（到期日当天任何时刻都可以，Q36） |
| multiplier | 用户不填，取该合约当时持仓的 multiplier |
| 备注 | 可选，最多 500 字符 |

平仓与开仓存放在同一个交易记录里（FEAT-002 列表和按 ID 查询都能查到）。

### 操作：新增一笔平仓
保存前按顺序检查，任一失败就整笔拒绝、不保存任何东西，返回能直接给用户看的中文原因（含具体数字）：

1. **字段校验**：按上表。成交日晚于到期日时提示类似"到期日（2026-11-06）之后不能平仓"。
2. **有可平的持仓、方向正确（Q7）**：在本笔成交时点（同一时间的已有交易排在本笔之前）该合约必须有持仓，且 BTC 对应空头、STC 对应多头。
   - 没有持仓：如"该合约（AAPL 2026-12-18 200 P）在成交时没有持仓，无法平仓"
   - 方向不对：如"该合约在成交时为多头持仓（1 张），应使用 Sell to Close（STC）"
3. **张数（Q21）**：
   - 超过当时持仓：如"平仓 4 张超过当时持仓 3 张"
   - 不是最早若干笔整批次之和：如"必须一次平掉整笔开仓：最早一笔是 2 张，可平 2 张或 3 张"（列出当时所有允许的张数）
4. **补录不能让之后的交易违规（Q27 思路）**：把本笔按成交时间插入后，从插入点起该合约的每一笔已有交易都要按新的持仓和 FIFO 批次重新检查；之后任一笔平仓变成"没有持仓 / 方向不对 / 超过持仓 / 不是整笔批次"就拒绝，提示是哪个时间的哪笔交易。之后的已有开仓按 FEAT-001 的 Q7/Q23 检查（平仓只会让持仓变少，通常不会出问题）。
5. **现金（Q13、Q19、Q20）**：
   - BTC：现金 −净额；冻结 −被平批次冻结之和（空头 put；空头 call 在 M1 不存在，为 0）。**同一时点先释放冻结再扣现金**，要求平仓后总现金 ≥ 0、可用现金 ≥ 0；然后按 Q19 重放，之后每个时点也都不能为负。
   - STC：现金 +净额，冻结不变（多头没有冻结）。只增加现金，不会造成不足。
   - 现金不足时提示包含需要的金额、释放的冻结和可用现金，如"可用现金不足：需要 20,349.36，可用 349.35 + 释放冻结 20,000.00 = 20,349.35"。

保存成功后的效果：
- 被平掉的批次从持仓中消失（剩余张数为 0）；合约净张数为 0 时持仓消失。之后同一合约可以重新开仓，方向和 multiplier 都可以与之前不同。
- 现金流水新增一条（来源类型"期权平仓"）：时间 = 成交时间，金额 = −净额（BTC）或 +净额（STC），冻结变动 = −释放金额（BTC 平空头 put）或 0，说明如 `BTC 2 张 AAPL 2026-12-18 200 P`（multiplier ≠ 100 时同 FEAT-001 加注），备注 = 交易备注。
- 本笔的已实现盈亏（Q21 新规则）：空头 = 被平批次开仓净额之和 − BTC 净额；多头 = STC 净额 − 被平批次开仓净额之和。只由后端计算。
- 补录的平仓改变了之后已有平仓匹配的批次时（Q39），之后那些平仓的释放冻结和已实现盈亏按新的匹配计算，现金汇总和流水反映新结果。

### 查询
- 按 ID 查询一笔平仓：返回与开仓相同的字段（含现金变动、冻结变动），另外返回**被平掉的批次**（每个批次的开仓交易 ID、开仓时间、张数、开仓净额）和**本笔已实现盈亏**。开仓交易的这两项为空。
- 交易列表（FEAT-002）：平仓自动出现，方向筛选 BTC / STC 生效；现金变动和冻结变动带符号。
- 持仓（FEAT-003）：按 FIFO 扣掉被平批次后显示；冻结合计随之减少。另外为每个持仓返回**当前可平的张数**（最早 1 笔、最早 2 笔……整批次的累计张数，如 `[2, 3]`），供平仓按钮使用，前端不自己计算；以及该持仓当前**是否可以平仓**（今天 ≤ 到期日）。

## 页面与交互（给 frontend）

### 入口 1：持仓页的"平仓"按钮
- FEAT-003 持仓页每行加"平仓"按钮，**只在今天（美东）≤ 到期日时显示**（"今天到期"的也显示；"已过期 N 天"的不显示）。
- 点击后打开平仓表单（对话框或单独页面均可），预填且不可改：合约、方向（空头 → `BTC（买入平仓）`，多头 → `STC（卖出平仓）`）、multiplier（仅显示）。
- 张数：从后端给的"可平张数"中选择（如 2 / 3），默认最小的那个；旁边提示"必须整笔平掉开仓批次（FIFO）"。
- 净额：标签随方向变化——BTC "实付总额（含手续费）"，STC "实收净额（已扣手续费）"。
- 成交时间：默认当前美东时间，注明"美东时间"，可改（补录）。
- 备注：可选。
- 表单附近显示当前现金汇总（复用 FEAT-007 的组件）。

### 入口 2：原"录入开仓"页放开平仓（Q37）
- 页面改名为"录入交易"（导航文字同步改），方向增加 BTC、STC 两个选项；选 BTC / STC 时隐藏或禁用 multiplier（由后端取持仓的 multiplier）。净额标签同上。
- 用途：补录已经过了到期日、但平仓发生在到期日当天或之前的交易（这时持仓页不显示平仓按钮）。

### 提交与结果
- 前端只做格式校验（必填、正整数、> 0、小数位数、时间不晚于当前），不判断持仓、批次、现金。
- 后端拒绝时显示原因原文，保留已填内容。
- 成功后显示确认信息：合约、方向、张数、净额、成交时间（美东）、现金变动（如 `−241.30`）、冻结变动（如 `−40,000.00`，0 显示 `—`）、**被平掉的批次**（每行：开仓时间、方向、张数、开仓净额）、**本笔已实现盈亏**（如 `+457.40`，正绿负红）。
- 成功后现金汇总、持仓页、交易列表无需手动刷新即显示新数据。
- 资金页流水：来源类型"期权平仓"显示中文，说明列显示后端说明。
- 金额统一用格式化 util。

## 验收标准
所有场景从空库开始，当前时间不早于 2026-11-11 10:00（美东；后端测试可把时钟固定为此时间，E2E 用真实时钟）。"现金汇总"= 总现金 / 冻结 / 可用。

**场景 A 数据**：入金 80,000.00（2026-10-26 10:00）；L1 = STO 2 张 AAPL 2026-12-18 200 P，净额 698.70（2026-11-03 10:30）；L2 = STO 1 张 AAPL 2026-12-18 200 P，净额 360.00（2026-11-04 11:00）。现金汇总 81,058.70 / 60,000.00 / 21,058.70；持仓 AAPL 200 P 空头 3 张，2 个批次，可平张数 2 / 3。

1. **平掉最早一笔整批次（BTC，释放冻结）**
   **Given** 场景 A
   **When** 录入 BTC 2 张 AAPL 2026-12-18 200 P，净额 241.30，成交时间 2026-11-05 10:00
   **Then** 保存成功；确认信息：`AAPL 2026-12-18 200 P`、`BTC（买入平仓）`、2 张、241.30、`2026-11-05 10:00（美东）`、现金变动 `−241.30`、冻结变动 `−40,000.00`、被平批次 `2026-11-03 10:30 STO 2 张 +698.70`、已实现盈亏 `+457.40`（698.70 − 241.30）。
   **And** 现金汇总 80,817.40 / 20,000.00 / 60,817.40；现金流水新增一条"期权平仓" `−241.30`、冻结变动 `−40,000.00`、说明 `BTC 2 张 AAPL 2026-12-18 200 P`。
   **And** 持仓页：AAPL 200 P 空头 1 张、`+360.00`、每张 `+360.00`、冻结 `20,000.00`、批次数 1（`2026-11-04 11:00`、`1 / 1`、`+360.00`），可平张数 1；顶部冻结合计 `20,000.00`。
   **And** 交易列表第一行：`2026-11-05 10:00`、`BTC（买入平仓）`、`AAPL 2026-12-18 200 P`、`2`、`−241.30`、冻结变动 `−40,000.00`；方向只选 BTC 时只显示这一笔。

2. **不能部分平仓一笔开仓（Q21）**
   **Given** 场景 A
   **When** 录入 BTC 1 张，净额 120.65，成交时间 2026-11-05 10:00
   **Then** 被拒绝，提示"必须一次平掉整笔开仓：最早一笔是 2 张，可平 2 张或 3 张"；已填内容保留；没有新增交易、流水，现金汇总和持仓不变。

3. **一笔平仓覆盖多个批次，盈亏按整笔计算**
   **Given** 场景 A
   **When** 录入 BTC 3 张，净额 400.00，成交时间 2026-11-05 10:00
   **Then** 保存成功；冻结变动 `−60,000.00`；被平批次两行（L1 2 张 +698.70、L2 1 张 +360.00）；已实现盈亏 `+658.70`（698.70 + 360.00 − 400.00）；现金汇总 80,658.70 / 0.00 / 80,658.70；持仓页不再有 AAPL 200 P，`共 0 个持仓`，冻结合计 `0.00`。

4. **超过持仓、方向不对、没有持仓**
   **Given** 场景 A
   - **When** BTC 4 张 **Then** 被拒绝，提示"平仓 4 张超过当时持仓 3 张"。
   - **When** STC 2 张 **Then** 被拒绝，提示该合约为空头持仓，应使用 Buy to Close（BTC）。
   - **When** BTC 1 张 AAPL 2026-12-18 **205** P **Then** 被拒绝，提示该合约没有持仓。
   - **When** BTC 2 张 AAPL 2026-12-18 200 P，成交时间 2026-11-03 10:00（早于 L1 开仓）**Then** 被拒绝，提示成交时没有持仓。
   以上每项都不保存、不改变现金和持仓。

5. **全部平掉后重新开仓（可换方向）**
   **Given** 场景 A，已按第 1 条平掉 L1
   **When** 录入 BTC 1 张，净额 150.00，成交时间 2026-11-06 10:00
   **Then** 平掉 L2，已实现盈亏 `+210.00`；现金汇总 80,667.40 / 0.00 / 80,667.40；持仓中没有该合约。
   **And When** 录入 BTO 1 张 AAPL 2026-12-18 200 P，净额 300.00，成交时间 2026-11-06 11:00 **Then** 保存成功（之前已无持仓，不冲突），持仓页出现多头 1 张、`−300.00`；现金汇总 80,367.40 / 0.00 / 80,367.40。

6. **先释放冻结再检查现金（Q20）**
   **Given** 入金 20,000.00（2026-10-26 10:00）；STO 1 张 AAPL 2026-12-18 200 P，净额 349.35（2026-11-03 10:30）；现金汇总 20,349.35 / 20,000.00 / 349.35
   **When** BTC 1 张，净额 500.00（2026-11-05 10:00）**Then** 保存成功，现金汇总 19,849.35 / 0.00 / 19,849.35，已实现盈亏 `−150.65`。
   **And Given** 同样的初始数据 **When** BTC 1 张，净额 20,349.36 **Then** 被拒绝（平仓后总现金会是 −0.01），提示中包含需要 20,349.36、可用 349.35、释放冻结 20,000.00。
   **And When** 净额 20,349.35 **Then** 保存成功，现金汇总 0.00 / 0.00 / 0.00，已实现盈亏 `−20,000.00`。

7. **多头 call 卖出平仓（STC）**
   **Given** 入金 10,000.00（2026-10-26 10:00）；BTO 1 张 AAPL 2026-12-18 210 C，净额 512.65（2026-11-03 10:30）；现金汇总 9,487.35 / 0.00 / 9,487.35
   **When** STC 1 张，净额 830.00（2026-11-05 10:00）
   **Then** 保存成功；现金变动 `+830.00`，冻结变动 `—`；已实现盈亏 `+317.35`；现金汇总 10,317.35 / 0.00 / 10,317.35；持仓消失；流水说明 `STC 1 张 AAPL 2026-12-18 210 C`。
   **And**（另起同样初始数据）**When** BTC 1 张 **Then** 被拒绝，提示应使用 Sell to Close（STC）。

8. **到期日之后不能平仓；到期日当天可以（Q36）**
   **Given** 入金 50,000.00（2026-10-26 10:00）；STO 1 张 TSLA 2026-11-06 250 P，净额 300.00（2026-11-02 10:00）；现金汇总 50,300.00 / 25,000.00 / 25,300.00
   **When** 在持仓页查看 **Then** TSLA 行显示"已过期 N 天"，**没有**"平仓"按钮。
   **When** 通过录入交易页录入 BTC 1 张，净额 10.00，成交时间 2026-11-09 10:00 **Then** 被拒绝，提示到期日（2026-11-06）之后不能平仓。
   **When** 同样录入但成交时间 2026-11-06 16:30 **Then** 保存成功（到期日当天任何时刻都允许），已实现盈亏 `+290.00`，现金汇总 50,290.00 / 0.00 / 50,290.00，TSLA 从持仓页消失。

9. **持仓页的"平仓"按钮**
   **Given** 场景 A
   **When** 在持仓页点击 AAPL 2026-12-18 200 P 行的"平仓"
   **Then** 平仓表单预填 合约 `AAPL 2026-12-18 200 P`、方向 `BTC（买入平仓）`（不可改）；张数可选 2 或 3，默认 2；净额标签为"实付总额（含手续费）"；成交时间默认当前美东时间。
   **When** 净额填 241.30、成交时间改为 2026-11-05 10:00 提交 **Then** 结果同第 1 条；不刷新页面，持仓行变为 1 张、可平张数只有 1，现金汇总和交易列表同步更新。
   **And Given** 一个今天到期的多头持仓（E2E：到期日取运行当天的美东日期，如 BTO 1 张 SPY <今天> 600 C 净额 50.00，成交 2026-11-02 10:00）**Then** 该行显示"平仓"按钮，方向预填 `STC（卖出平仓）`。

10. **补录平仓不能让之后的平仓违规；合法补录时之后的平仓重新匹配（Q39）**
    **Given** 入金 80,000.00（2026-10-26 10:00）；L1 = STO 1 张 AAPL 2026-12-18 200 P 净额 349.35（2026-11-03 10:30）；L2 = STO 1 张同合约 净额 360.00（2026-11-04 11:00）；已有 BTC 1 张 净额 100.00（2026-11-06 10:00，平掉 L1，已实现盈亏 +249.35）。现金汇总 80,609.35 / 20,000.00 / 60,609.35
    **When** 补录 BTC 2 张，净额 200.00，成交时间 2026-11-05 10:00
    **Then** 被拒绝：插入后 2026-11-06 10:00 的 BTC 1 张将没有持仓可平；提示指出该时间和该笔；不保存。
    **When** 补录 BTC 1 张，净额 120.00，成交时间 2026-11-05 10:00

    - 张数 0、−1、1.5；净额 0、−10.00、241.305
    - 成交时间晚于当前时间

## 边界情况
- **一笔平仓覆盖多个批次**：盈亏按整笔算（验收 3）。
- **同一合约多次开平仓**：全部平掉后可以重新开仓，方向和 multiplier 都可以变（验收 5）。
- **不允许部分平仓一笔开仓**：一笔 2 张的开仓不能只平 1 张（验收 2）。如果实际在券商只平了一部分，本系统目前无法记录，需等以后的"部分平仓"需求。
- **同一时间的开仓和平仓**：同一时间按录入顺序；先录入的开仓才能被同一时间后录入的平仓平掉。
- **到期日当天**：任何时刻都可以平仓（Q36）；到期日之后拒绝，过期持仓等 M2 处理（作废/指派/行权）。
- **补录早于已有交易的平仓**：之后的交易重新检查（验收 10）；合法时之后的平仓重新匹配批次（Q39）。
- **释放冻结后可用现金**：先释放再检查（验收 6）；释放额 = 被平批次冻结之和（FEAT-003 的批次冻结，含 Q28 的向上取整）。
- **multiplier ≠ 100**：取持仓的 multiplier（验收 11）。
- **周末 / 假日**：不检查交易日（FEAT-009）。
- **标的拆股**：不在本需求（FEAT-028）。

## Out of Scope
- 部分平仓一笔开仓（Q21 新规则下不允许；以后可单独立需求）
- 已实现盈亏列表 / 已平仓记录 / 汇总（FEAT-006、FEAT-008）；本需求只在确认信息和按 ID 查询里给出本笔盈亏
- 修改/删除交易（FEAT-005）
- 到期作废、被指派、行权及其按钮（FEAT-012/013/014）
- 卖出 call、股票（FEAT-011）；多腿/展期（FEAT-022/024）
- 交易日历校验（FEAT-009）
- 任何券商接入

**设计决定**
- **平仓用单独的接口**，没有放开开仓接口：两者请求字段不同（平仓没有 multiplier），也不破坏 FEAT-001 契约（开仓接口拒绝 BTC/STC，QA 有测试）
- **开仓和平仓共用一个合约重放（`ContractReplay`）**：每次写入都把新交易插入该合约全部交易重放，检查新交易和**之后每一笔已有交易**（Q27/Q39）。所以补录开仓也会检查之后的平仓。例：已有 11-05 平 2 张，补录 11-02 的 1 张开仓，会让那笔平仓不再是整笔批次 → 拒绝（`CLOSE_NOT_WHOLE_LOTS`）
- **Q39 的存储选择**：被平批次和已实现盈亏不落库，读取时重放得出，补录后自动按新匹配。释放的冻结存在流水的 `frozen_change`（现金重放只看流水）；补录导致之后某笔平仓的释放额变化时，在同一事务里改正那条流水的 `frozen_change`，现金检查用改正后的值。同一合约的批次单价相同，所以只有 Q28 的取整差异会触发（例：12.345 × 1 的 2 张批次冻结 24.69，两笔 1 张批次合计 24.70），测试覆盖了这种情况。流水的现金金额永远不变
- 检查顺序：平仓按需求的 1→5；"之后的交易违规"返回那笔违规种类对应的错误码，message 指出时间、方向、张数。开仓保持 FEAT-001 的顺序（多空冲突以及之后的平仓违规 → Q16 → multiplier → 现金）
- 现金不足（BTC，本笔时点）文案：`可用现金不足：需要 X，可用 A + 释放冻结 R = S`；之后某时点变负时沿用 FEAT-007 格式
- 到期日之后平仓：错误挂在 `tradedAtLocal`
- 已实现盈亏 = 被平批次开仓净额（带现金方向符号）之和 + 本笔现金变动，正好等于需求里空头、多头两个公式
