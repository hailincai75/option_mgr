# FEAT-001: 录入开仓期权交易（BTO / STO）

- **Status:** Approved
- **Priority:** P0
- **Depends on:** FEAT-007（资金账户：入金/出金、总现金/冻结/可用现金与流水）——必须先做
- **Scope:**
  - [ ] Backend: Done

## 背景 / 用户故事
作为一个期权交易者，我想要把在券商成交的**开仓**期权交易（买入开仓 BTO、卖出开仓 STO）记进系统，只填一个含手续费的净额，并且系统帮我检查现金够不够、卖 put 时自动冻结担保现金，以便我的账上现金和券商一致、永远不会出现透支。

平仓（BTC / STC）不在本需求，见 FEAT-004。

## 已定的口径（来自 backlog Open Questions）
- 单账户、只有 USD（Q3、Q4）
- 只记**含手续费的净额**，不记成交价、不记手续费（Q6）
  - STO：扣除手续费后的实收。例：卖出 2 张 @3.50，手续费 1.30 → 净额 698.70
  - BTO：含手续费的实付。例：买入 1 张 @5.12，手续费 0.65 → 净额 512.65
- 一个合约任一时刻只能纯多或纯空（Q7）
- 现金不能为负；可用现金 = 总现金 − 冻结现金；STO put 冻结 行权价 × multiplier × 张数（Q13）
- 成交时间按美东时间录入，默认当前时间，存 UTC（Q14）
- M1 拒绝 STO call（Q16）
- 净额 > 0，最多 2 位小数（Q17）
- STO put 担保检查不把本笔权利金算进可用现金（Q18）
- 补录历史记录按时间重放，之后每个时点现金都不能为负；同一时间按录入顺序（Q19）
- 同一合约有未平仓持仓时 multiplier 必须一致（Q23）
- 格式限制：行权价最多 3 位小数；标的 1–10 位字母/数字/点；备注最多 500 字符（Q25）

## 需要的数据和操作（给 backend）

### 一笔开仓交易需要保存的数据
| 字段 | 说明 / 规则 |
|------|-------------|
| 标的 | 必填。去掉首尾空格、转大写；只允许字母、数字和 `.`（如 `BRK.B`），长度 1–10 |
| 到期日 | 必填，日期（无时间）。不得早于成交时间所在的美东日期；可以等于（0DTE） |
| 行权价 | 必填，> 0，最多 3 位小数（如 12.5、200） |
| 类型 | Call 或 Put |
| 方向 | 本需求只允许 BTO、STO |
| 张数 | 必填，正整数 |
| 净额 | 必填，> 0，最多 2 位小数（Q17）。用户只填正数，方向决定现金流入还是流出 |
| 成交时间 | 必填，用户提供的是美东时间的日期 + 时刻；保存为 UTC 时间点；不得晚于当前时间 |
| multiplier | 必填，正整数，默认 100 |
| 备注 | 可选，最多 500 字符 |

- 合约唯一标识 = 标的 + 到期日 + 行权价 + Call/Put。同一合约多次开仓保存为多笔独立交易（为 FIFO 批次做准备）。
- 金额（净额、行权价、冻结金额）全部精确十进制，不允许二进制浮点误差。

### 操作：新增一笔开仓交易
保存前按顺序检查，任一失败就整笔拒绝、不保存任何东西，并返回能直接给用户看的原因（含具体数字）：

1. **字段校验**：按上表。
2. **多空冲突（Q7）**：该合约在成交时间点已有空头持仓时不能 BTO，已有多头持仓时不能 STO。提示用户使用 Buy to Close / Sell to Close。
3. **STO call（Q16）**：M1 拒绝所有 STO call，提示"需要股票持仓功能（FEAT-011）后才能卖出 call"。
4. **multiplier 一致（Q23）**：该合约已有未平仓持仓时，新开仓的 multiplier 必须与之相同。
5. **现金检查（Q13、Q18、Q19）**：
   - BTO：需要的现金 = 净额。
   - STO put：需要的担保 = 行权价 × multiplier × 张数，要求**本笔录入前**的可用现金 ≥ 担保金额（本笔收到的权利金不算进去，Q18）。
   - 按成交时间把本笔插入到已有的现金记录（入金、出金、其它交易）中按时间顺序重放：插入后**从本笔成交时间起的每个时点**，总现金和可用现金都不能为负（Q19）。同一时间点的记录按录入顺序排列。
   - 现金不足时提示"需要 X，可用 Y"（Y 为该时点的可用现金）。

保存成功后的效果：
- BTO：总现金减少净额；冻结不变。
- STO put：总现金增加净额；冻结增加 行权价 × multiplier × 张数。
- 每笔交易在 FEAT-007 的现金流水中产生一条记录：时间 = 成交时间，金额 = +净额（STO）或 −净额（BTO），说明能看出是哪笔交易（方向、标的、到期日、行权价、C/P、张数）。
- 冻结金额本需求内不会被释放（释放在 FEAT-004 平仓、M2 到期/指派中做）。

### 操作：查询
- 能按 ID 查回刚保存的交易，返回所有字段；成交时间同时能让前端显示成美东时间。
- 现金汇总（总现金 / 冻结 / 可用）和流水沿用 FEAT-007，本需求只是让交易的影响反映进去。

## 页面与交互（给 frontend）
- 一个"录入开仓交易"的表单（新页面或对话框均可，入口放在显眼位置，如顶部导航或首页按钮）。
- 表单字段：标的、到期日（日期选择）、行权价、Call/Put、方向（BTO / STO 两个选项）、张数、净额、成交时间、multiplier（默认 100）、备注。
  - 净额的标签随方向变化：选 STO 时显示"实收净额（已扣手续费）"，选 BTO 时显示"实付总额（含手续费）"。
  - 成交时间默认填入当前美东时间，旁边注明"美东时间"。
  - 表单上方或旁边显示当前 总现金 / 冻结 / 可用现金（数据来自 FEAT-007）。
  - 前端不计算担保金额、不预测提交后的现金（业务计算只在后端）。
- 提交：
  - 前端做基本格式校验（必填、正数、小数位数），错误显示在对应字段下。
  - 后端拒绝时，在表单上显示后端返回的原因原文，**保留用户已填的所有内容**。
  - 成功时显示确认信息：合约（如 `AAPL 2026-12-18 200 P`）、方向、张数、净额、成交时间（美东），并刷新现金汇总；表单可清空以便继续录入下一笔。
- 金额统一用项目的格式化 util 显示：2 位小数、千分位，如 `30,349.35`；流出显示负号。

## 验收标准
除特别说明，以下场景都从空库开始，入金/出金通过 FEAT-007 录入；"现金汇总"指页面上的 总现金 / 冻结 / 可用现金。

1. **STO put 成功并冻结**
   **Given** 2026-11-02 10:00（美东）入金 30,000.00
   **When** 录入 STO 1 张 AAPL 2026-12-18 200 P，净额 349.35，成交时间 2026-11-10 10:30（美东），multiplier 100
   **Then** 保存成功；该交易的成交时间存为 `2026-11-10T15:30:00Z`；现金汇总为 总现金 30,349.35、冻结 20,000.00、可用 10,349.35；现金流水新增一条 +349.35，说明中含 STO、AAPL、2026-12-18、200、P、1 张。

2. **多张 + 小数行权价**
   **Given** 入金 5,000.00
   **When** 录入 STO 2 张 F 2026-12-18 12.5 P，净额 48.70
   **Then** 现金汇总为 总现金 5,048.70、冻结 2,500.00、可用 2,548.70。

3. **BTO 成功**
   **Given** 入金 30,000.00
   **When** 录入 BTO 1 张 AAPL 2026-12-18 210 C，净额 512.65
   **Then** 现金汇总为 总现金 29,487.35、冻结 0.00、可用 29,487.35；现金流水新增一条 −512.65。

4. **BTO 可用现金不足**
   **Given** 入金 500.00
   **When** 录入 BTO 1 张 AAPL 2026-12-18 210 C，净额 512.65
   **Then** 被拒绝，表单显示"可用现金不足：需要 512.65，可用 500.00"，已填内容保留；现金汇总仍为 500.00 / 0.00 / 500.00；没有新增交易和流水。
   **And When** 把净额改为 500.00 再提交 **Then** 保存成功，可用现金 0.00。

5. **冻结的现金不能用于买入**
   **Given** 入金 20,500.00，并已录入 STO 1 张 AAPL 2026-12-18 200 P 净额 349.35（现金汇总 20,849.35 / 20,000.00 / 849.35）
   **When** 录入 BTO 1 张 MSFT 2026-12-18 450 C，净额 900.00
   **Then** 被拒绝，提示"需要 900.00，可用 849.35"。
   **And When** 净额改为 849.35 **Then** 保存成功，现金汇总为 20,000.00 / 20,000.00 / 0.00。

6. **STO put 担保不足（Q18：权利金不算进可用）**
   **Given** 入金 19,999.99
   **When** 录入 STO 1 张 AAPL 2026-12-18 200 P，净额 349.35
   **Then** 被拒绝，提示"可用现金不足以担保卖出 put：需要 20,000.00，可用 19,999.99"；没有新增交易、流水和冻结。
   **And Given** 入金恰好 20,000.00 **Then** 同样的录入成功，现金汇总为 20,349.35 / 20,000.00 / 349.35。

7. **同一合约多次开仓**
   **Given** 入金 50,000.00，已录入 STO 1 张 AAPL 2026-12-18 200 P 净额 349.35（成交 2026-11-10 10:30）
   **When** 再录入 STO 1 张 AAPL 2026-12-18 200 P 净额 360.00（成交 2026-11-11 11:00）
   **Then** 保存成功，系统中有 2 笔独立交易；现金汇总为 总现金 50,709.35、冻结 40,000.00、可用 10,709.35。

8. **多空冲突（Q7）**
   **Given** 入金 30,000.00，已有空头 1 张 AAPL 2026-12-18 200 P
   **When** 录入 BTO 1 张 AAPL 2026-12-18 200 P，净额 300.00
   **Then** 被拒绝，提示该合约当前为空头持仓，应使用 Buy to Close 平仓；现金不变。
   **And When** 录入 BTO 1 张 AAPL 2026-12-18 **205** P，净额 300.00 **Then** 保存成功（不同合约不冲突）。
   **And Given** 已有多头 1 张 AAPL 2026-12-18 210 C **When** 录入 STO 1 张 AAPL 2026-12-18 210 C **Then** 被拒绝，提示应使用 Sell to Close。

9. **STO call（Q16）**
   **Given** 入金 100,000.00
   **When** 录入 STO 1 张 AAPL 2026-12-18 250 C，净额 120.00
   **Then** 被拒绝，提示需要股票持仓功能后才能卖出 call；没有新增交易和流水。

10. **标的规范化**
    **Given** 入金 30,000.00，已有空头 1 张 AAPL 2026-12-18 200 P
    **When** 录入 BTO，标的填 ` aapl `，其余同该合约
    **Then** 按 AAPL 识别为同一合约，按第 8 条被拒绝。另录入 STO 1 张 ` msft ` 2026-12-18 400 P（入金足够时）→ 保存后标的显示为 `MSFT`。

11. **成交时间（美东 ↔ UTC，含夏令时）**
    **When** 打开录入表单 **Then** 成交时间默认是当前美东时间（例：当前为 UTC 2026-11-10 14:45 → 显示 2026-11-10 09:45）。
    **When** 录入成交时间 2026-07-15 10:30（美东，夏令时）**Then** 存为 `2026-07-15T14:30:00Z`，确认信息和查询结果显示 2026-07-15 10:30（美东）。
    **When** 录入成交时间 2026-11-10 10:30（美东，标准时间）**Then** 存为 `2026-11-10T15:30:00Z`。

12. **字段校验**（每一项单独提交都应被拒绝、不保存，错误显示在对应字段）
    - 张数为 0、−1、1.5
    - 净额为 0、−10.00、349.355（3 位小数）
    - 行权价为 0、−5、200.1234（4 位小数）
    - multiplier 为 0、10.5
    - 标的为空、`AA PL`、`$AAPL`、超过 10 个字符
    - 成交时间晚于当前时间（例：当前 2026-11-10 09:45 美东，填 2026-11-10 10:00）
    - 到期日早于成交日：成交 2026-11-10，到期日 2026-11-09
    - 备注超过 500 字符
    **And** 到期日等于成交日（成交 2026-12-18 10:00 美东，到期日 2026-12-18）应允许保存（0DTE）。

13. **补录历史交易的现金检查（Q19：按时间重放）**
    **Given** 入金 10,000.00（2026-11-02 10:00）、出金 9,000.00（2026-11-05 10:00），当前现金 1,000.00
    **When** 补录 BTO 1 张 AAPL 2026-12-18 210 C，净额 1,500.00，成交时间 2026-11-03 10:00
    **Then** 被拒绝：插入后 2026-11-05 出金时现金会变成 −500.00；提示中说明在哪个时点不足。
    **When** 同样补录但净额 800.00 **Then** 保存成功，当前现金汇总为 200.00 / 0.00 / 200.00。
    **When** 补录 BTO 净额 100.00，成交时间 2026-11-01 10:00（早于第一笔入金）**Then** 被拒绝，可用 0.00。

14. **补录 STO put 影响之后的出金**
    **Given** 入金 25,000.00（2026-11-02 10:00）、出金 5,500.00（2026-11-05 10:00）
    **When** 补录 STO 1 张 AAPL 2026-12-18 200 P，净额 349.35，成交时间 2026-11-03 10:00
    **Then** 被拒绝：插入后 2026-11-05 出金时可用现金为 25,349.35 − 5,500.00 − 20,000.00 = −150.65。
    **And Given** 出金改为 4,000.00 的场景 **Then** 同样的补录成功，当前现金汇总为 21,349.35 / 20,000.00 / 1,349.35。

15. **非标准 multiplier（Q23）**
    **Given** 入金 5,000.00
    **When** 录入 STO 1 张 XYZ 2026-12-18 200 P，multiplier 10，净额 34.35
    **Then** 冻结 2,000.00，现金汇总 5,034.35 / 2,000.00 / 3,034.35。
    **And When** 再录入 STO 1 张 XYZ 2026-12-18 200 P，multiplier 100 **Then** 被拒绝，提示该合约已有持仓、multiplier 为 10。

16. **失败时保留输入、成功后刷新**
    **Given** 第 4 条的拒绝场景 **Then** 表单上所有已填字段仍保留原值。
    **Given** 第 1 条的成功场景 **Then** 页面显示确认信息 `AAPL 2026-12-18 200 P`、STO、1 张、349.35、2026-11-10 10:30（美东），现金汇总无需手动刷新即显示 30,349.35 / 20,000.00 / 10,349.35。

## 边界情况
- **同一合约多次开仓**：每次都是独立一笔，冻结累加（验收 7）。
- **到期日当天开仓（0DTE）**：允许（验收 12）。
- **补录已过期合约的历史开仓**（如今天 2026-11-10，补录 2026-10-01 开仓、到期日 2026-10-17）：只要成交日 ≤ 到期日就允许保存；该持仓保持未平仓状态，到期处理在 M2（FEAT-012/013）。
- **周末/美股假日**：到期日或成交时间落在周末/假日时 M1 不检查、不提示（FEAT-009 再做）。
- **同一成交时间的多条记录**：按录入顺序排列（Q19）。
- **可用现金恰好等于需要的金额**：允许，可用变为 0.00（验收 4、5、6）。
- **夏令时切换**：成交时间按 America/New_York 规则换算（验收 11）。夏令时切换当天不存在/重复的时刻（如 2026-03-08 02:30、2026-11-01 01:30）如何处理，由后端按 Java 时区库的默认规则处理并在 Implementation Notes 说明。
- **标的拆股**：不在本需求（FEAT-028）。
