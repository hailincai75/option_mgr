- **Status:** Verified

- **Depends on:** FEAT-011（股票）、FEAT-038（卖出 call）、FEAT-012（作废）、FEAT-013 / FEAT-041（被指派）
- **Scope:**

## 背景 / 用户故事
我只做 covered call：卖 call 时系统要确认同一账户有足够没被占用的股票，被覆盖的股票在 call 平掉、作废或被指派前不能卖出。FEAT-038 期间录入、还没有股票记录的 call 不要挡住其它操作，补录股票后自动变为已覆盖。

## 已定的口径
- Q77：卖出 call 硬性检查可用股数，不支持裸卖（规则 2）。Q78：被覆盖股票锁定（规则 3）。Q79：旧空头 call 不追溯拒绝（规则 5）。
- Q19：按 `(时间, 录入顺序)` 重放（规则 4）。Q21：覆盖按整个批次（规则 1）。Q53：只看同一账户。Q86：转入记在当天 00:00。
- Q61 / Q62：提示和标签按规则 7 更新。
- Q101：旧批次自动纳入检查（规则 5）。Q102：价差不算覆盖（规则 8）。Q103：指数 call 同样要求股票（规则 9）。

## 规则
1. **术语**（按账户、按标的）：
   - **需要股数**：一个空头 call 开仓批次 = 张数 × multiplier；整批计算，不存在"覆盖一半"的受检批次。
   - **受检批次**：FEAT-039 上线后录入的 STO call 批次（包括补录很早时间的），以及按规则 5 纳入检查的旧批次。
   - **旧批次**：上线前已保存、尚未纳入检查的 STO call 批次。
   - **被覆盖股数**(t) = 时点 t 仍未平的受检批次需要股数之和；**可用股数**(t) = 持股(t) − 被覆盖股数(t)。旧批次不占用股票。
   - 批次在平仓（BTC）、作废（记在到期日 16:00，Q63）、被指派（指派时间）时点起不再需要股票；已过期未处理的批次（Q34）仍需要。
2. **卖出 call 检查（Q77）**：新增 STO call，或修改 STO call 的张数 / 成交时间 / multiplier 时，在该笔成交时点要求 可用股数（不含本笔）≥ 本笔需要股数，否则拒绝（文案 E1）。只改净额、备注不检查。
3. **股票锁定（Q78）**：新增或修改股票卖出时，在成交时点要求 卖出股数 ≤ 可用股数，否则拒绝（文案 E2）。
4. **重放不变式（Q19）**：任何写操作（股票买入 / 卖出 / 转入的新增、修改、删除；STO call、BTC 的新增、修改、删除；作废、被指派的新增与删除）之后，从受影响时点起每个时点、每个标的都要满足 持股 ≥ 被覆盖股数，否则整笔拒绝、不写审计（文案 E3）。已平掉的受检批次在其未平期间同样约束历史。检查顺序：在原有检查（Q15 持股、Q21 整笔、Q75）之后、现金检查之前。
5. **旧批次（Q79）**：
   - 不追溯拒绝；不占用股票、不参与规则 4，所以不会挡住与它无关的操作。
   - 修改它的张数 / 成交时间 / multiplier → 按规则 2 和 4 检查，通过即成为受检批次；只改净额、备注 → 仍为旧批次。
   - **自动纳入检查（Q101）**：上线时、以及之后该账户每次保存成功后，按 `(开仓时间, 录入顺序)` 逐个检查仍未平的旧批次——把它当作受检批次后，若从开仓到现在每个时点都满足 持股 ≥ 被覆盖股数，则永久成为受检批次（锁定股票）。不满足则保持旧批次，显示"未覆盖"，并给出最早不满足的时点和当时持股。已经平掉（BTC / 作废 / 被指派）的旧批次永远是旧批次。修改 / 删除引起的纳入写进该审计的连带变化，如 `STO #5 纳入覆盖检查`；新增记录引起的不写审计（Q42）。
6. **与事件的关系**（由规则 1、4 得出）：call 被指派交出股票、批次同时不再需要，可用不变；put 被指派从指派时点起增加持股；删除 BTC / 作废 / put 被指派可能被规则 4 拒绝。
7. **文案**（`{}` 为变量；C = 0 时省略"，其中…"）：
   - **E1**：`需要 {N} 股 {标的}，可用 {A} 股（持有 {H} 股，其中 {C} 股已覆盖其它 call）`
   - **E2**：`卖出 {N} 股超过可用股数 {A} 股（持有 {H} 股，其中 {C} 股被 call 覆盖），请先平掉对应的 call`
   - **E3**：`{补录|修改|删除|被指派}后 {美东时间} 起 {标的} 不足以覆盖卖出的 call：需要 {R} 股，持有 {H} 股`（时间取最早不满足的时点）
   - **录入页提示（替换 Q61 原文）**：`卖出 call 需要同一账户有足够的可用股票覆盖：每张 = multiplier 股，可用股数 = 持股 − 已被其它卖出 call 覆盖的股数，不足时不能保存。卖出 call 不冻结现金。`
   - **持仓页标签（替换 Q62 的"未冻结"）**：受检 → `已覆盖 {N} 股`（悬停：`占用 {标的} {N} 股，平仓、作废或被指派前这些股票不能卖出`）；旧批次 → `未覆盖`（悬停：`上线前录入，未纳入覆盖检查：需要 {R} 股，当前可用 {A} 股；{时间} 时持有 {H} 股。补录该时间之前的股票后自动变为已覆盖`）。一行同时有两种批次时两个标签都显示，如 `已覆盖 100 股` `未覆盖 2 张`。
8. **价差（Q102）**：用多头 call 保护的空头 call（call 垂直价差、iron condor 的 call 腿）不算覆盖，同样要求股票。
9. **指数期权（Q103）**：指数期权（Q11）的 STO call 同样要求"股票"，即实际无法录入；用户目前不做指数期权。

## 需要的数据和操作（给 backend）
- 规则 2–5 的检查与重放，覆盖规则 4 列出的所有写操作；拒绝时返回 E1 / E2 / E3 文案和对应字段。
- 每个空头 call 批次保存"受检 / 旧批次"状态；上线迁移时把已有 STO call 批次标为旧批次并立即按规则 5 评估一次（迁移前按 Q60 备份）。
- **持仓**：股票部分每个标的增加 被覆盖股数、可用股数；空头 call 行给出 受检部分需要股数、旧批次张数与需要股数、当前可用股数、最早不满足的时点与当时持股（用于规则 7 悬停）。
- 审计：规则 5 的连带变化。其余现有数据不变。

## 页面与交互（给 frontend）
- **录入交易页**：选 STO + Call 时显示规则 7 的新提示（不弹确认、不阻止提交）；被拒时按现有方式显示后端文案。
- **持仓页期权部分**：空头 call 行冻结现金列显示规则 7 的标签，"未冻结"不再出现；空头 put 金额、多头 `—`、顶部冻结合计（Q35）不变。
- **持仓页股票部分**：在持股后面增加"被覆盖""可用"两列（整数股）。
- 股票录入 / 修改、期权修改 / 删除、作废 / 被指派删除被拒时，按现有方式显示后端文案。
- 首页、交易列表、已平仓、资金流水不变。

## 验收标准
后端测试固定时钟；E2E 换成相对日期。标的均为虚构；时间均为美东。

**场景 D**（默认账户）：入金 10,000.00（2026-11-02 10:00），按顺序：

| 编号 | 记录 | 时间 |
|------|------|------|
| S1 | 转入 IXQZ 200 股，成本 1,600.00 | 2026-11-02 |
| C1 | STO IXQZ 2026-12-18 10 C，1 张，净额 50.00 | 2026-11-03 10:00 |
| C2 | STO IXQZ 2026-12-18 11 C，1 张，净额 30.00 | 2026-11-04 10:00 |

（录 C2 前先做第 1 条的拒绝。）此后 IXQZ 持股 / 被覆盖 / 可用 = **200 / 200 / 0**。

**场景 L**（"旧账户"，测试预置为上线前录入）：入金 2,000.00（2026-11-02 10:00）；L1 = STO IXQZ 2026-12-18 10 C，2 张，净额 90.00（2026-11-03 10:00）；无股票。

1. **卖出 call 检查（Q77）**：录 C2 前，STO 2 张 IXQZ 2026-12-18 11 C（2026-11-04 10:00）→ 拒绝 `需要 200 股 IXQZ，可用 100 股（持有 200 股，其中 100 股已覆盖其它 call）`；录 C2（1 张）→ 成功。持仓页 C1、C2 行各显示 `已覆盖 100 股`；股票部分 IXQZ `200 / 200 / 0`。

2. **锁定与 BTC 释放（Q78）**：场景 D，卖出 IXQZ 100 股、实收 1,000.00（2026-11-05 10:00）→ 拒绝 `卖出 100 股超过可用股数 0 股（持有 200 股，其中 200 股被 call 覆盖），请先平掉对应的 call`。BTC C2 1 张、实付 10.00（2026-11-05 11:00）→ 股票 `200 / 100 / 100`；再卖出 100 股，时间 2026-11-05 10:30 → 仍按 E2 拒绝；时间 2026-11-05 12:00 → 成功，`100 / 100 / 0`。之后删除该 BTC → 拒绝 `删除后 2026-11-05 12:00 起 IXQZ 不足以覆盖卖出的 call：需要 200 股，持有 100 股`；把 BTC 时间改为 2026-11-05 12:30 → 拒绝 `修改后 2026-11-05 12:00 起 …需要 200 股，持有 100 股`。

3. **补录 / 修改 / 删除重放（Q19）**，各从场景 D 开始：
   - 补录卖出 IXQZ 100 股、实收 900.00（2026-11-03 12:00）→ 拒绝 `补录后 2026-11-04 10:00 起 IXQZ 不足以覆盖卖出的 call：需要 200 股，持有 100 股`。
   - S1 股数改为 150 → 拒绝 `修改后 2026-11-04 10:00 起 …需要 200 股，持有 150 股`；删除 S1 → 拒绝 `删除后 2026-11-03 10:00 起 …需要 100 股，持有 0 股`。
   - C2 张数改为 2 → 按 E1 拒绝（需要 200，可用 100）；C1 时间改为 2026-11-01 10:00 → 拒绝 `需要 100 股 IXQZ，可用 0 股（持有 0 股）`；C1 净额改为 55.00 → 成功。

4. **作废与 call 被指派**：场景 D，时钟 2026-12-21 11:00。C2 被指派 1 张（日期 2026-12-18）→ 成功，股票 `100 / 100 / 0`（可用不变）。作废 C1 → `100 / 0 / 100`。卖出 IXQZ 100 股、实收 1,050.00（2026-12-21 10:00）→ 成功。删除 C1 的作废 → 拒绝 `删除后 2026-12-21 10:00 起 IXQZ 不足以覆盖卖出的 call：需要 100 股，持有 0 股`。另：在第一步之后卖出 100 股、时间 2026-12-18 15:00 → 按 E2 拒绝（持有 200 股，其中 200 股被 call 覆盖）。

5. **put 被指派增加持股（wheel）**："小账户"：入金 5,000.00（2026-11-02 10:00）；STO 1 张 QRTV 2026-11-20 40 P，净额 80.00（2026-11-03 10:00）。STO 1 张 QRTV 2026-12-18 45 C、净额 60.00（2026-11-10 10:00）→ 拒绝 `需要 100 股 QRTV，可用 0 股（持有 0 股）`。时钟 2026-11-23 10:00：put 被指派 1 张（日期 2026-11-20）→ QRTV 100 股；STO 45 C，时间 2026-11-20 15:00 → 同样拒绝；时间 2026-11-23 09:45 → 成功，股票 `100 / 100 / 0`。删除该 put 被指派 → 拒绝 `删除后 2026-11-23 09:45 起 QRTV 不足以覆盖卖出的 call：需要 100 股，持有 0 股`。

6. **旧批次不挡操作（Q79）**：场景 L，上线后：L1 行显示 `未覆盖`，悬停含 `需要 200 股，当前可用 0 股`。买入 IXQZ 100 股、实付 800.00（2026-11-10 10:00）→ 成功，股票 `100 / 0 / 100`，L1 仍 `未覆盖`（2 张整批，100 股不够，不部分覆盖）。STO 1 张 IXQZ 2026-12-18 12 C、净额 20.00（2026-11-10 11:00）→ 成功（旧批次不占用股票），股票 `100 / 100 / 0`。改 L1 备注 → 成功，仍 `未覆盖`；改 L1 张数为 1 → 拒绝 `需要 100 股 IXQZ，可用 0 股（持有 0 股）`。

7. **自动纳入检查（Q101）**：接第 6 条。转入 IXQZ 200 股、成本 1,500.00、日期 2026-11-04 → 成功，L1 仍 `未覆盖`，悬停含 `2026-11-03 10:00 时持有 0 股`；股票 `300 / 100 / 200`。删除该转入（成功），改录转入日期 2026-11-01 → L1 变为 `已覆盖 200 股`，股票 `300 / 300 / 0`。卖出 100 股 → 拒绝 `卖出 100 股超过可用股数 0 股（持有 300 股，其中 300 股被 call 覆盖），请先平掉对应的 call`；删除 2026-11-01 的转入 → 拒绝 `删除后 2026-11-03 10:00 起 IXQZ 不足以覆盖卖出的 call：需要 200 股，持有 0 股`。

8. **提示与标签（Q61、Q62）**：录入交易页选 STO + Call → 显示规则 7 的新提示全文；BTO + Call、STO + Put 不显示。场景 D 加 STO 1 张 IXQZ 2026-12-18 40 P、净额 70.00（2026-11-04 11:00，冻结 4,000.00）后，持仓页：40 P 行冻结 `4,000.00`，C1 / C2 行 `已覆盖 100 股`，任何页面都没有"未冻结"；顶部冻结合计 4,000.00。

9. **multiplier ≠ 100、账户隔离**：场景 D 加买入 IXQZ 10 股、实付 85.00（2026-11-04 11:00）→ `210 / 200 / 10`；STO 1 张 IXQZ 2026-12-18 13 C、multiplier 10、净额 5.00（2026-11-04 12:00）→ 成功，该行 `已覆盖 10 股`，股票 `210 / 210 / 0`；再录同样一笔 → 拒绝 `需要 10 股 IXQZ，可用 0 股（持有 210 股，其中 210 股已覆盖其它 call）`。在第 5 条的"小账户"STO 1 张 IXQZ 2026-12-18 10 C → 拒绝 `需要 100 股 IXQZ，可用 0 股（持有 0 股）`；默认账户不变。

## 边界情况
- 同一时间的记录按录入顺序：同一时间、更晚录入的买入不算 STO 时的持股。
- 多张批次只能整批覆盖：受检批次不会部分覆盖；旧批次股票不够整批时显示 `未覆盖`（第 6 条）。
- 已过到期日未处理的空头 call（Q34）继续占用股票，作废或被指派后才释放。
- 旧批次被 call 指派（FEAT-041）：交出股票若使受检批次不足 → 按 E3 拒绝（前缀"被指派"），即使 Q75 持股检查通过。
- 删除 STO call 不会因覆盖被拒（只会释放股票）。
- 周末、假日不影响覆盖计算；拆股见 FEAT-028。

## Out of Scope
- 用多头 call 或价差保护代替股票（Q102）；指数期权覆盖（Q103）。
- 指定由哪批股票覆盖、哪批交出（交出仍按股票 FIFO，FEAT-041）。
- 主动行权 put 的可用股数检查（FEAT-014、Q81）。
- 首页 / 到期提醒显示未覆盖个数；策略分组（M4）；合并查看（FEAT-035）。
